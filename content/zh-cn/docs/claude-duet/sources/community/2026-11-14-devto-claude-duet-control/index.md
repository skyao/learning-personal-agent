*2026 年 10 月 21 日，Anthropic 开放了 Claude Duet 的研究预览版。这是一个 Claude 以主动式智能体方式工作的应用：它盯着你连接的账户，在你不在的时候把活准备好，有事情需要你时给你发消息。有意思的地方不在于 Claude 现在能先开口，而在于 Anthropic 把最重要的那些控制移到了模型之外，以及还有哪些环节仍然取决于人点一下「同意」。以下是 Duet 如何工作、它的安全设计哪些地方做对了、真正的风险在哪里，以及我今天会怎么用它。*

## 午饭前的十二次审批

想象一下，周一早上 7:40。

你还没打开笔记本电脑，手机上已经有一条消息在等你。Claude 已经读过你的收件箱和日历。今天有三件事需要你：一份合同等着签字，一笔客户发票逾期未付，还有四封邮件的回复草稿已经备好待发。

你在火车上批准了这些草稿。

到午饭时，Claude 已经请求审批十二次。发这封跟进邮件。用一次性卡支付这笔软件续费。把第三季度摘要分享给那位来信索要的财务联系人。每个请求都准确写明会发生什么、发往哪里、由谁接收。

到第八个请求时，你已经不再读了。你在点。

那位索要第三季度摘要的财务联系人，发信域名与你的客户域名只差一个字母。审批卡按要求完整显示了收件地址。你只是没看。

这是一个假设场景，不是报道过的 Duet 事件。它也不是一个关于模型粗心的故事。每一道防护都发挥了作用。智能体准备好了工作，一项独立检查判定「按邮件要求分享一份报告」符合你的意图，审批卡显示了目的地。

失效的那道控制是注意力。

Anthropic 对这项风险说得异常直接。在描述 Duet 的防护措施时，公司承认：「审批疲劳是一个严重问题，因为请求太多会教人一路点过去。」（译注：原文为 "approval fatigue is a serious issue, because too many requests teach people to tap through them."）

这句话是合适的起点，因为它点出了一件事：当 AI 智能体先给你发消息时，真正改变的是什么。

聊天助手等着你。由你决定什么时候提问、分享什么、拿到答案后怎么办。

主动式智能体则自己决定什么时候需要你。它读你并未选择给它看的内容，准备你并未明确要求的动作，按它的时间表而不是你的时间表要求你做决定。

> **当 AI 智能体先开口，同意就从「逐项批准每个请求」变成了「授予常驻权限」。Claude Duet 把最重要的控制放在模型之外，这是正确的架构。但最后一道控制仍然是人的批准，而人的注意力是这套系统里最稀缺的资源。**

## 要点速览（TL;DR）

- **Claude Duet 是一个主动式智能体应用，不是新模型。** 它运行在 Claude Opus 5.5 上，是 iOS、Android 和 claude.ai 上的独立应用，于 2026 年 10 月 21 日以研究预览形式推出。
- **访问权限有限。** 预览面向美国的 Claude Pro 和 Max 订阅用户，需通过等候名单加入。Team 和 Enterprise 套餐尚不支持。
- **它在你离开时工作。** Duet 运行在自己的云虚拟机上，有自己的浏览器，每隔几小时检查一次已连接的账户，准备晨间简报，起草回复，并以文件形式交付较大的工作成果。
- **它继承你在 Claude 里的上下文。** Duet 使用你 Claude 账户里的记忆、技能和连接器，可以触达 Claude Marketplace 里 6,000 多个连接器与插件。
- **后果性操作需要审批。** 发送可能敏感的消息、付款和删除，都需要你批准一个显示操作、目的地和内容（包括每一位收件人）的请求。
- **意图检查在模型之外运行。** Anthropic 说，一项独立的检查——由 Claude Code 的 auto mode 分类器扩展而来——会判断每个动作是否符合你的意图，因此藏在页面里的指令无法回答它。
- **凭证永远不会到达模型。** 密码通过加密表单传递，登录令牌由智能体机器之外的代理注入。对任何智能体来说，这都是正确的模式。
- **有些操作即使获批也会被阻止。** 交易证券、在银行账户之间转移资金、访问他人的账户，都在禁止之列。
- **「主动」意味着收件箱变成了一条输入通道。** 任何能给你发邮件的人，现在都能把文字摆到一个代表你行动的智能体面前。提示注入不再是一个边缘情况，而成了默认的威胁模型。
- **记忆比连接活得更久。** 断开一个应用会停止新的访问，但 Duet 已经学到的东西会一直留着，直到你重置它的记忆。
- **后台工作不是免费的。** Duet 的定期检查和任务，与你日常的 Claude 对话共用同一套用量额度。
- **审批质量才是真正的瓶颈。** 用 Duet 最好的方式，是让审批保持稀少、有意义并被认真阅读，而不是批得更快。

## Claude Duet 到底是什么

大多数报道都聚焦在标题上：Claude 现在会先给你发消息。细节更重要。

|  | Claude Duet 研究预览 |
| --- | --- |
| **推出时间** | 2026 年 10 月 21 日 |
| **模型** | Claude Opus 5.5 |
| **平台** | iOS 和 Android 上的独立应用，外加 claude.ai |
| **适用对象** | 美国 Pro 和 Max 套餐账户，需排队申请 |
| **尚不支持** | Team 和 Enterprise 套餐 |
| **价格** | 预览期间不额外收费；占用你常规的 Claude 用量额度，包括会话上限和每周上限 |
| **运行位置** | 自己的云虚拟机和浏览器 |
| **上下文** | 你的 Claude 记忆、技能和连接器 |
| **集成** | 6,000 多个连接器和插件，包括 Gmail、Slack、QuickBooks、HubSpot、Docusign 和 Gusto |
| **购买** | 通过 Stripe 的 Link 钱包或 Shopify 的 Shop Pay，使用一次性卡号 |

Anthropic 把目标用户描述为任务多到跟不过来的专业人士和小企业主。公司也明确说了 Duet 不适合做什么。据 TechCrunch 报道，Anthropic 说 Duet「不擅长跑腿或订票，也不能在它使用浏览器时实时展示给你看」。

推出时报道的其他预览限制：

- 你不能选择模型、观看 Duet 工作，或接管它的浏览器；
- 它不能打电话或发短信；
- 它不是持续监控账户，只是每隔几小时检查一次；
- 它尚不支持 Microsoft 365；
- 有些连接器（如 Slack）存在限制。

Anthropic 对「为什么现在有 Duet」的说法，落点在模型的判断力上。Mike Krieger 说：「我们发现 Opus 5.5 是我们第一个具备判断力、能以正确方式主动行动的模型。」Anthropic 的发布材料称，模型的判断力帮助它「决定什么需要你、什么可以等，以及何时先跟你确认」。

对产品团队来说，这是个合理的说法。它也恰恰是那种绝不应成为唯一控制手段的说法。Duet 其余的设计表明，Anthropic 同意这一点。

## 先分清反应式、定时和主动式智能体

「主动式智能体」很容易和已有的功能混为一谈。它们是不同的东西，差别决定了风险。

| 模式 | 谁决定何时行动？ | 它读什么 | 同意模型 | 主要风险 |
| --- | --- | --- | --- | --- |
| **反应式聊天** | 你，每一次 | 你选择分享的内容 | 按请求 | 答错 |
| **定时例程** | 你，通过定义触发条件 | 例程所限定的范围 | 按例程 | 按计划做错事 |
| **主动式智能体** | 智能体，基于它观察到的东西 | 它的连接器能看到的一切 | 常驻权限加审批 | 对什么重要的判断出错，基于不可信输入行动 |

这个区分很重要。

在反应式聊天里，用户就是过滤器。由你决定粘贴哪封邮件、上传哪份文档、采纳哪个答案。

在主动式智能体里，智能体是过滤器。它读收件箱、日历、CRM 和共享盘，判断什么值得你注意，并准备一个动作。

这一下同时改变了三件事：

1. **输入的选择权移到了智能体手里。** 它会读你从未选择给它看的内容，包括陌生人写的内容。
2. **时机移到了智能体手里。** 当它认定某事重要时，它就来打断你。
3. **同意变成了常驻的。** 你授权了一次，智能体就持续使用这份授权。

审批是你把其中一部分控制取回来的方式。这就是为什么审批的设计和数量如此重要。

## Duet 的控制架构如何运作

Anthropic 于 2026 年 10 月 23 日为 Duet 发布了一份异常详细的安全、隐私与保障说明。把它当作一份架构来读，大致是这样：

```
   Connected accounts                     You
   (email, calendar, CRM,           (phone or claude.ai)
    accounting, docs, web)                  ^
            |                               | approval card:
            v                               | action, destination,
+-----------------------+                   | content, recipients
| Claude Duet agent     |                   |
| Opus 5.5 on a cloud   |-------------------+
| VM + isolated browser |  proposed action
| memory, skills        |
+-----------+-----------+
            |
            v
+-----------------------+   +-------------------------+   +---------------------+
| Intent check          |   | Outbound sensitive-info |   | Hard blocks         |
| outside the model     |   | classifier              |   | securities, moving  |
| (from Claude Code     |   | never share / needs     |   | money between       |
|  auto mode classifier)|   | consent / allowed       |   | accounts, others'   |
+-----------+-----------+   +------------+------------+   | accounts            |
            |                            |                +---------------------+
            v                            v
+-------------------------------------------------------------+
| Credential layer outside the agent                          |
| password form encrypted to browser | token proxy injects    |
| sign-in tokens at request time      | one-time payment cards|
+-------------------------------------------------------------+
```

每一层控制着某个具体的东西。每一层也都留下了某些未被控制的东西。

### 第一层：通过连接器和记忆获得的常驻访问

Duet 使用你 Claude 账户里的记忆、技能和连接器。它每隔几小时检查一次已连接的账户，并准备工作。

这一层控制的是 **Duet 能看到什么**。它不控制 **Duet 该信任什么**。陌生人发来的邮件和你上司发来的邮件，走的是同一个连接器。

### 第二层：审批层

在 Duet 发送可能敏感的消息、付款或删除东西之前，Anthropic 说它会「向你显示操作、目的地和内容，包括每一位收件人」，然后等待。

有些步骤无法被「不再询问」规则覆盖，包括付款或转账、删除订单、创建账户。你不在时运行的例程遵循同样的防护措施。

这一层控制的是 **哪些操作需要人来做决定**。它不控制 **人是否真的读了那个请求**。

### 第三层：模型之外的意图检查

这是 Duet 最重要的设计选择。

Anthropic 说，一项独立的自动检查——由 Claude Code 的 auto mode 分类器扩展而来——会评估每个动作是否符合你的意图。用 Anthropic 的话说：「这项检查在做事的模型之外运行，因此藏在页面里的指令无法影响结果。」（译注：原文为 "The check runs outside the model doing the work so instructions hidden in a page cannot affect the outcome."）

这个边界划得对。如果一封恶意邮件让智能体相信转发某份文档是你任务的一部分，智能体自己的推理就已经被污染了。一项不读智能体推理、也无法以同样方式被注入文字触及的检查，要稳健得多。

这一层控制的是 **该动作是否可能与你的请求相符**。它并不能让决定变得确定。它仍然是一个分类器，而 Anthropic 说这些防护措施「偶尔会漏掉一些东西，或把一条无害的消息标出来」。

### 第四层：凭证从不进入模型

Anthropic 说：「Claude Duet 永远看不到你的密码、浏览器 cookie、登录令牌或其他凭证。」

- 密码在 Claude 应用的表单里输入，用一把一次性密钥加密，然后传给浏览器，全程不会被打开。
- 登录令牌不放在智能体的机器上。那里只有一个占位符，机器之外的代理会在请求时插入真实的值。
- 计划支持 1Password 登录，这样你可以在那里批准凭据的使用。

这就是我在关于智能体身份的文章中推荐的凭证模式，如今已经在一个消费级产品里落地。一个被提示注入的智能体，无法泄露它从未见过的密码。

这一层控制的是 **凭证的暴露**。它不控制 **智能体用这些凭证授予的访问权去做什么**。

### 第五层：出站敏感信息分类器

一个独立的分类器会把每一条外发消息（包括通过浏览器上传的文件）对照三个等级检查：

- **绝不分享：** 登录凭证、完整的银行卡号和银行账户号码、政府身份证件号码。Anthropic 说 Duet「被要求绝不把这些分享给任何人，即使你要求它这么做」。
- **需要同意：** 其他私密信息，例如健康或财务细节，需要你明确批准。你自己的请求就算作同意。
- **允许：** 其余一切。

如果一条消息被拦下，Duet 可以重写它、去掉敏感内容，然后把修订版提交审批。

这一层控制的是 **特定类别的数据外流**。它不控制 **普通业务内容**（例如一份季度报告）被发给了错误的收件人。

### 第六层：硬性阻断

有些操作即使获批也仍然被禁止：交易证券、在账户之间转移资金这类银行操作、访问他人的账户。

这些是确定性的边界，也是这套系统里最强的控制。任何判断、分类器或疲惫的人，都无法越过它们。

### 第七层：限定范围的支付

购物使用来自 Link 这类钱包的一次性卡号，限定一个商户和一个金额，并由你在 Link 应用里批准。你真实的卡号不会被分享出去。

这就是我在关于智能体支付的文章里说的任务绑定消费模式：把凭证限定到这笔交易上，把批准放在智能体无法控制的界面上。

### 第八层：在网络上表明自己的身份

Duet 用一个独特的 User-Agent 标头表明自己的身份，并公布自己的 IP 地址。Anthropic 提到，有些网站已选择拒绝被访问。

这是个很小的细节，含义却很大。网站可以识别并治理智能体的流量，而不必猜测某个浏览器会话是不是属于一个人。

## Duet 做对的地方

从生产架构的角度看，Duet 有几个选择值得借鉴——无论你是否会用 Duet。

**它把强制执行移到模型之外。** 意图检查、凭证处理、出站分类器和硬性阻断都位于做事的模型之外。对任何读取不可信内容的智能体来说，这是唯一最重要的原则。

**它把凭证当作基础设施，而不是上下文。** 通过代理注入令牌、加密传递密码，意味着模型从不持有秘密。

**它为钱使用了非智能体的审批界面。** 支付审批发生在钱包应用里，而不是智能体渲染出来的屏幕上。

**它让某些操作无法被批准。** 一份简短的硬性阻断清单，比任何数量的判断力都更值得信任。

**它把同样的规则用于后台例程。** 很多系统对定时工作会放松控制。据 Anthropic 说，Duet 没有。

**它不仅测试攻击，也测试诱惑。** Anthropic 说，其防护措施评估使用了任务的清白版本、注入版本和「诱惑」版本，还用了影子流量，外加红队测试、一次可访问源代码的外部渗透测试，以及通过 HackerOne 的漏洞赏金覆盖。

**它对局限是诚实的。** Anthropic 说审批频率、登录方式和分类器准确率仍在调整中，防护措施有时会漏掉东西。

这种坦率，比声称绝对安全更让人安心。

## Duet 尚未解决的问题

### 审批疲劳是结构性问题

审批在稀少且有分量时才有效。主动式智能体的价值来自做很多事，所以审批量会随着有用程度自然增长。

Anthropic 自己的说法点出了失效之处：请求太多会教人一路点过去。显示每一位收件人是正确的设计。它只有在有人真的去看收件人时才起作用。

解法不是更快的审批，而是更少、质量更高的审批：把相关动作分组，突出异常（例如新的收件人和形近域名），把打断留给真正需要人做的决定。

### 收件箱默认就是不可信输入

在聊天里，提示注入通常需要你粘贴或浏览某种恶意内容。主动式智能体则会读一切送到眼前的东西。

任何能给你发邮件、分享文档，或在你的智能体监控的频道里发帖的人，都能把文字摆在它面前。Anthropic 说 Duet 使用了其浏览器使用研究中的提示注入防御，意图检查的设计也使得隐藏的指令无法回答它。

这些防御降低了风险。它们没有改变一个基本事实：主动式智能体的威胁模型从「攻击者可以往我的输入里写东西」开始。

### 访问结束后记忆仍在

Anthropic 说，断开一个应用会立即停止新的访问，但「Claude Duet 已经学到的东西会一直留着，直到你重置它的记忆」。Duet 还会使用你 Claude 账户里的记忆，所以早前对话里的细节对它可见。

这是个合理的产品决定。它也恰恰是我在关于记忆投毒的文章里描述的那个面。从一封不可信邮件里读到的内容，可以塑造智能体记住的东西，而那些记忆可能比产生它的那条连接活得更久。

如果你因为担心某个账户而断开它，那就把记忆也重置。

### 「主动」不等于「实时」

Duet 每隔几小时检查一次已连接的账户，而不是持续监控。Anthropic 已经承认，它可能误解对话、误判优先级，或漏掉两次检查之间发生的变化。

不要把主动式智能体当作任何时间敏感事项的告警系统。

### 意图检查仍然是概率性的

「在模型之外」是重大改进。它不等于确定性。一个判断动作是否符合你意图的分类器，会有假阴性和假阳性——Anthropic 也直接这么说了。

这就是为什么硬性阻断和人的批准仍然必不可少。在我关于 Jev 与决策模型的文章里，原则是：概率是证据，不是许可。这里同样适用。

### 后台工作花的是你的额度

Duet 的晨间简报、定期账户检查和任务，与你日常的 Claude 对话共用同一套用量额度，包括会话上限和每周上限。一个在你睡觉时工作的智能体，也在你睡觉时花钱。Anthropic 给每位新用户一次完整的额度重置，有效期到 2026 年 11 月 30 日——这等于承认了这一点。

### 责任仍然在你身上

Duet 经你批准发出的一封邮件，就是你的邮件。你批准的一笔购买，就是你的购买。主动式智能体不会转移责任，它转移的是你行使责任的时刻——往往挪到会议间隙的一块手机屏幕上。

### 企业级控制还没有

Duet 不在 Team 或 Enterprise 套餐中提供，也不支持 Microsoft 365。这意味着组织目前还没有针对它的管理员级控制。

这也意味着一些专业人士会把个人的 Pro 或 Max 账户连到工作邮箱和 Slack 上。对 IT 团队来说，这是个影子智能体问题：一个自主系统，对公司数据有常驻访问权，处在公司政策之外，由一个想提高效率的员工创建。

## Duet 属于一个品类，而不是孤例

Duet 是在一个拥挤的时刻推出的。推出时的报道把它与 OpenAI 的 Dots 和 Meta 的 Muse 相提并论，TechCrunch 还列出了同一空间里的另外几个个人与商务智能体。

细节各不相同。方向是一样的：助手正在从回答问题，转向监控你的账户并代表你行动。

这使得 Duet 的安全设计比它的功能清单更重要。Anthropic 公布的那些模式——模型之外的意图检查、凭证代理、一次性支付卡、出站分类器、硬性阻断——是与任何主动式智能体作比较的合理基线。

## 我今天会怎么用 Duet

如果你在预览中，这是我会采用的初始设置。

1. **连得比你能连的少。** 先从一个邮箱账户和一个日历开始。观察两周 Duet 的行为之后，再加会计、CRM 或电子签名工具。
2. **头两周读每一位收件人。** 用这段时间了解正常的审批请求长什么样，之后异常才容易显出来。
3. **对外部邮件避免「不再询问」。** 任何离开你组织的东西都保留审批。
4. **把邮件内容当作信息，而不是指令。** 如果 Duet 因为某封邮件的要求而提议做某件事，先查清那封邮件是谁发的。
5. **把高风险财务排除在范围之外。** Duet 已经阻止在账户之间转账。在预览期间，我还会让薪资和银行连接器保持断开。
6. **定期检查记忆。** 看看 Duet 学到了什么；断开账户时重置记忆。
7. **留意你的用量。** 后台检查会消耗额度。如果 Duet 把每周上限花在低价值的简报上，就缩小它的范围。
8. **遵守你公司的政策。** 除非你的组织允许，不要用个人智能体连接工作账户。

## 小团队的四周试用计划

Duet 面向专业人士和小企业。一个小团队试用它，我会采用一个简短而有章法的计划。

### 第一周：只观察

- 每人连接一个收件箱和一个日历。
- 使用简报和草稿，但不通过 Duet 发送任何东西。
- 记下它正确标出了哪些事项、漏掉了哪些、高估了哪些。

### 第二周：批准低风险发送

- 允许 Duet 经批准发送内部回复。
- 统计每人每天的审批次数。
- 记录任何没读就点掉的审批。

### 第三周：接入一个业务系统

- 接入一个系统，例如 CRM 或会计工具。
- 让 Duet 用它准备报告和看板。
- 复核是否有任何外发消息包含了不该外流的数据。

### 第四周：定下边界

- 决定哪些操作 Duet 可以准备、哪些可以经批准发送、哪些保持手动。
- 把这条边界写下来，并与团队共享。
- 为任何断开的账户重置记忆。

四周结束后，你会知道 Duet 是否在不制造审批疲劳的前提下节省了时间。对主动式智能体来说，这是唯一重要的指标。

## 向任何主动式智能体提的七个问题

1. 哪些检查在做事的模型之外运行？
2. 模型是否曾看到密码、cookie 或令牌？
3. 哪些操作无论用户点什么，都永远无法被批准？
4. 审批请求会显示什么？它会不会突出异常，例如新的收件人？
5. 我断开一个账户时，记忆会怎样？
6. 它多久检查一次我的账户？两次检查之间可能漏掉什么？
7. 对组织来说，有哪些管理员控制、审计日志和政策设置？

如果一个产品回答不了前三个问题，那它是在索取它尚未赢得的信任。

## 结语：先开口的助手

在 AI 助手历史的大部分时间里，每一段对话都由人开始。这给了我们一个看不见的控制：我们选择 AI 看到什么、什么时候行动。

Claude Duet 改变了这一点。它观察、排优先级、准备，然后来问。这确实有用，而 Anthropic 公布的防护措施显示了一次认真的安全尝试：检查在模型之外，凭证在模型之外，支付限定到一个商户和一个金额，以及一份再多的批准也解不开的短清单。

这些控制处理了机器能处理的部分。

剩下的是人读、或者不读那张审批卡的那一刻。

对主动式智能体来说，最重要的设计目标不是速度或自主性，而是保护那一刻：更少的打断、更清楚的异常，以及真正意味着有人看过的审批。

Duet 先开口。

确保最后说话的仍然是你。
