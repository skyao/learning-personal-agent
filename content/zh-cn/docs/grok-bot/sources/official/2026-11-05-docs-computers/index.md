**内容摘要**：每个团队成员有一台托管计算机，其上的所有 Bot 都在这里工作。**Manage Member Computers and Data** 仅限 Enterprise，组织管理员和 Enterprise 团队管理员可用，可批量重建（Recreate）或终止（Terminate）成员的计算机，删除计算机及数据，或删除成员的全部 Grok Bot 数据。重建和终止都保留成员的持久磁盘，重建时正在执行的 Bot 会在安全点暂停并在新计算机上继续，终止则让运行中的工作停止，下次发消息会在同一磁盘上新建计算机；删除计算机及数据一次最多 1,000 名成员，删除全部数据一次最多 100 名，均不可撤销并写入审计日志。每个团队同时只能有一个操作，包括其他管理员或 API 发起的；团队设置变更后，Grok Bot 页会出现 **Restart VMs to apply changed settings**，可用 **Restart all VMs** 重建全员计算机。还可设置保留期，在无人给成员的任何 Bot 发消息达 30 至 365 天后自动删除休眠的计算机，默认关闭且删除前不通知。

**保留理由**：写明了计算机重建、终止、删除的差别和数据保留规则，是了解云端计算机生命周期与持久磁盘的直接材料。

管理 Grok Bot 计算机

你团队的每位成员都有一台托管计算机，他们运行的所有 Bot 都在那里工作。在 [Cursor 控制台的 Grok Bot 页面](https://cursor.com/dashboard/bot)**安全与合规（Security & Compliance）**下的**管理成员计算机与数据（Manage Member Computers and Data）**，让管理员可以一次为许多成员重建或终止计算机、[删除计算机及其数据](#delete-vms-and-data)，或[删除某位成员的全部 Grok Bot 数据](#delete-all-grok-bot-data)。**数据保留（Data Retention）**下的**计算机保留期（Retention Period for Computers）**会替你[删除不活跃的计算机](#delete-inactive-computers-automatically)。其余管理员控制项见 [面向团队与企业的 Grok Bot](https://docs.x.ai/grok-bot/teams-and-enterprises)。

**管理成员计算机与数据仅限 Enterprise。** 组织管理员和 Enterprise 团队管理员可以使用。成员从来看不到这个控制项。团队管理员还可以[在设置变更后重启团队的计算机](#restart-after-a-settings-change)。

## 重建或终止

两种操作都保留成员的持久磁盘，所以他们同步过的 Bot、文件和登录信息会在下一台计算机上恢复。两种操作都会移除成员自己安装的应用和软件包。你的 Team Setup Scripts 安装的任何内容会在新计算机上恢复。

| 操作 | 会发生什么 | 何时使用 |
| --- | --- | --- |
| **重建（Recreate）** | 在最新镜像上构建一台替换计算机，并运行 [Team Setup Scripts](https://docs.x.ai/grok-bot/private-networks)。当前计算机在替换机就绪前仍可用，之后 Grok Bot 切换过去。正在一轮工作中的 Bot 会在安全点暂停，并在新计算机上继续。如果它无法及时暂停，该成员的重建不会开始，并显示为失败。 | 一次向许多成员推行新镜像或更新后的 Team Setup 清单。[网络策略](https://docs.x.ai/grok-bot/security#network-policy)变更无需重建即可到达计算机。 |
| **终止（Terminate）** | 删除成员的计算机，无论运行中还是休眠中。正在运行的工作停止。计算机不会自行重启；成员的下一条消息会在同一持久磁盘上启动一台新计算机。 | 结束成员当前的工作，或清理卡住的计算机。终止不会移除访问权限；见[常见问题](#faq)。 |

## 删除虚拟机与数据

**删除虚拟机与数据（Delete VMs and Data）**删除成员的计算机及其持久磁盘。他们的 Bot 和对话保留，下一条消息会启动一台空白计算机。

* **每次操作最多 1,000 名成员。**
* **不可撤销。** 每次操作都记录在[审计日志](https://cursor.com/dashboard/audit-log)中。

## 删除全部 Grok Bot 数据

**删除全部 Grok Bot 数据（Delete All Grok Bot Data）**永久删除成员的 Bot、对话、记忆、例程和计算机，覆盖其所属的每一个团队。这包括队友在用的 Team Bots、已连接的应用、邮箱和文件。他们的 Cursor 账号保留，仍留在团队中，下次使用 Grok Bot 时从头开始。

* **每次操作最多 100 名成员。**
* **不可撤销。** 每次操作都记录在[审计日志](https://cursor.com/dashboard/audit-log)中。

## 执行一次操作

### 打开管理成员计算机与数据

前往 [Cursor 控制台中的 Grok Bot](https://cursor.com/dashboard/bot)，在**安全与合规**下找到**管理成员计算机与数据**，选择**管理（Manage）**。

### 选择成员

按姓名或邮箱搜索，然后勾选你想要的成员。**全选（Select all）**会选中当前结果中的所有人。

### 选择操作

打开**管理所选（Manage selected）**，选**重建虚拟机（Recreate VMs）**或**终止虚拟机（Terminate VMs）**。确认屏会重述该操作及其影响的成员数。同一菜单还提供[删除虚拟机与数据](#delete-vms-and-data)和[删除全部 Grok Bot 数据](#delete-all-grok-bot-data)。只有在你希望成员从空白开始时才使用这两项。

### 确认

选择**重建虚拟机**或**终止虚拟机**开始。没有计算机的成员会被跳过。

### 查看结果

进度卡显示排队、运行中、已完成、已跳过和失败的数量，每位成员的各行显示其状态。操作完成后，选择**完成（Done）**清除结果并开始另一次操作。

## 一次操作如何运行

* **它在 Cursor 一侧运行。** 关闭对话框或浏览器不会停止它。在同一浏览器中重新打开**管理**即可接着看进度。
* **大批量操作需要一段时间。** 成员按批处理，每次重建都要等替换计算机就绪才算完成。
* **每个团队同时只能有一个操作。** 在你对已完成的结果选择**完成**之前，操作按钮保持禁用。该限制覆盖所有管理员：当该团队还有另一个操作在运行时发起的启动会显示**未开始（Not Started）**，且不做任何改动。选择**完成**，等正在运行的操作结束，然后重新开始。
* **重试启动绝不会造成重复工作。** 当控制台无法确认操作已开始时使用它。
* **被拒绝的启动会说明原因。** 无法运行的启动，例如所选成员都已不在团队中，会显示**未开始**及其原因，且不做任何改动。

## 通过 API 执行操作

要用脚本在多个团队中推行，请用 Organization API 发起相同的操作。组织管理员可以重建、终止或删除成员的计算机，或删除他们的全部 Grok Bot 数据。你发送一个团队、一组成员和一个操作，然后轮询该操作获取计数，并且对于最多 1,000 名成员的操作，还会得到每位成员的结果。

API 和控制台共享每个团队一个操作的限制。从任一处发起的操作都会阻塞另一处，直到它完成。

API 需要一个带 `admin:*` 范围的 Organization API 密钥。端点、请求字段和错误码见 Organization API 参考中的 [Grok Bot 计算机](https://cursor.com/docs/account/organizations/organization-admin-api#grok-bot-computers)。

## 被跳过和失败的成员

已完成的操作会为你选中的每位成员列出一条结果。

| 结果 | 含义 | 怎么办 |
| --- | --- | --- |
| **已跳过**，无虚拟机 | 该成员没有运行中或休眠中的计算机。 | 无需处理。 |
| **已跳过**，操作无法完成 | 该成员已离开团队或从未登录过，或其账号在操作排队期间发生了变化。 | 无需处理。 |
| **失败**，另一次重建正在进行 | 该成员的计算机已在被更新或另一位管理员重建。 | 等它完成，然后为该成员重新执行。 |
| **失败**，虚拟机扫描未完成 | Cursor 无法确认该成员计算机的状态，因此未做任何改动。 | 几分钟后重新执行该操作。 |
| **失败**，另一次删除正在进行 | 该成员的 Grok Bot 数据已在被删除。 | 等它完成。 |
| **失败**，无法删除 Grok Bot 数据 | 删除没有完成。 | 重新执行该操作。如果失败两次，[联系支持](https://grok.com/help/grok-bot/get-help)。 |
| **失败**，操作无法完成 | 重建或终止没有完成。对于重建，该成员计算机上的某个 Bot 可能未能及时暂停，成员保留当前计算机。 | 为受影响的成员重新执行该操作，可以的话等他们的 Bot 空闲后再做。如果失败两次，请带上该成员的邮箱和操作时间[联系支持](https://grok.com/help/grok-bot/get-help)。 |
| **失败**，无法获取重建状态 | Cursor 无法判断该成员的计算机上是否已有重建在进行，因此未做任何改动。 | 几分钟后重新执行该操作。 |

## 设置变更后重启

某些团队设置变更后，Grok Bot 页面顶部会显示**重启虚拟机以应用变更的设置（Restart VMs to apply changed settings）**。选择**重启全部虚拟机（Restart all VMs）**，再选择**重建虚拟机**，即可用当前团队设置重建团队每位成员的计算机。重启的运行方式与其他重建操作相同，有相同的进度卡和结果，开始后该提示会消失。

Enterprise 团队的团队管理员可以执行此重启，不仅限于组织管理员。它只做重建；**终止虚拟机**和**删除虚拟机与数据**在**管理成员计算机与数据**下。

## 自动删除不活跃的计算机

休眠的计算机一直保留到有人删除它，即使成员已经转做别的或不再使用 Grok Bot。同一控制台页面**数据保留**下的**计算机保留期**会替你完成清理。当在你选择的期限内没有人给某位成员的任何 Bot 发消息时，Cursor 会在其下一次休眠时删除该计算机及其持久磁盘。从应用或 Slack 发的消息都计入，无论发送者是该成员还是队友。Bot 自行启动的例程和其他工作不计入。发送一条消息会重新开始计时。

该设置默认关闭。可选择 30、60、90、180 或 365 天，或 30 到 365 天之间的自定义期限。开启它或缩短期限时会先弹出确认。

* **删除的效果与[删除虚拟机与数据](#delete-vms-and-data)相同。** 成员的 Bot 和对话保留。他们的文件、登录信息和已安装的应用永久消失，下一条消息会启动一台空白计算机。
* **没有警告。** 成员的计算机被删除前不会收到通知。
* **最短的期限生效。** 一台计算机覆盖成员所属的所有团队，因此遵循其任一 Enterprise 团队设置的最短期限。

每次删除都记录在[审计日志](https://cursor.com/dashboard/audit-log)中。关闭该设置会停止后续删除。

## 成员看到什么

重建期间，桌面应用显示**正在更新 Grok Bot 的计算机（Updating Grok Bot's computer）**，直到切换完成。正在工作的 Bot 会在安全点暂停，并在新计算机上继续。计算机被重建时，其中的登录会话可能失效，因此成员需按你身份提供方的策略重新登录公司工具。

终止之后，成员的下一条消息会在其持久磁盘上启动一台新计算机。重新连接可能需要几分钟。已同步的 Bot、文件和登录信息会恢复；正在运行的一轮工作会丢失。

## 常见问题

### 我能从另一个团队重建某位成员的计算机吗？

可以。从该成员所属的任一团队中选择他。一台计算机服务于该成员所在的所有团队，所以从一个团队重建或终止它，会在所有地方影响同一台计算机。

### 终止会让成员无法使用 Grok Bot 吗？

不会。终止计算机只结束该成员当前的工作。他的下一条消息会在同一持久磁盘上启动一台新计算机，带着他的 Bot、文件和登录信息。要移除访问权限，请把该成员从团队中移除，或用**管理组访问权限（Manage Group Access）**关闭他的访问，并在你的身份提供方中撤销他的会话。见[启用 Grok Bot](https://docs.x.ai/grok-bot/teams-and-enterprises#enable-grok-bot)。

### 自动删除会打断仍在工作的 Bot 吗？

不会。Cursor 只删除处于休眠状态的计算机。处于唤醒状态的计算机——因为某个 Bot 正在工作或成员正在使用 Grok Bot——绝不会被该设置删除，即使成员的 Bot 在整个期限内都没有收到消息。
