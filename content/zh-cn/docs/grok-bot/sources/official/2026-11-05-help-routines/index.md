例程（routine）告诉一个 Bot 何时运行某个工作流。它可以按时间表运行，也可以在发生某事时运行，例如 Slack 消息、GitHub、Linear、Sentry 或 PagerDuty 事件、电子邮件或 webhook 调用。例程在云端运行，即使你的笔记本合上也不受影响。有关发送到 Bot 自己地址的电子邮件，见[给你的 Bot 一个电子邮件地址](https://cursor.com/help/grok-bot/agent-email#how-do-i-have-my-bot-act-on-incoming-email)。

## 如何设置或更改例程？

在聊天中询问 Bot。说明它应该做什么以及何时做。例如：「每个工作日上午 9:00，在这个聊天中总结新的支持工单。」Bot 会创建该例程，它会出现在该 Bot 的例程中。

要在桌面端更改例程，打开它并选择 **Edit**。Grok Bot 会启动一条发给该 Bot 的消息，开头是「Edit your routine:」并带上例程名称。添加应更改的内容，然后发送。

在手机上，打开 Bot 的配置文件，点击 **Routines** 下的 **Add routine**。Grok Bot 会启动一条消息，开头是「Set up a routine to 」。补完这句话并发送。

## 我在哪里查看 Bot 的例程？

在桌面端：

1. 点击聊天顶部的 Bot 名称，打开其详情。
2. 在 **Details** 选项卡中找到 **Routines**。

每一行显示例程的名称及其运行时间，或 **Paused**。使用行上的开关暂停或恢复它。如果该 Bot 没有例程，你会看到 **Ask in chat to set a routine**。

点击一个例程将其打开：

- **Instruction** 是 Bot 在每次运行时做的事情。
- **When to run** 列出时间表和启动它的事件。
- **Webhook** 显示由 webhook 调用启动的例程的 URL 和密钥。

底部的按钮是 **Pause** 或 **Resume**、**Test**、**Edit** 和 **Delete routine**（垃圾桶图标）。删除会要求你确认。它会停止未来的运行，且无法撤销。

在手机上，打开 Bot 的配置文件并找到 **Routines**。点击一个例程可查看 **Active**、**Schedule**、**Next run**、**Instruction** 和 **Run history**。关闭 **Active** 可暂停该例程。要删除例程，滑动该例程所在的行。

## 时间表和时区如何工作？

时间表使用 **Settings** 中 **Bot** 下标记为 **Timezone** 的时区。**Auto-detect** 跟随这台计算机。当例程应遵循不同时区时，选择一个时区，例如工作所属的办公室。

用平实的语言要求时间表，例如「每个工作日上午 8:00」或「每 2 小时」。然后打开例程并检查 **When to run**。它会用文字显示保存的时间表，以便你确认它符合你的本意。如果不符合，选择 **Edit** 并告诉 Bot 要修正什么。

新例程会等待下一个计划时间。它不会在创建时运行。如果你在 8:05 设置「每天上午 8:00」，第一次运行是明天上午 8:00。要立即尝试，请使用 **Test**。

## 如何测试例程？

在桌面端打开例程并选择 **Test**。在运行完成之前，按钮显示 **Running…**。结果显示在该 Bot 的聊天中。

测试会执行真实工作。它可以更改文件并使用已连接的应用。请使用安全的输入。如果测试无法启动，你会看到 **Couldn't start a test run**，或一条说明原因的消息。

有些例程不显示 **Test**。它们仍会按时间表或触发器运行。

## 如果用量下降得很快，我应该更改什么？

从例程的运行频率开始。每次运行都会消耗用量，因此运行频繁的例程比运行稀少的例程消耗更多。每小时的时间表、较短的间隔，或繁忙频道上的 Slack 触发器，可能一天就用掉一周的用量。

如果你的 **Weekly usage limit** 比预期更快用完，请暂停不需要的例程。然后在升级套餐或按需限额之前，让 Bot 放宽时间表并收窄 Slack 触发器。从不运行的例程不消耗用量。**Test** 会消耗，因为它执行工作。

有关每周用量和按需月度限额，见[套餐与计费](https://cursor.com/help/grok-bot/plans)。

## Slack 触发器如何工作？

Slack 触发器是例程的一部分，而不是 Slack 应用的一部分。该应用让 Bot 以你连接的 Slack 用户身份发布和读取内容。触发器在 Slack 中发生某事时启动例程。在依赖它之前，请在拥有该 Bot 的 Cursor 账户上连接 Slack。见[连接应用](https://cursor.com/help/grok-bot/connect-apps#what-can-a-connected-app-do)。

向 Bot 请求你想要的触发器。例程可以在 Bot 被提及时、某个词或短语被提及时、你对消息做出回应时，或在任何消息上启动。它可以监视一个频道或整个 Slack。**When to run** 会用文字显示触发器，例如一个短语和一个频道。

让频道和短语保持狭窄。繁忙频道中针对任何消息的触发器会频繁运行，并把用量花在不需要 Bot 的消息上。只有新活动才算数。触发器存在之前的消息不会启动运行。

## webhook URL 和密钥在哪里，200 意味着什么？

让 Bot 为例程添加 webhook 触发器。然后在桌面端打开该例程。**Webhook** 部分显示三个字段：

- **POST to** 是 URL。
- **key** 是密钥。发送方将其作为 `Authorization: Bearer <key>` 包含在内。
- **header** 是该完整标头，可直接复制。

点击字段即可复制。使用该标头向该 URL 发送 HTTP POST。你可以发送 JSON 正文。Bot 会连同例程指令一起接收该正文。

响应 **200** 表示 Grok Bot 接受了调用并启动了一次运行。这并不表示 Bot 已完成指令。请在 Bot 的聊天中查看结果。任何其他响应都表示运行未启动。确认例程未暂停，且请求使用了当前密钥。

## 为什么我的例程还没有运行？

请先检查这些：

- 例程未处于 **Paused**。在手机上，**Active** 已开启。
- **When to run** 显示了你预期的时间表或触发器，且时区正确。
- 新时间表会等待下一个时间点。使用 **Test** 立即运行。
- 对于 Slack，消息是新的、位于触发器监视的频道中，并匹配其短语。
- 对于 webhook，调用返回了 **200** 并使用了当前密钥。

在手机上，**Run history** 会把每次最近的运行显示为 **Running**、**Succeeded** 或 **Failed**。失败的运行会显示原因。**No runs yet** 表示尚未有任何内容启动该例程。

## 为什么我的例程因速率限制错误而失败？

例程有每小时限制。你的例程合计每小时最多运行 300 次，每个例程每小时最多 200 次。超过任一限制的运行会失败，并提示「Automation run rate limit exceeded」。如果某个例程持续触及其限制，请让 Bot 收窄触发器或放宽时间表。

有些运行也可能因为这个错误而失败，原因是所有 Grok Bot 例程共享的一个限制，即使你自己的例程运行次数低于该限制。这是一个已知问题，我们的工程师正在修复。

因这个错误而失败的运行不会自动重试，所以请自行重新运行该例程。使用 **Test** 立即运行。对于 webhook，请再次发送调用。
