生成式AI的风终于刮到了C端用户场景。Muse 26年9月份才上线，10月21日Meta在Q3财报电话会议上就披露，已突破1000万用户，日活超250万，两周留存率达到23%，这组增长数据即使跟早期的ChatGPT对比也不遑多让。

## 一、personal agent 是什么

在尝试理解这种迅猛增长的原因之前，让我们先简单梳理一下这波生成式AI浪潮，从产品视角经历了哪几个阶段：

### （一）chatbot 阶段

以ChatGPT在2022.11月上线为起点，DeepSeek首次把思维链展示给用户为重要节点。这一阶段的AI产品是一种问答引擎。它既能像朋友一样跟用户闲聊（Character.AI是这类产品的代表），又能借助RAG技术替代Google这类通用搜索引擎，回答用户各种知识类问题。

Character.AI作为陪聊类AI产品的代表，前不久刚刚申请破产了，可见这类产品的局限性。不是一个持续的用户需求，用户在尝鲜之后渐渐地离开了。

而作为Google替代者的定位，可以认为这方面的功能现在用户用的越来越多，趋势也越来越明显。传统搜索引擎已经日渐式微，有日薄西山之势，这从Google最新一季财报的增长数据也可以印证。

用户使用传统搜索引擎时的心智有两类：寻找问题的答案、找到特定网站的链接。在前一个心智上，AI chatbot带来的体验是颠覆式的。它不需要用户自己去一堆网页上查找、尝试理解才能得到答案。AI chatbot背后的大模型能根据用户的问题，直接生成答案，甚至可以给你一份详尽结构化的调研报告。

即使Google目前仍凭借自身海量用户、强大的商业生态，目前也只能勉励维持营收，下滑只是时间问题。唯一的疑问是，以后Google是作为用户的选择之一，还是彻底被AI产品取代。当然Google也在积极推进自己的AI问答产品Gemini。

### （二）work agent 阶段

chapgpt上线之后大获成功，让很多从业者包括openai自己都相信，生成式AI将首先带来C端应用的全面开花。openai在随后的1-2年内发布了文生视频模型sora及其社区、AI浏览器ChatGPT Atlas、Agent应用市场agent store等。目前这些项目都已经被取消或整合。反而另一条线上，长期被认为是openai的跟随者Anthropic异军突起，主要原因就是Anthropic推出的大模型Claude在coding上能力非常强，彻底打穿了coding这个场景。在这之前，AI编程普遍被认为只能做一些代码智能填充的任务，但是Claude真的做到了可以让AI帮你大段写逻辑代码，甚至整个项目的coding都可以让Claude来完成，用户只需要用自然语言不断给Claude提需求就可以了。

Claude很快在程序员群体传播开来，且由于编程是高价值场景，程序员以及相关的科技公司都愿意付费让AI提升自己的工作效率。Anthropic的年度经常性收入ARR快速追赶并超越了openai，成为前沿大模型实验室中事实的领头羊。大家才幡然醒悟，原来B端生产力场景才是LLM最好的落地场景，B端任务聚焦，很多任务也有相对明确的交付标准，最重要的是模型在B端场景被验证能带来生产力的很大提升，直接给B端用户创造价值，B端用户自然有很强的付费意愿。这样，大模型在B端生产力场景就形成了很好的落地闭环。

目前在所有年度营收 ARR 1亿美金以上的AI应用中，编程领域的产品总营收占比超过大半，包括Cursor、Codex、Claude Code、Cognition Devin、Lovable、Replit。Anthropic在编程场景的押注大获成功，OpenAI和国内的DeepSeek、智谱、Kimi也很快跟进，目前在这个场景的竞争非常激烈。当然，大模型的编程能力不仅仅只是一个垂类能力，随着交给AI的任务呈现越来越复杂，长链条、多步骤，甚至多Agent协同的趋势越来越明显，大模型可以通过编程解决直接执行有难度的任务。

除了编程，AI作为work agent目前在以下领域都有产品年度营收ARR达到了1亿美金以上，包括，多媒体影像生成：视频（Seedance、Kling、Runway）、音乐（Suno）、图像与设计（Midjourney、lovart）、短剧（libtv）、数字人（HeyGen）；智能客服（Sierra）；通用办公（Manus、Genspark）；企业知识管理（Glean）；法律（Harvey、Legora）；医疗（EliseAI、Abridge）。

### （三）personal agent 阶段

如果说 work agent 偏重于在一般人的工作场景替代或者帮助用户执行工作任务，那么 personal agent 就是在生活场景帮用户安排生活计划、处理琐事、节省时间等。人类对AI早期的想像其实都是类似个人助理的形态，例如诺兰电影《星际穿越》中幽默能干的TARS、《钢铁侠》中的Jarvis等。所以personal Agent其实是更容易被普通用户接受的AI形态，一个能陪你聊天、能解答你问题、在必要时还能帮你干活的助理。但是现在面向C端消费者的personal agent产品发展却远远落后于B端的work agent，显然是因为C端产品在寻找高频强需求场景时遇到了挫折，没有激发用户比较强的付费意愿。

即使有挫折，但是在 personal agent 类产品的尝试是没有间断的，其中有突破并曾经掀起了一股全民“龙虾热”的项目就是2016年1月正式命名的OpenCLaw。OpenClaw的目标是让AI能成为真正帮用户做事的个人助理。OpenCLaw本身不是基础大模型，它调用远程大模型API或者本地部署的大模型，它是在基础大模型之上的Agent Runtime + Harness + 工具执行平台。用户可以通过聊天软件（例如WhatsApp）给OpenCLaw下达命令，从而实现控制个人设备、执行命令，并完成任务。因为是部署在本地设备上，只要设备不关机，OpenCLaw就可以做到7x24小时待机或者执行任务，即使你在睡觉的时候。这点跟以往的AI产品还是有明显的差异化体验。但是“龙虾热”在公众中并没有持续很长时间，主要的原因有几个：1是有技术门槛，部署配置使用OpenCLaw步骤繁琐，没有技术背景的普通用户很难直接上手；2是安全风险较大，如果要让OpenCLaw在本地给用户干活，需要给它开放很多文件和操作权限，但是大模型本身有幻觉可能执行错误，再加上开源项目部署到本地容易被抓住漏洞入侵；3是没找到强需求的落地场景，用户在刚开始的兴奋尝鲜之后，往往不知道用它干什么，虽然“龙虾”听起来很能干；4是成本偏高，想让OpenCLaw单独运行在一台设备上，需要购置一台新设备。

“龙虾热”没有持续很长时间，但是OpenCLaw却给后续的personal agent产品打开了新的思路。大家就在想，能不能克服OpenCLaw推广遭遇的问题，给C端用户带来一款受欢迎并且价值可持续的产品？

## 二、那些有热度的 personal agent 产品

### （一）Muse

Muse是Meta于26年9月份上线的一款 personal agent 产品。这波 personal agent 的热潮如果说OpenCLaw是起始点，那么Muse就是引爆点。Muse的爆火个人觉得主要是以下几个原因：

1. 得益于Meta在C端强大的流量分发能力。Meta手握Facebook、Instagram等C端王牌产品，只要他想集中火力全力推广，新产品短期必然能在C端形成热度和传播。当然热度能否持续，还要看产品本身创造的用户价值能否持续。

2. Muse产品本身不错。Muse作为一个个人助理，它系统提示的第一行就是“你的目标是让用户的生活更美好”。相比于之前的工具和陪聊类产品，Muse有几个显著的特点：

（1）Muse是真的能做事的Agent。他能写代码，能预定餐厅，能帮你安排行程并下单旅行中的酒旅，他还能检查你的邮件，主动提醒你待办事项，帮你退掉被遗忘的订阅收费项目。

（2）Muse能7x24小时“always-on”来服务用户，每个用户的Muse在云端都有一个独立的虚拟主机，有文件系统、命令终端和浏览器。你所有的数据都存储在虚拟主机上，所有任务的执行也都在云端虚拟机。因此，Muse能全天候待命为你服务。

（3）Muse能主动为你服务。Muse被设定成有主动意识的个人助理，任务执行的中间结果或者它有一些新的建议，它都会主动的给你发消息。它被设定的目标就是帮你解决问题，完成待办事项，给你建议，让你的生活更加美好。

（4）Muse有全新的交互体验。Muse的主交互界面是一个有长期记忆的自然对话框，你可以像跟真人对话一样和Muse沟通，给它指派任务。对话框支持富媒体，不仅文字，还包括图片、视频、音频，需要用户明确控制时的结构化卡片等。

（5）Muse有长期记忆。你和Muse对话历史会作为长期记忆存在云端虚拟机上，会作为新会话的上下文帮助Muse更好的理解你的需求，记住你的任务。

（6）Muse可以多任务并行并持续追踪。Muse可以同时并行执行并跟踪多个任务，你的todo list可以一起交给它，无需等待上一个任务完成才能进入下一个任务。

（7）Muse尽可能让任务执行过程对用户透明。你可以在Tab页Goals跟踪目前Muse在执行哪些任务，跟踪每个任务的执行进度。Muse正在做什么也会在界面上有直接的文字提示。

3.Muse的安全机制有精心设计

OpenClaw之所以没有被大众长期接受，我觉得安全性是个很重要的原因。OpenClaw虽然有安全机制但高度依赖用户配置，例如有沙箱但是默认关闭，对于没有技术背景的普通用户安全配置可能不够，再加上大模型本身可能执行错误导致数据泄露和操作失误的风险激增。而Muse的设计是内建了很多安全机制的。Meta作为有几十亿用户的C端产品公司，它在推出Muse之前除了保证产品功能上能够吸引用户，同时很重要的一点就是要保证用户的数据和操作安全可控。Muse目前公开的安全架构是最系统的，核心优势是凭证隔离、独立授权、网络出口控制及人类审批组成了多层防线。Muse把执行环境隔离作为基础架构的一部分，从系统层面将“AI想做什么”和“AI被允许做什么”隔离。Muse还实现了对用户账户密码凭证的隔离，不给模型传真实的凭证，连接器使用的是替代凭证。

根据管理层在最新财报会议上透露，Muse目前已经有清晰的PMF（Product Market Fit）。目前最常见的用例是购物，超过四分之一的Muse用户参与其中，平均客单价超过200美元。除购物之外，最常见的用例是个人生产力工具，以及将Muse连接到邮箱和日历等服务。下一步，除了继续打磨产品，就是将Muse普及，形成规模化的网络。

### （二）Instinct

如果说Muse是大公司personal agent的产品代表，那么Instinct就是创业公司的产品代表。相比Muse，Instinct没有Meta强大的分发渠道，也没有那么多GPU卡。现实的选择就是循序渐进的增长，过程中不断迭代产品。Instinct在营销上是0花费，主要靠邀请制和口碑在传播，每天能够保持10%的速度增长。在营销和功能丰富程度上，Instinct显然无法与Muse竞争。看创始人Noah Shinn的访谈，目前Instinct的迭代非常重视产品设计和用户体验。

例如交互上，Instinct目前连独立的APP都没有，只有手机号、邮箱和聊天账号。有事你可以在WhatsApp上给它发消息、或者给它发短信、打电话，甚至有急事它也会主动给你打电话。创始人解释没有APP是因为他们认为用户不应该为了使用AI而要去学习新的软件，应该在他熟悉的地方就可以使用。这有一定道理，但也可能是短期资源有限而做的取舍，毕竟独立APP可以给用户带来更加完整丰富的交互体验，例如富媒体卡片这种Muse常用的交互Instinct就使用不了。

目前Instinct的增长速度虽然不及Muse，但是用户参与度很高，但Instinct特别强调产品要和用户很好的沟通，Understandability优于Capability。即用户要能理解正在发生什么，当他给Instinct下任务、交互时，他能预测接下来会发生什么。即Instinct要成为一个靠谱、被信任、能帮用户解决问题的助理或者伙伴。

Instinct在功能丰富度上不及Muse，它更追求在一些被验证的场景让用户有更好的端到端的使用体验，比如餐厅订位、旅行计划和机票酒店预订。在餐厅订位这个场景，Instinct不仅可以让用户免去拿号迟了吃不上，拿号早了会过号的苦恼，它还在设计一些新的功能，比如能让Instinct去跟订位系统沟通，在你过生日的时候优先让你订上座位，诸如此类。目前Instinct在用户量还不多的情况下，交易额已经达到10亿美金，约50%来自旅行场景。Instinct收入的来源也是对用户实际形成交易的抽成，他们认为，这种实际的交易达成是给用户创造了真实的价值，抽成更加合理，而不是通过引导用户注意力的方式来获利。这里有Instinct的一个认知，认为AI Agent会重塑互联网或数字服务行业，任何靠用户注意力和广告挣钱的公司，如果人换成Agent之后，都将面临巨大挑战。

Instinct相比Muse更早上线的一个功能是Instinct网络，即agent网络。这个功能设计的出发点是让agent代替人，去与朋友同事家人沟通协作。例如，你和朋友们想约一个聚餐，但是你周一有空，小明周二有空，小王周三有空，来回沟通好几次也不一定能敲定合适的聚餐时间。这个时候如果你和朋友都是用Instinct，且都加入了Trusted Person Network（可信联系人网络），那作为每个人代理的Instinct就可以先在日历上查日程确定每个人的空闲时间，然后把这个信息传给其他受信任的Instinct，最终协商确定时间，整个过程不需要人亲自参与。同理，如果需要组织活动，就可以让Instinct在网络上交流每个人平时的爱好，然后由agent网络达成共识。Instinct网络的目的就是把社交、协商、合作中机械重复人不想参与的部分全部交给agent去完成，人只需要享受自己真正感兴趣那部分。这中间比较麻烦的是数据安全，如何设计能让Instinct知道社交的边界，不会泄露允许之外的隐私数据给其他Instinct agent。

### （三）Karpo

Karpo是国内创业者开发的一款面向海外用户的personal agent产品。对比Muse和Instinct这种通用型personal agent，Karpo的定位就是本地生活垂类场景的personal agent. Karpo创始人也解释了路线选择的原因：一是因为通用agent是大厂的特权，创业公司只有在部分垂类场景把用户体验做的更好才有机会，而不是像大厂在通用agent赛道无差异化的竞争。总结来说，Karpo想做的是用户意图的捕获，以及供给的个性化生成。对Karpo来讲，创造一个能持续捕获用户意图的环境，比费劲去提升模型或者 Browser Use 能力的杠杆更高，因为后者会随着模型进步自然得到解决。

Karpo认为personal agent最重要的是获取意图。Muse和Instinct更强调任务的执行，解决的是很明确的需求，比如你要订餐厅、买机票，有点类似传统搜索的定位。而Karpo想再往前走一步，在用户还只有一个感受、没形成明确需求的时候接住它，然后基于意图进行供给的个性化生成，有点类似于传统推荐的定位。

用户首次对话时，Karpo会自我介绍：我很了解这个城市，很会吃喝玩乐，跟着我就对了。通过自我介绍来建立用户心智，Karpo想接手的是你的晚上、周末和假期。如果你对Karpo说“我今天心情不好”，Karpo大部分情况下会跟你说，“要不要出去喝一杯”或者“我给你找点能让你开心起来的事情”。它可能会给你推荐好喝好玩的bar，也可能会给你买一张你喜欢的歌手的演唱会门票。它想带给你的是一种探索、社交、及时行乐的生活方式。

显然，Karpo的重点不在于跟Muse竞争执行任务的能力，而在于本地生活场景中，怎么提前捕获用户意图，怎么建立本地生活供给的数据壁垒，以及怎么依据长期记忆生成个性化的供给。另外一点，Karpo强调它服务的是特定的一群人，区别于上一代产品服务于特定的需求（美团做外卖、滴滴做出行），personal agent天然就擅长在不同需求之间串联，反而不同人群的个性和生活状态是不一样的。

在商业化方面，Karpo目前还没有形成清晰的路径，可能会类似于Instinct的交易抽成。在使用场景上，从26年3月上线iMessage版本到现在，大约50%到60%的用户，主要需求是享受生活、探索、社交和交友，差不多20%是照顾家庭，还有10%是自我提升。

### （四）Dots

Dots是OpenAI在9月底推出的personal agent，依托于自研的强大基座模型GPT-6 Astra，Dots执行任务的成功率、稳定性相比Muse、Instinct更胜一筹，因此更适合需要agent解决复杂长期的任务目标的时候。和Muse一样，Dots同样有云端虚拟机、长期记忆和后台任务7x24小时“aways-on”的特点。

和Muse不同的是，Dots的野心不仅是personal agent，同样想做最好的work agent。目前已推出个人Dot，企业专用Dot，完整的多Dot团队也会逐步开放。考虑是openai推出的产品，它的竞争力来自于GPT-6 Astra、现有ChatGPT用户关系、超过4000个跨应用连接，以及与Codex执行能力的整合。因此，Dots有潜力成为最受欢迎的面向知识工作者的通用personal agent。

### （五）Duet

Duet是Anthropic团队推出的产品，同样依托自研的强大基座大模型Claude Opus 5.5。Duet的目标用户是专业人士和小企业主，为他们提供一个有判断力、能够主动发现问题的AI助理。Duet同样有独立的云端虚拟机、长期记忆、6000多个连接器和插件和后台任务“aways-on”。Duet目前定位偏work agent，尚不允许用户查看它的浏览器支持过程，对订票等个人生活任务的适配也不如专业工作任务成熟。

### （六）Grok Bot

Grok Bot是由原SpaceXAI和Cursor团队合作开发的agent产品，定位也更偏向知识工作、企业运营和数字员工协作，与Muse、Instinct等个人生活Agent有区别。由于Cursor团队在编程agent产品研发方面经验较丰富，多个自主agent协同完成工作是Cursor在编程产品上的最新形态，可以把Grok bot的多bot并行协作看成是这个理念在非编程场景的推广。

例如，在一家初创企业中，可以设置销售Bot、营销Bot、运营Bot 和工程Bot。销售Bot 维护CRM、起草客户跟进信息；工程Bot复现错误并形成工单；运营Bot检查账单和招聘事项。相比于前面介绍的personal agent产品，Grok bot最明显的两个特点是：

1. 多Bot并行，多个Bot可以相互发送消息，在群聊里讨论任务并交接工作。
2. 示范式学习：用户操作一次具体工作流程，Bot可以将其保存为 Skill 或 Routine，之后自动重复。

10月27日，WIRED发布了一篇六款personal Agent的同场体验，测试了新闻研究、午餐订购、日历冲突、旅游计划和主动支持等任务。测试涵盖 Dots、Duet、Grok Bot、Muse、Instinct 和 Gemini Spark。WIRED单次体验的主要结论如下（仅可参考）：

Dots：综合表现最佳。任务执行较稳定，尤其擅长跨邮件与日历发现问题，但使用门槛较高。

Muse：最适合普通用户上手。测试综合表现紧随Dots，安装和设置过程最简单。

Duet：交互界面最佳。任务跟进体验受到好评，但部分实际结果仍不稳定。

Instinct：短信交互存在争议。极简交互对部分人有吸引力，但认为不容易观察Agent正在做什么。

## 三、我们真的需要personal agent吗

10月21日，朱啸虎就在一场AI论坛上明确质疑，看不明白personal agent“到底能用来干嘛”。他的质疑基于以下四点：

1. 绝大部分人工作生活中不需要助理秘书。

2. personal agent没有高频场景，Muse和Instinct使用较多的旅行场景，不是高频任务。

3. 国内用户使用习惯不同于美国。90%的用户不用日历安排计划，90%的用户工作之外不用邮箱。现在用户大部分时间都消耗在短剧和其他娱乐产品上了。

4. 国内很多平台和APP不愿意给AI Agent开放数据，应用生态很难起来。

我觉得判断人是否真的需要personal agent，还是要从personal agent能给我们提供什么价值的角度考虑，以及需要付出多少成本。personal agent创造价值可以从两个角度观察：

1. personal agent是不是帮助我们省钱、省时间、省精力了。是否让我们摆脱了日常并不想花时间的琐事，让我们有更多的时间和精力做自己真正愿意花时间想做的事。不管是跟家人朋友相处、享受美景美食，还是读书提升自己，亦或只是追喜欢的剧打喜欢的游戏。总之，personal agent是否能让我们可以做更多自己喜欢做的事？
2. personal agent是不是拓展了我们的能力边界。是否让我们能做之前做不了的事。例如，我是个算法工程师，以前我自己开发个应用，遇到需要logo的时候，就只能在网上大量搜索选一个自己满意的图案再简单调整一下。但是有了personal agent之后，我就可以把自己对logo的想法（例如教育的主题），视觉效果（例如想要毕加索的线条、想要莫奈的颜色）等都告诉agent。agent从零开始给我出几个设计稿让我选，它会一边调整设计，一边跟我沟通了解我的偏好。我本来只是个算法工程师，那现在我也可以做设计师的工作了，那AI agent明显就拓展了我的能力边界。类似这类拓展我们能力边界的用例是否很多？

回到朱啸虎的质疑，他说大部分人不需要秘书。他是对的，但是如果这是一个比人类秘书更加专属私密、能力更强（不只是协调工作、日常事物，还能帮你改善睡眠、指导你的亲密关系，帮你规划开支），但是成本却更低的personal agent呢。人类秘书月薪两万，personal agent月薪一百甚至免费。更重要的是，personal agent还在解锁越来越多的场景。

归根结底，我是不是需要personal agent，取决于personal agent是不是真的“好用”。这里的“好用”是指它现有的能力真的足够帮我解决问题。例如，我最近想把家里的旧沙发换掉，我就不知道怎么处理旧沙发了，是直接找人拖走，还是当成二手卖掉。后来在各种二手平台和小红书上才了解到，直接找人拖走需要付一笔清理费，当成二手卖掉是更好的选择。但是卖二手沙发是个很耗时耗精力的事情啊。不管是在闲鱼卖，还是在小红书发帖子卖，还是在别人收二手沙发的帖子下面留言跟进，都需要付出大量精力来沟通推进。如果目前国内真的有personal agent产品能帮我把这类事做了，我肯定愿意每月花一百雇一个personal agent。

普通人在网上的时间大部分花在短视频、追剧、游戏这些娱乐产品上，这些本来也不是personal agent的目标任务。personal agent永远不会去代替人享受生活，就像Muse系统prompt的第一句——“你的目标是让用户的生活更美好”。

至于国内应用生态的的难题，我觉得只是一个快慢的问题，而不是永远不会改变的问题。只要这次的改变是从C端、流量端的用户习惯变化推动的，那么供给端的跟进改变只是时间的问题。美团不愿意开放商家外卖数据给agent，京东外卖肯定愿意。携程不愿意开放数据，同程旅行就会愿意尝试差异化竞争。然后行业里的第二第三就会倒逼龙头接受改变。就像Amazon封锁了Muse访问交易的行为，Shopify就同意了与Muse建立合作。

最终，要回答“是不是真的需要personal agent”这个问题。我认为只要随着大模型的能力越来越强，personal agent能解锁越来越多个人生活场景的任务，且在系统端保证安全可控（长期看应该问题不大），personal agent就会被越来越多人需要。当然这中间到底蕴藏了多少商业价值，则需要每个具体场景来具体分析。
