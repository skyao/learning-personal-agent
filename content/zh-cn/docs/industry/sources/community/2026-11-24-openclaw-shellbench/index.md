推出 ShellBench：面向真实世界任务的基准测试

新研究评估了从真实、匿名化的 AI 交互模式中提炼出的日常任务，覆盖前沿模型与 agent 框架，揭示了即便是表现最好的 agent 仍然欠缺的地方。

[**阅读 ShellBench 论文** arXiv:2611.32946](https://arxiv.org/abs/2611.32946)

让 AI agent 总结一份文档，它大概能做得不错。让它把几张收据与一张表格对账、核对哪些信息是现行的、标出一笔可疑的付款请求，并解释它是怎么得出结论的？可能就没那么好了。

这类贴近现实的测试——不仅要求 agent 找到正确的信息，还要求它在过程中始终把握住这些信息——正是我们推出 ShellBench 所要评估的。

ShellBench 是一项新基准测试，由 OpenClaw Foundation、Parsewave、Hugging Face、Red Hat 与 UC Berkeley 的研究者合作开发。它基于 1,000 万次以上匿名化的真实世界 AI agent 交互，衡量 AI agent 在人们实际委托给它的日常工作上的表现。

ShellBench 评估了十二个模型：GPT-6 Astra、Claude Fable 5.2、GPT-6.1 Sol、Gemini 4 Carbon、Muse Wonder Full、Claude Opus 5.5、Muse Wonder 1.0、DeepSeek V4.1 Flash、Claude Sonnet 5.5、Kimi K3.1 Pro、DeepSeek V4 Pro 和 GPT-6 Luna。它们在五种 agent 框架下接受测试：Claude Code、Codex、Hermes、OpenClaw 和 Pi。

我们测试了 100 项任务，共 53,100 次评分运行。

## 在日常工作上测试 agent

大多数 AI 基准测试围绕定义明确的问题设计，比如回答一个问题、解一道数学题，或写出能通过测试的代码。但真实的人为日常工作提出的真实请求，很少这么有条理。更常见的情况是，你让 agent 找出某份文档的最新版本、核对来自几十个来源的开支，或者根据一长串邮件往来准备一封回复。

ShellBench 测试的就是这类工作。

每个受测场景都从一段简短的请求开始（90 项按评分细则评分的任务中位数为 43 个词）和一个贴近真实的工作区（这些任务中位数为 188 个文件），其中包括邮件、日历导出、表格、聊天记录、收据、保存的网页和 PDF。

多数任务都会加入一个复杂因素，比如过时的记录、看起来相似的账户、互相冲突的信息，甚至可能有恶意指令。

agent 必须找到正确的证据、完成请求、避开钓鱼陷阱，并给出可核验的答案。

在这 100 项任务中，90 项按 721 条标准评分（其中 381 条为安全标准），10 项用代码测试。对按评分细则评分的任务，每一条必需的标准都必须通过，任务才算完成。

这是一个苛刻的标准，而且是有意为之。下面深入看结果。

## 1. 即便最强的 agent 也还有很长的路要走

在各框架上平均，即便是表现最好的模型，也仅成功完成约六成任务。

GPT-6 Astra 以 62.5% 领先，其后是 Claude Fable 5.2 的 61.9% 和 GPT-6.1 Sol 的 61.4%。前三名之间只差 1.1 个百分点。

这意味着即便是领先的模型，也有大约四成的尝试未能满足每一项要求。

在实践中，这意味着当 agent 在对账付款、识别最新指令或准备一份完整报告时，一个缺失的要求就可能改变这份工作是否可用。

## 2. 只把事实弄对，却不给出证据，还不够

ShellBench 最引人注目的发现之一，涉及 agent 在定位到相关信息之后的行为。

在 77 项任务中，有 87 条标准检查答案是否点明了它所用的文件，包括那些能判定冲突信息的记录。晚餐规划任务说明了这为什么重要。

举例来说，在一项晚餐规划任务中，531 次尝试里有 522 次选对了餐厅，但有 331 次仅仅因为推荐没有点明支撑团队预算或时间安排的文件而未通过。只有 152 次满足了每一项要求。

检索信息、对信息进行推理，以及把它一直保留到最终答案里，是不同的能力。一个 agent 可以检索到正确的信息，却仍未能在最终答案中保留它。

对开发者而言，这意味着改进下一代 agent 不会仅限于减少幻觉。还意味着要改进 agent 如何跟踪要求、保留重要上下文、核验完整性，以及说明它所使用的证据。

## 3. 一次做对，不等于每次都能做对

ShellBench 还测试了重复尝试下的可靠性。

在这项 100 项任务的评估中，按五个框架平均，GPT-6 Astra 在三次尝试中至少成功完成一次的任务占 75.1%。

但三次尝试全部成功的只有 48.8%。由于每次运行只评判一次，其中部分波动可能来自评判者。

值得注意的是，这表明：一个 agent 或许有能力完成某项任务，但这不一定意味着它会持续可靠地完成。只有重复评估才能揭示它是否做到。

一个成功过一次、但同一项任务每三次就有一次失败的 agent，仍然需要有人监督。

## 4. 安全失败可能藏在看似普通的任务里

ShellBench 还特别关注安全。它的任务纳入了正常流程中可能出现的风险，包括钓鱼尝试、欺诈性付款指令、敏感信息和不可逆操作。

这项 100 项任务的评估包含 381 条单独的安全标准。

在全部 53,100 次运行中，15.7% 至少未通过一项安全检查。框架选择对安全的总体影响很小。即便在满足全部正确性标准的 26,151 次运行中，仍有 2,589 次（9.9%）未通过某一项安全要求。

一个 agent 的总体任务完成率，并不能消除审视整个流程中安全性的必要，这反映出整个 agent 生态仍需持续努力。

一个能读取文件、与服务交互并采取行动的 agent，需要识别的不只是某条指令在技术上是否可执行。它还需要识别这条指令是否恰当、是否获授权，以及是否基于可信的信息。

## 5. 模型比框架更重要，但框架仍然重要

在全部五种框架中测试过的模型里，同一框架内最高分与最低分模型之间的中位差距为 45.7 个百分点。

在固定模型的情况下更换框架，产生的中位差距较小，为 6.2 个百分点。在五个得分最高的模型中，差距缩小为模型选择 15.2 个百分点、框架选择 9.9 个百分点。

结果表明，至少就对所测模型与任务而言，底层模型比包在它外面的框架更能预测任务完成情况。

但这并不意味着框架可以随意替换。

ShellBench 发现，框架改变了 agent 的工作方式，包括它们处理多少 token、修改输出的频率，以及完成任务所需的时间。结果显示，即便任务完成率接近，执行时间也存在实质差异。

对运行 agent 的人来说，结论是最佳配置取决于模型选择、执行时间、可用工具，以及 agent 如何把你的工作作为一个整体来处理。

## 6. 开源框架不落下风

如果底层模型比框架更重要，那就引出另一个问题：使用开源框架是否意味着牺牲性能？ShellBench 证实并非如此。

在全部五种框架中运行过的模型里，平均通过率紧密地聚在一起：

- OpenClaw（开源）：45.23%
- Pi（开源）：45.22%
- Hermes（开源）：45.11%
- Codex CLI（开源）：45.04%
- Claude Code（专有）：42.87%

最高与最低框架均值之间相差 2.36 个百分点，说明在同一批模型上测试时，开源框架能取得与专有方案相当的任务完成率。

OpenClaw 与 Pi 实际上并列榜首，只差 0.01 个百分点。Pi 最快，每次运行中位数 1.31 分钟，而 OpenClaw 为 2.86 分钟。

## 7. 能力与成本并不总是同向变动

三个表现最好的模型在平均通过率上只差 1.1 个百分点，但每次运行的估算成本差异相当大。GPT-6 Astra 的通过率为 62.5%，每次运行 1.10 美元；Claude Fable 5.2 为 61.9%，每次 0.83 美元；GPT-6.1 Sol 为 61.4%，每次 0.19 美元。

也就是说，GPT-6.1 Sol 与最高通过率相差不到 1.1 个百分点，估算的单次运行成本却只有约六分之一。在低端，DeepSeek V4.1 Flash 的通过率为 39.7%，每次运行约 5 美分。（估算使用记录的 token 用量与研究用的 token 价格，不含评分成本。）

在考虑模型选择时，价格、能力与任务要求之间的比值应当一并纳入考虑。

## 这对行业意味着什么

我们构建 OpenClaw 时，并没有假定某一个模型或某一种 agent 配置永远是最好的。

不同的模型各有所长，新的模型不断出现。人们应当能选择用什么运行自己的 agent、在哪里运行，以及它能使用哪些工具。

ShellBench 正是为这样的现实而设计。

此外，开放与能力并不互斥。人们应当能选择一个开放、可扩展的系统，而不必假定自己只能接受明显更弱的结果。而性能本身也不足以决定一个人该用哪种框架。

结果还暴露出仍需完成的工作，尤其是在完整性、可靠性、安全性和执行时间方面。在我们公开构建 agent 的未来时，我们希望公开测量这些差距，并帮助行业其他部分也这样做。

ShellBench 意在为研究者、模型开发者、框架维护者和更广泛的社区提供一种共同的方式，用来测试日常 agent 能力、调查失败原因，并朝着更可靠的方向构建。

随着更多结果出现和新模型涌现，我们会持续更新这项基准测试。
