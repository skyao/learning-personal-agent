> 灵光 2.0 想把 AI 从一次性的任务执行者，变成持续跟进生活事务的个人助理：记住需求、盯住变化，在你离开对话之后继续干活。背靠支付宝，它在信息管理、内容生产和交易执行三条线上各走到了哪一步，又不得不把哪些事交还给你，四个维度逐一实测。

![](images/img-01-a20e08.webp)

在大模型行业卷完参数、卷完长文本，又在 GUI Agent 的延迟与高错误率里撞得头破血流之后，Personal Agent 到底该怎么落地，成了 2026 年下半年所有大厂的必答题。

2026 年 10 月 27 日，蚂蚁发布灵光 2.0，成为国内大厂较早正式推出的 Personal Agent 产品之一。它试图把 AI 从一次性的任务执行者，变成持续跟进生活事务的个人助理：记住需求、关注变化，在用户离开对话后继续工作。

不过，平台边界仍然难以撼动。尽管各家都在隔空对标海外的 Muse，国内目前还没有一款 Personal Agent 能够自主完成淘宝上的购物闭环。即便是灵光公开展示的购物能力，也主要集中在选购规划、比价和持续跟踪。

背靠支付宝，灵光天然拥有切入真实消费与本土生活服务的高起点，这使它成为一个极具参考价值的行业样本：大厂沉淀多年的账户体系、支付链路与服务网络，究竟能支撑个人助理走多远？

带着这个疑问，我们从产品交互、长程任务、授权机制与生态边界四个维度，拆解灵光 2.0 已经跑通的路径，以及它依然不得不交还给用户的半成品地带。

## 01 三大场景实测

我们按一个人最常交给助理的三类事来测：替我记事（信息管理），替我出活（内容生产），替我花钱（交易执行）。

### 1. 信息管理

先看信息管理。打开 App，第一屏就是“帮你盯”，正在替你盯着的事以卡片形式陈列。

![](images/img-02-fe722c.webp)

用法很简单：口头交代一件事，比如某趟航班的价格、某件商品的降价、某个截止日期，它会一直记着、定时去查，有变化时弹窗提醒。用户不需要反复回来追问，这正是 Personal Agent 区别于 Chatbot 的核心体验。借助本地权限，它还能管理你的闹钟和日历。

![](images/img-03-f8fb30.webp)

![](images/img-04-9cd3de.webp)

连接上支付宝后，灵光可以帮你做每月的账单分析。而且不止于静态数据，通过简单的提示词，它就可以帮助用户做到主动每月消费管理。

![](images/img-05-f5c222.webp)

规划类任务上，灵光同样可用。我们让它做了一份慕田峪长城游览攻略，最终它给出了一份完整的时间表，并能一键添加进本机日历，从规划到落进日程，链路是通的。不过过程中需要用户补充不少信息，它更像一个和你一起把计划做细的协作者。

![](images/img-06-9de9fc.webp)

![](images/img-07-03f559.webp)

授权设计上，灵光采用按需授权：它不会在首次使用时一次性索要所有权限，而是在任务需要调用某项服务时，才弹出相应的授权请求。这降低了用户一上来就交出全部权限的心理门槛，也与 APASS“被允许做什么”的思路一致。

在权限边界上，灵光整体收得比较紧。以百度网盘为例，连接之后，它对整个网盘拥有检索权，能搜到、看到所有文件，但操作权只限于它自己的一个专属文件夹，可以在里面整理文件，却不能把文件移出或复制出去。这种“看得宽、动得窄”的设计偏保守，对用户数据来说是一种保护。不足之处在于边界不够透明：它不会事先说明哪些操作做不到，往往要实际尝试之后才会告知，用户需要多花一点时间摸清它的能力范围。

![](images/img-08-99a9e7.webp)

### 2. 信息管理

### 3. 交易执行

交易能走多远，取决于 Agent 能连上多少服务。灵光的连接系统分两类：应用服务包括支付宝、钉钉、飞书、邮箱和百度网盘；系统服务可以调用手机本地的日历、位置、文件和短信，还能编辑 iCloud 里的文件。

![](images/img-15-67b4e1.webp)

从这张清单可以看出，灵光当前的交易能力主要依托支付宝生态展开。在这个范围内，电影是体验最完整的场景：说清片名、时间和大致位置，它能查到具体院线、具体影院的场次，一路推进到选座环节，把选座链接直接交给你，用户点开即可选座付款。

![](images/img-16-35ad1f.webp)

机票的体验与之接近。查询比较之后，它能给出对应航班的链接，直接跳转到携程完成预订。

![](images/img-17-63bb71.webp)

酒店、餐馆和演出这类预订场景，目前以信息服务为主：灵光会查信息、给推荐、讲理由，响应速度很快，但最终预订这一步仍需用户自行完成。

![](images/img-18-eb26bb.webp)

外卖、网购、打车，以及淘宝跨店比价、取消订单、退货、联系客服等更复杂的操作，当前版本尚未覆盖，灵光会明确告知用户暂时无法办理；售后环节目前支持查询快递进度。

![](images/img-19-828fc8.webp)

总体来看，灵光在交易上的定位是替用户挑好、选好，把最后的确认和付款留给用户本人。对一款强调“管事”的产品来说，这是一种相对克制的设计取舍。

跳出具体场景，灵光最突出的优点其实是门槛低。打开即用，不需要配置，也不需要理解什么是 Agent。

日常绝大多数任务，它的响应都非常快。交互方式也不止打字：语音对话模式可以像打电话一样直接聊，交互足够自然，能够满足用户练习英语的场景需求；打开实时识别，摄像头对准物体，它就会自动识别并弹出相关信息。这些设计的共同指向，是把一个复杂的 Agent 系统包装成普通用户拿起手机就会用的工具。对国内大多数还没接触过 Personal Agent 的用户来说，灵光很可能是他们的第一个入口。

![](images/img-20-22a701.webp)

## 02 先修路，再算账：当成本跑在商业模式前面

为什么是蚂蚁率先在国内大厂里打出了 Personal Agent 这张牌？

如果只把灵光 2.0 看作一个独立的 AI 应用，很容易低估它在蚂蚁集团内部的战略位置。在过去二十多年里，支付宝连接了超过 10 亿用户、8000 万商家和上万项民生与商业服务。但行业里一直有一个共识：由于传统搜索框和九宫格货架的交互限制，支付宝庞大的服务生态里，真正被高频唤醒和充分开发的比例可能只有 10%。大量的长尾服务平时都静默地沉睡在水面之下，因为没有人会每天主动打开几十个小程序去挨个翻找。

在蚂蚁集团 CEO 韩歆毅的判断里，AI 时代的商业流量逻辑正在发生根本性重写——可能从过去的“抢时长”全面转向“接意图”。一个 24 小时替用户惦记着事的智能体，正是捕捉意图、唤醒那另外 90% 沉睡生态的最佳探针。但韩歆毅也坦承，眼下智能体的供需两端尚未形成正循环：用户想用，商家侧却还没有准备好足够优质的智能体服务。

面对这个“鸡生蛋、蛋生鸡”的早期困局，蚂蚁选择的应对策略是“先修路”。

过去大半年里，蚂蚁几乎把智能体商业闭环所需的底座挨个铺了一遍：在支付端，今年 5 月支付宝披露已完成 3 亿笔智能体支付，并相继推出了专门面向机器调用的 AI 支付、Token Pay 和 AI 钱包；在信任端，蚂蚁拿出了自研的 APASS（智能体可信基础设施），把身份认证、意图安全、授权密钥隔离与隐私保护直接写进运行底层；而在供给端，蚂蚁不仅推出了帮助商家快速构建智能体的“阿宝”，还设立了每年 1000 万元的“智能体涌现奖”，试图用真金白银把开发者和商家的供给催熟。

但落到灵光 2.0 这款产品本身，商业上的账其实还没算通。

在目前的实际运行中，灵光在涉及花钱和履约的环节展现出了极度的克制。用行业对智能体自主权的分级来看，灵光的交易能力目前依然停留在辅助决策与跳转引导，距离全自动闭环代办还有相当长的一段距离。既然交易没有真正闭环在 Agent 内部，「交易抽佣」这套最性感的商业模式就暂时无从谈起。

因此，灵光 2.0 眼下的战略价值，更像是一支探路先锋：替蚂蚁抢占“主动管事”的用户心智，在真实场景中积累最宝贵的长程任务数据，同时给自家的 APASS 可信基建打磨出一个标杆样板。

然而，收入模式还在摸索，算力成本却已经实打实地跑在了前面。

在灵光 2.0 的架构下，每一个“帮我管”的进度条背后，都是一台在云端持续驻留、定时唤醒的独立主机。试想一个极其普通的场景：一个重度用户随手在后台挂上十个“每两小时查一次价或巡检一次状态”的长期任务，哪怕他一整天都没有点开过灵光 App，系统在云端每天也要为他执行上百次网页检索、接口拉取与模型推理。

在“管得越多、花得越多”而变现链路尚未跑通的阶段，如何扛住指数级膨胀的并发轮询成本，是灵光迈向千万级国民应用前必须解开的财务死结。

## 03 结语：那些宏大叙事还有多远

把灵光 2.0 的实测结果抽离出来，重新放回整个 AI 行业的宏大叙事里，我们会发现，人们期待的那些终局拼图，距离今天的远近其实并不相同。

**离我们最近的是基础设施的重建。** 围绕 Agent 的数字身份、最小颗粒度授权、机器支付（如 Token Pay）以及全链路操作存证，正在以肉眼可见的速度工程化落地。这一层的技术并不存在难以逾越的黑科技，真正的卡点在于行业标准各自为政——当每家大厂都试图定义自己的可信与支付底座时，跨平台的信任互认还需要漫长的博弈。

**排在第二位的是生态打通，而这从来都是一个利益问题，而非技术问题。** 尽管灵光 2.0 引入了 MCP 和 CLI 协议试图拓宽手脚，但在核心交易链路上，它的能力半径基本仍以支付宝生态为边界。中国用户高频使用的微信聊天、美团外卖、淘宝京东的深层交易、滴滴的网约车调度，目前依然接不进来。这与大洋彼岸正在发生的戏码如出一辙：当 Meta 推出 Muse 时，渴望流量的独立站底座 Shopify 选择了拥抱，而手握闭环电商帝国的亚马逊则毫不犹豫地筑起高墙。没有哪个超级平台愿意轻易交出用户界面，沦为别人家 Agent 背后静默的 API 管道。

**至于被反复提及的“超级入口迁移”，则还要更远一些。** 只要在盯完机票价格、选好外卖套餐、挑中双 11 商品之后，最后那一步依然需要弹出链接、跳转回原本的 App 里去完成确认和付款，所谓的流量入口就没有发生真正的转移。Agent 只是接管了交易前的“信息摩擦”，却还没有接管交易本身。

**而最遥远的，是真正的 A2A（Agent to Agent，智能体与智能体的自主协同）。** 遇到航班延误去和酒店协商免费取消、买到瑕疵品去和电商客服交涉退货赔偿、或者替你去和餐厅沟通改期留座——这类需要跨主体博弈、协调与谈判的复杂任务，灵光目前还做不到。而在天平的另一端，千千万万的商家侧也远远没有生长出足够多、可被外部直接调用的服务型 Agent。

从“问答”到“管事”，再到真正的“托付”，智能体每往上走一级，都需要底层模型、平台生态与商业规则在同一时刻就位。灵光已经推开了第一扇门，但通往下一级的钥匙，并不全握在蚂蚁自己手里。
