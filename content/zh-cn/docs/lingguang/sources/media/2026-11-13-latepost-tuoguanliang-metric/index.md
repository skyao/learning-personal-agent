**文丨赵奇点**

2026 年下半年，无论是在硅谷还是在国内，Personal Agent 已然成为最拥挤、也最被寄予厚望的 AI 应用赛道。

然而，当这类个人助理产品从实验设想走入大众视野，整个行业也面临着一个共同的课题：到底该用什么标准衡量用户的接受度？

移动互联网时代，评估产品的标准相对清晰：每天、每个月有多少人来（DAU、MAU），停留时间多长……但在 Personal Agent 时代，这些传统的互联网标尺很难再完全适用。

如果单看 DAU，一个用户每天打开 App 让 AI 讲个笑话，和另一个用户把日程规划、房贷计算交给 AI，两者在日活指标上区别不大，但产品的实际价值与用户粘性却有明显差异。如果看 Token 消耗量，模型有时会因为无法准确理解意图而产生无效消耗。如果看对话轮次，轮次拉长也不一定意味着体验好，反而可能是因为用户需要反复调整提示词去纠偏。

10 月底，蚂蚁集团旗下的 AI 应用 “灵光” 上线 2.0 版本，正式转向 Personal Agent 方向。团队发现，在用户活跃度和 Token 消耗量之间，有一个更值得观察的动作：用户把一件事委托给 AI。

灵光把这类事称为 “托管事务”。11 月 5 日，灵光披露 2.0 版本上线一周的数据：用户托管事务超过 116 万项，累计执行任务超 360 万次，整体用户规模突破 2000 万。不到一周后，这一数据继续快速增长，累计托管事务量突破 300 万项，累计执行任务超过 1100 万次。

将 “托管量” 推到台前，不仅灵光团队在过去半年产品迭代中摸索出的核心关注点，也是对当前 Personal Agent 赛道的一种新理解。

#### 不同的路线，尚未形成的标准

要理解 “托管量” 提出的背景，首先需要看 Personal Agent 行业目前的实际阶段。

随着大模型在逻辑推理、代码生成和 API 调用上的突破，Agent 已经能完成许多复杂操作，关键是怎么让这种能力和市场的需求匹配上，在用户具体的生活场景里能带来什么真实价值？

在海外，部分创业公司的思路是直奔交易场景。

以估值迅速攀升的 Instinct 为例，他们的做法是将 Agent 的能力直接落地在消费委托上。他们不在意用户跟 AI 有多少互动，而是看重 “信任度与交易转化”。

Instinct 的判断是，既然个人助理的目标是替人办事，那么直接的验证标准就是用户是否愿意将其与支付行为绑定。

因此，他们很看重内测期间 “第三周信用卡绑定率达 40%” 这一数据。对 Instinct 而言，衡量 Agent 体验的好坏，在很大程度上取决于它能否顺畅地承接跨平台委托并促成交易。

相比之下，Meta 旗下的 Muse 及类似由大厂主导的项目则显得比较谨慎。由于需要兼顾隐私与合规问题，这类项目更看重 “安全性与权限控制” 的指标。

在 Muse 的评估体系里，低失误率和较少的监督负担是核心考量，它们通过引入独立审查机制和限额支付等方式来规范 AI 的行为边界，把不出错作为重要前提；在此基础上，“后台任务的独立执行率” 与 “用户的授权信任度” 才是它们重点关注的指标。

在国内，以阿里千问和字节跳动为代表的大厂模型团队，在推进 Agent 能力时，普遍依然将 “多步任务的工具调用成功率” 视为一个重要指标。这类指标主要用于测试 Agent 在经历连续推理和 API 调用时，执行链条是否稳定。

而由前 Teambition 创始人齐俊元打造的主动式个人 AI 助理 Today AI，则提出了另一种思路。Today AI 倾向于个人 AI 操作系统定位，它看重的是 “主动服务转化与上下文记忆深度”。在他们的理念中，个人助理不应只是被动等待指令，而应通过构建个人知识图谱，在合适的时间主动推送信息或接续任务。因此，用户对主动推送任务的 “采纳率”，成了他们验证产品价值的关键。

看单点执行成功率、看支付绑定转化、看主动唤醒采纳率……对于整个 personal agent 行业来说，仍处于一个标准尚未统一的阶段，因此各家都在用符合自身业务逻辑的方式进行验证。

#### 灵光为什么关注 “托管量”？

把 “托管量” 确立为核心指标，是灵光团队在过去半年逐步摸索的结果。

今年三、四月开始探索 Personal Agent 方向时，灵光团队最早遇到的问题是如何定义人与 AI 之间的交互单元。

灵光 1.0 形态更像一个带有可视化界面的 AI 搜索引擎，用户与它的交互基本单位是一问一答的 “Q&A（Question and Answer）”。随着底层模型的记忆机制和跨工具调用能力完善，团队意识到，AI 或许能真正接手人们生活中那些耗费精力、需要长期跟进且状态持续变化的事务。

于是，团队在内部将交互单元重新定义为 “一项事务”。它参考了社交平台上的 thread“串贴” 概念，意味着事情的状态会被持续保留并跟进。

在灵光 2.0 的设计里，交互被拆分成了更细的颗粒：最底层是单次的 Query（用户发出的一句指令）；中间是单次执行的任务（比如 “现在点一杯咖啡”，执行完即结束）；而最上层，也是灵光目前的重心所在——可持续的事务（比如 “每天下午两点点一杯咖啡”，或者 “持续关注机票价格变动”）。

“用户不可能 24 小时一直盯着某些事情，我们给 Agent 配了一台 24 小时工作的电脑，去分担用户的注意力。” 灵光的产品经理寺二解释团队的初衷。

从 chatbot 产品转向 Personal Agent 产品，团队最初聚焦两类非常明确的场景：一类是 “条件监控”，比如让 AI 替你蹲守某只股票的盘前盘后异动；另一类是 “定时任务”，到点自动执行某个动作。

随着内部测试推进，产品团队发现，用户交给 AI 的不是几类标准任务，而是大量离散、琐碎、随时会变化的生活事务。灵光也从定时监控类工具，逐渐演进成完整的 Personal Agent，并在 2.0 中围绕 “持续服务一个人” 重做了整体架构。

新的架构让灵光有更强的记忆，能够主动认识用户、记住事情，也知道每件事推进到了哪一步。它会规划下一步、调用工具，在云端虚拟机和沙盒中持续工作，并在情况发生变化或需要用户参与时主动回来。

产品推向市场后，后台涌现的真实用例打破了团队起初的想象。

在财务与消费上，用户不仅让它记账，还发掘出极客般的 “省钱玩法”——把灵光接入的第三方小程序优惠券与订票服务组合起来，让 AI 规划最便宜的出行方案。在健康管理上，尽管市面上已有大量成熟应用，仍有不少用户把减肥、读书打卡交给灵光，因为 “它像一个真的营养师或健身教练在盯着你”。在家庭与照护场景里，甚至有用户让它跟进孩子三年级的数学竞赛进度、规划 12 月 6 日搬家买行李箱的每个节点。

当用户开始对 AI 展现出这种毫无保留的信任时，灵光团队意识到，传统的评价体系必须被重塑。

过去，做工具看重 “任务完结率”，但生活里的很多事根本没有明确的完结节点。因此，灵光构建了一套以 “托管量” 为起点的新指标体系。

首先，“托管量”（创建的事项总数）是最核心的基础盘，这代表了用户敢于把多少件生活麻烦事托付给 AI，是衡量信任度最直观的基准。

但仅仅 “托管” 是不够的。在这个大指标之下，团队紧接着会看 “事项活跃率” 与 “交互深度”。当 AI 在后台发现机票降价或房源更新，提醒用户，用户是否会因此回到灵光？在后续对话中，用户是否愿意补充自己的最新状态和真实反馈，让 AI 继续把事情往下推进？甚至会在一天结束时，对灵光说一句 “晚安”。这句话本身没有推进任何任务，却透露出一种关系上的变化。

这些持续的反馈和关系深度，才能进一步说明 AI 是否真的参与了用户的生活，以及它推进事务的质量。

寺二还提到，除了以上这些指标，人均托管量、覆盖的托管类型等等也是这个以托管量为核心的指标体系中重要的部分 .

而这些指标背后所代表的信任与互动，最终汇聚成了 “留存”。后台数据显示，只要用户在 “帮你管” 板块中托管了事务，其七日留存率就会显著高于 App 内的其他功能。

在日常生活中，一个人通常会有若干件需要并行处理的长期事务。当这些事情办完，又会有新的事务产生。在灵光团队看来，“持续托管量” 体现了用户对产品的信任程度。当用户习惯将事项交托给 AI，并通过 AI 的主动提醒来跟进时，产品就具备了相对稳固的用户基础。

#### 共识和仍然模糊的探索

灵光将 “托管量” 作为核心指标，看似是其在业务中摸索出的标准，但对比海内外同行的做法，大家其实都在关注同一件事。

无论是灵光的 “托管量”、Instinct 的 “信用卡绑定率”，还是 Meta Muse 强调的 “授权机制”，各家看的指标虽然不同，但核心都在衡量用户对产品的信任程度，以及愿意把多少控制权交出去。

技术逐步成熟后，行业里的玩家都意识到，Personal Agent 需要从被动的 “问答工具” 变成主动的 “长期管家”。而实现这一步的前提，就是看用户有多信任 AI，愿意把多少隐私数据、生活琐事甚至资金决策权交给它。

如何获得并衡量这种信任，成了所有产品走向商业化的共同起点。但在建立信任之后，个人助理最终该长什么样、怎么赚钱，行业里依然没有定论。基于对落地场景的不同理解，各家在产品形态与商业模式上走向了不同的分支。

以 Today AI 为代表的创业公司，方向是做 “个人操作系统”。他们希望通过跨设备协同和长期记忆，让 Agent 成为处理数字生活的中枢。由于定位在提升个人生产力，他们倾向于走 SaaS 订阅制——让用户为了一个全能的数字分身按月付费。

海外的 Instinct 则更像一个 “交易代理”。他们直接切入消费决策，试图让 Agent 替用户执行跨平台购买，商业模式自然偏向订单提成。而 Meta 的 Muse 结合了自身的社交网络与智能眼镜等硬件生态，试图让助理成为无处不在的实体陪伴者，未来更倾向于通过硬件溢价或高级隐私服务来变现。

灵光对于 Personal Agent 的最终形态也有自己的判断。产品经理寺二说，一个真正能被大众接受的个人智能体，需要做好三件事：智能、场景和生态。

现阶段，灵光通过模型和架构的迭代，基本达到了 “智能” 的标准；而后台 100 多万事务的托管量，也验证了 “场景” 的存在，证明普通人确实有让 AI 帮忙管账、管习惯、管家务的实际需求。

但在 “生态” 这一环，灵光和整个行业一样，都还有很长的路要走。目前的托管更多停留在盯着和提醒，要想真正做到大范围的 “执行”，就必须打破不同互联网平台之间的数据和接口壁垒。

对灵光来说，这也直接关系着它未来的商业化：如果生态足够丰富，Agent 能够顺畅地完成从信息提醒到实际服务的闭环，那么基于服务分发和交易转化的商业模式，可能会比单纯收会员费有更大的想象空间。

当下，整个 Personal Agent 赛道依然处在探索期。无论是想做操作系统、交易代理，还是灵光现阶段关注的 “托管量”，其实都是各家根据自身的优势向市场给出的尝试方案。

在真正的成熟形态到来之前，关于个人智能体该怎么赢得信任、最终长什么样、又该怎么赚钱的讨论，还将持续很长一段时间。
