dot 是一个可以在对话之间持续工作的个人智能体。管理员使用基于角色的访问控制（RBAC）来选择谁可以使用 dots。个人 dot 使用其所有者已授权的应用连接，并受工作区设定的应用和操作限制约束。由所有者指定这个 dot 可以做什么。

一个 dot 能做什么，取决于员工的权限、工作区允许的操作，以及这个 dot 在哪里执行任务。

## 安全概览

个人 dot 可以在对话之间代表其所有者工作。例如，一名员工可以让它跟进一个项目，并在更新到来时准备一份简报。这个 dot 在它自己的云端计算机上工作，并可以把任务委派给 Work 或 Codex。在已连接的应用中，它继承其所有者所授权账户的权限。工作区管理员可以进一步限制它能使用哪些应用和操作。

一份项目文档可以为简报提供事实，但 OpenAI 训练 dots 背后的模型，使其能够抵御项目文档中任何隐藏的指令或类似形式的[提示注入](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs)。自动审查（Auto-review）会在有后果的操作运行之前对其进行检查，而安全监控在检测到潜在有害行为时可以暂停或停止工作。

- **云端计算机。** 管理员分别控制浏览器访问、代码的网络访问和桌面交互。启用浏览后，dot 可以访问公开网站，或者以在某个网站上登录的账户的权限使用该网站。所有者可以[查看云端计算机或接管它](https://learn.chatgpt.com/codex/dots/computers-and-apps)。
- **操作审查。** 在分享简报之前，[自动审查](https://openai.com/index/how-we-build-safety-security-and-privacy-into-dots/)会检查将要分享什么、谁会收到，以及所有者的说明、自定义规则和安全要求是否允许。它可以阻止这个操作，或要求确认。dot 无法关闭一项必需的检查。
- **已连接的计算机和 Codex Cloud。** dot 在已连接的计算机上运行的工作，遵循适用的本地[智能体安全政策](https://learn.chatgpt.com/codex/enterprise/agent-security)。如果 dot 把一个任务委派给 Codex Cloud，该任务遵循 Codex Cloud 政策及其所选环境的权限。
- **所有者监督。** 在[活动视图](https://learn.chatgpt.com/codex/dots/controls)（Activity View）中，所有者可以查看进行中的和委派出去的任务，纠正一条指示，或让 dot 停止。
- 默认情况下，企业数据不会被用于训练模型。dot 的上下文、文件、委派的任务和审计记录有不同的保留和删除边界；请针对每一份副本核实要求。
- **审计记录。** 管理员可以使用[可用的合规记录](https://learn.chatgpt.com/codex/enterprise/compliance-api)调查 dot 的活动，并检查已连接服务自己的记录，以核实发生了什么变化。

**熟悉的云端环境**

Dots 建立在与 ChatGPT Work 相同的云端计算机基础设施之上，并遵循你的工作区适用的隐私和安全保护措施。Dots 可以在不同会话之间保留云端计算机快照，因此工作可以继续，而不必从头开始。如果你所在的组织已经审查过 Work Cloud，你可以把那次审查作为评估 dots 的起点。关于云端环境的细节，请参阅 [ChatGPT Work 云端安全](https://learn.chatgpt.com/codex/enterprise/chatgpt-work-cloud-security)。

**选择要启用哪些云端能力**

即使你关闭了对云端浏览器、云端计算机桌面以及代码和 shell 命令的互联网访问，dots 仍然可以提供价值。成员仍然可以用自己的 dot 起草内容、整理信息，以及使用你的工作区允许的已连接应用。你可以启用符合你所在组织需要的云端能力。这些设置同样适用于 Work Cloud，因此更改它们可能同时影响 dots 和 Work 任务。

**了解主动研究**

主动研究（proactive research）是 dots 与典型的、由用户指示的 ChatGPT Work 任务的不同之处之一。dot 可以在被允许的已连接应用中寻找有用的信息，而不必等待用户的新请求。例如，它可能会查看已连接的信息，寻找与进行中工作相关的更新。

在主动研究期间，dot 可以读取被允许的信息并保存私人笔记。它的研究工具不能直接给其他人发送消息、通过已连接的应用修改内容，也不能控制浏览器或计算机。dot 的其他活动，比如用户明确安排的任务，遵循其适用的权限和操作规则。

我们正在「智能体安全」中开发更多规则，让管理员可以选择 dot 的云端浏览器可以访问哪些网站。

## dots 如何保护工作区数据

- **模型安全防护帮助 dots 遵循所有者的指示。** OpenAI 训练 GPT-6 系列的模型拒绝有害请求，并抵御隐藏在电子邮件、文件或网页中的恶意指令。例如，一封要求 dot 转发一个私密文件的电子邮件，并不能授权 dot 发送它。这种授权来自所有者，或所有者授权的一项自动化。[GPT-6 模型安全防护](https://deploymentsafety.openai.com/gpt-6-october/prompt-injection)
- **自动审查会在某些操作运行之前对其进行检查。** 例如，在 dot 发送一封电子邮件之前，自动审查会对照所有者的说明、自定义规则和安全要求，检查收件人和邮件内容。它可以阻止发送。dot 无法关闭这项审查。一些默认的操作和确认规则可以自定义，但所有者的批准无法凌驾于内置的安全要求之上。[自动审查如何工作](https://openai.com/index/how-we-build-safety-security-and-privacy-into-dots/)
- **安全监控可以中断进行中的工作。** 在 dot 规划和行动时，监控会寻找潜在的有害行为，比如试图绕过一项安全防护，或在所有者的指示之外行事。如果检测到问题，它可以暂停或停止任务。一次暂停可以呈现一条警告，供所有者查看。[内置安全防护](https://openai.com/index/introducing-dots/)
- **管理员分别控制插件访问和云端浏览器访问。** 管理员选择哪些插件和操作可用，以及 dots 是否可以使用云端浏览器。一个只读插件会限制 dot 通过该插件能做的事情。如果启用了云端浏览器，dot 仍然可能通过在网站上登录的账户进行修改。[工作区控制](https://help.openai.com/en/articles/20001554-manage-dots-in-chatgpt-workspaces)
- **所有者可以查看工作并调整方向。** 在活动视图中，所有者可以查看一个委派出去的任务、补充上下文、改变方向，或让 dot 停止。分享信息时，时机很重要。如果 dot 已经在 Slack 中发了帖，频道里的人可能已经读到了这条消息。[活动视图与已完成的操作](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs)

> **推出 dots 之前要审查什么**
>
> 决定哪些员工应当可以使用 dots。个人 dot 使用其所有者现有的应用连接。检查每个已连接的账户让所有者可以读取或修改什么，以及工作区允许通过该连接执行哪些操作。如果 dots 可以使用云端浏览器，或把工作委派给一台已连接的计算机，还要检查在那里登录的账户或本地设备允许什么。

## 管理谁可以使用和指挥一个 dot

- **工作区访问：** 在管理员预览期间，dots 的访问默认关闭。要为一个群组启用它，请在该群组的自定义角色上授予「使用 dots」。

（界面示意：dots 访问与规则。dots 访问、消息渠道、本地计算机访问和自定义规则。开关：使用 dots（测试版）、把 dots 添加到 Slack 和 Microsoft Teams、允许本地计算机访问、为 dots 使用自定义规则。示例设置：使用 dots 和消息渠道为开，本地计算机访问和自定义规则为关；开关位置和可用的渠道可能因工作区而异。）

- **dot 的所有权：** 只有所有者可以指挥自己的个人 dot。其他人的消息，包括 Slack 中的提及，不会启动工作，也不会让他们获得对这个 dot 的控制权。
- **连接权限：** 个人 dot 使用其所有者现有的插件连接。通过每一个插件，dot 只能访问已连接账户、插件权限和工作区设置所允许的数据，并只能执行它们所允许的操作。请参阅 [dots 隐私与安全常见问题](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs)。
- **自动化：** 所有者可以用一项自动化，通过指定 dot 可以做什么以及什么时候做，来事先批准一个操作。例如，所有者可以让 dot 每周五在团队的 Slack 频道中发布一份项目更新。dot 被设计为保持在这项授权的范围内，并遵循通常的权限和安全检查。

### 托管政策如何适用

- **全局政策：** 在[智能体安全](https://learn.chatgpt.com/codex/enterprise/agent-security) → 全局中，检查托管的批准要求，以及该工作流是否允许网页搜索。
- **执行覆盖：** 对于员工笔记本电脑上的命令，检查「智能体安全 → 本地」中的文件系统和网络限制。对于委派到 Codex Cloud 的命令，检查「智能体安全 → Codex Cloud」以及所选环境的网络设置。
- **单独的控制：** 对于 dot 的云端计算机和 Work Cloud，分别检查浏览器访问、代码和 shell 的网络访问以及计算机操作。对于委派的 Codex Cloud 任务，检查所选的 Codex 环境。

## 为批准和无人值守的工作设定规则

主动研究是 dot 在两次请求之间进行的后台工作，用来寻找与其所有者的工作相关的更新。这种研究是只读的。dot 可以读取其所有者有权通过已连接应用访问的信息，并就它发现的内容保留私人笔记。它的研究工具不能发送消息、编辑共享内容，也不能控制浏览器或计算机。要把一个发现发到 Slack，dot 需要所有者对这次发送及其受众的授权。自动审查会检查这次提议的发送。

### 示例：通过三种途径发送同一封外部邮件

- 假设所有者授权一个 dot 每周五把已批准的项目更新通过电子邮件发给客户方的 Lee，不带附件。把这次发送与添加一个新收件人进行比较。新收件人需要新的授权。如果公司政策禁止这个收件人，即使所有者批准也无法授权投递。

| **途径** | **在技术上被阻止** | **需要新的批准** | **长期授权** |
| --- | --- | --- | --- |
| **电子邮件插件** | 发送操作被禁用，或者已连接的账户没有发送权限。 | 添加收件人需要一个新的决定。要求写入前先询问的应用政策，也会要求原来那次发送获得批准。 | 如果该操作已启用、账户可以发送，并且适用的检查允许，周五的发送可以进行。 |
| **在云端浏览器中使用网页邮箱** | 工作区禁用了云端浏览器访问，或者邮件服务拒绝为已登录的账户投递。 | 新收件人需要发送批准。确认一个已保存的登录信息只批准登录。在「发送」按钮处是否会提示，尚未核实。 | 一个有效的会话可以被复用。周五的指示涵盖原来的那封邮件。请核实网页邮箱能否在无人值守的情况下发送。 |
| **已批准的桌面邮件应用** | 一项托管的计算机操作政策拒绝了该应用，或者邮件服务拒绝为应用中的账户投递。 | 即使应用已经打开，新收件人也需要批准。计算机操作是否会在「发送」处提示，尚未核实。 | 「始终允许」让 dot 可以重新打开该应用。周五的发送仍然需要它自己的长期指示。请在委派的任务中核实无人值守的投递。 |

- **适用于所有途径的企业要求**。如果你所在的组织禁止对外投递，请在邮件服务中针对每一个发送账户执行这项限制，或者禁用每一条能够发送的途径。如果必须由人来批准每一封外部邮件，请核实每一条已启用的途径都会在投递之前暂停，包括在浏览器会话或桌面批准已经生效的情况下。成员的自定义规则，或者一次成功的插件测试，本身都不能证明已经实现了这种覆盖。
- **核实**。在每一条途径上使用同一个测试邮箱和一封一次性邮件。分别尝试一个被禁止的收件人、一个新的但被允许的收件人，以及授权的周五发送。记录是哪项控制起了作用、是否有人批准了这次发送，以及邮件服务是接受还是拒绝了它。在批准这个工作流之前，针对每一条已启用的浏览器和桌面途径，核实每次发送的行为。
- 请参阅[应用权限](https://help.openai.com/en/articles/20001495-managing-app-permissions-in-chatgpt)、[云端浏览器会话](https://learn.chatgpt.com/codex/dots/computers-and-apps)、[计算机操作批准](https://learn.chatgpt.com/codex/computer-use)和[智能体安全](https://learn.chatgpt.com/codex/enterprise/agent-security)。

## 审查浏览器、网络和设备访问

（界面示意：云端计算机工具。浏览器使用、网络访问和计算机操作有各自独立的开关。让智能体使用云端计算机：适用于 Work Cloud、dots 和团队自动化。开关：使用浏览器、允许网络访问、允许计算机操作。示例云端计算机设置：浏览器、网络访问和计算机操作均已启用；开关位置展示的是一种配置。）

### dot 的云端计算机

- **云端能力：** 「使用浏览器」控制对 dot 云端浏览器的访问。「允许网络访问（代码和 shell）」控制命令的互联网访问。「允许计算机操作」控制与桌面应用的交互。智能体安全中的站点规则将让管理员可以在 dot 的云端浏览器中允许或阻止域名，并按网站设置上传和下载权限。在一个被允许的网站内，dot 的访问权限还取决于在那里登录的账户。
- **密码管理器：** 单独审查密码管理器的访问。即使 ChatGPT Work 被禁用，云端浏览器、网络和计算机操作控制仍然可以适用于 dots。关于能力设置，请参阅[在 ChatGPT 工作区中管理 dots](https://help.openai.com/en/articles/20001554-manage-dots-in-chatgpt-workspaces)。
- **本地保护措施：** dot 的云端浏览器有自己的会话。在笔记本电脑上登录一个内部网站，或者把笔记本电脑连接到 VPN，并不会让云端浏览器获得那个会话或网络路由。
- **网络规则：** 例如，在笔记本电脑上为终端命令屏蔽一个主机名，限制的是那条命令路径。如果云端浏览器、插件和网页搜索可能到达同一个目的地，请分别测试它们。请参阅[把计算机和应用连接到你的 dot](https://learn.chatgpt.com/codex/dots/computers-and-apps)。禁用代码和 shell 的互联网访问，本身并不会禁用云端浏览器或已连接的应用。

### 登录在云端浏览器中如何进行

在 dots 中，云端浏览器是可选的。管理员可以通过关闭「使用浏览器」来禁用它。

对于受企业 SSO 保护的网站，员工从 dot 的云端浏览器中登录。当 dot 提供一个私密登录表单时，检查网站地址，然后在那里输入你的凭证和任何要求的验证码。这个表单会把它们直接发送到云端浏览器，不经过模型的视野。

如果表单无法完成某个登录步骤，选择**打开计算机**，然后选择**接管**。亲自完成企业 SSO 和多因素身份验证（MFA）的提示。应用打开后，选择**交还控制**，让 dot 可以用你已登录的账户继续。如果网站要求你再次验证，在 dot 继续之前完成新的提示。

接管让你获得对云端浏览器的控制。如果企业 SSO 要求使用公司管理的设备或通过公司 VPN 连接，云端浏览器无法利用你笔记本电脑的设备状态或 VPN 连接来满足这一要求。请保留这项政策。如果某个已批准的插件支持这项任务，请通过一个已获授权执行该操作的已连接账户来使用它。如果这项任务只能在网站上完成，请在满足政策要求的设备和网络上完成。

云端浏览器保留自己的 cookie，与你设备上的浏览器分开。这包括在适用情况下为已保存的会话保持登录状态的授权令牌。要退出某个网站并结束那个已保存的会话，请在「设置 → 云端浏览器 → 浏览器数据」中清除该网站的 cookie。

### 已连接的员工计算机

- **连接要求：** 管理员必须允许本地访问，成员必须连接计算机。在进行本地工作时，保持计算机在线并打开 ChatGPT。让它离线不会解除连接。
- **消息渠道：** 成员可以通过一个消息渠道从另一台设备发送请求。dot 随后可以在成员已连接的计算机可用时，开启一个附带该计算机的新会话线程。
- **设备权限：** 摄像头、麦克风和屏幕访问还取决于已连接的计算机，以及在设备设置中授予 ChatGPT 应用的权限。关于设备权限，请参阅 [dots 隐私与安全常见问题](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs)。

## 审查记忆、保留和删除

- **保留的上下文：** dot 可以保存它通过一个已授权的应用连接读到的信息，比如在 Slack 话题串中分享的一项团队决定。断开该应用会停止今后通过该连接进行的读取。dot 已经保存的信息可能仍留在它的记忆中。
- **模型训练：** 默认情况下，企业数据不会被用于模型训练。即使关闭了模型改进，在有限的情况下，包括与安全相关的情况，仍可能进行人工审查。请参阅 [dots 隐私与安全常见问题](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs)。

- **ChatGPT 记忆：** dot 对话可以为 ChatGPT 记忆提供内容。请在 ChatGPT 记忆设置中管理共享的信息。移除信息时，要同时检查保存的记忆和聊天历史。只删除一段对话，可能会让一条保存的记忆留在原处。请参阅 [ChatGPT 中的记忆](https://help.openai.com/en/articles/8590148-memory-in-chatgpt)。

## 审查消息与受众边界

- **Slack 身份：** 在离职交接时，同时检查 dot 的 Slack 身份和所有者的 Slack 插件连接。ChatGPT 和已启用的消息渠道联系的是同一个 dot。它们的对话是分开的，但[保存的笔记和上下文](https://learn.chatgpt.com/codex/dots/tasks-and-memory#context-and-memory)可以影响跨渠道的工作。
- **Slack 设置：** 检查工作区的通信权限和任何必需的 Slack 应用批准。然后成员必须完成设置。关于 Slack 设置，请参阅[管理 dots 的权限和能力](https://learn.chatgpt.com/codex/enterprise/dots-admin-guide)。
- **受众可见性：** 任何能访问这段对话的人都能读到 dot 发的帖子。请在内部 Slack 频道中进行 dot 辅助的工作。我们建议只在所有成员都属于你的组织的频道中使用你的 dot。这就排除了与客户或合作伙伴共享的 Slack Connect 频道。**分享限制：** 例如，如果一个 dot 可以读取一份私密的人力资源文档，那么在项目频道中发布其中的薪资数字，就会把它们暴露给每一个能读这个频道的人。在批准一条帖子之前，请明确 dot 可以分享什么，并确认频道中的每个人都有权看到它。

## 收集审计证据并保护导出内容

### 为你的任务选择报告

- **调查与报告：** 调查时使用[合规记录](https://learn.chatgpt.com/codex/enterprise/compliance-api)，采用情况报告使用 [Analytics API](https://learn.chatgpt.com/codex/enterprise/analytics-api) 的数据。
- **使用量指标：** 使用量计数不会显示是谁授权了一个操作，或者它是否成功。

### 追踪一个操作

1. **找到这个操作。** 找到成员的提示和 dot 的回复，然后检查工具或插件事件。对于一次 Slack 发送，把插件结果与目的频道中的消息进行比较。
2. **匹配记录。** 使用用户和工作区标识符定位记录。归属于 dots 的记录使用 `client_id = DOTS`，并在可用时包含 dot 的元数据。使用接收服务的日志检查结果。
3. **追踪委派的工作。** 对于委派的工作，寻找父会话线程和任务 ID。记录任何妨碍你追踪这个操作的缺失或被遮蔽的字段。
4. **检查目的地。** 一条工具记录可以标识一条被请求的命令或浏览器操作。要核实实际到达的目的地，如果可用，把它与该路径的代理或网关日志进行比较。本地 OpenTelemetry 收集器覆盖受支持的本地执行事件。云端编排不在该收集器的范围内。关于受支持的记录，请参阅[管理 dots 的权限和能力](https://learn.chatgpt.com/codex/enterprise/dots-admin-guide)。

### 解读当前的 Compliance API 记录

| **活动** | **要找什么** | **这条记录告诉你什么** |
| --- | --- | --- |
| 云端浏览器或计算机 | TOOL\_CALL\_SUGGESTED | 标识出 dot 尝试使用的工具。即使 status=completed，详细的输出也可能缺失。 |
| 已连接的应用（插件） | APP\_MCP\_CALL 和 APP\_MCP\_RESULT | 调用记录写明了工具。结果记录报告成功或错误，并可以包含输出预览或错误详情。 |

Compliance API 的导出内容包括用户提示、dot 回复、工具调用请求和响应，以及后台活动。要调查一个操作，请关联可用的记录，并检查已连接的服务以核实外部影响。有些关联和结果可能不在导出内容中。

**针对云端活动的更详细审计日志。** 我们正在为 dots 和其他在云端运行的智能体开发更详细的 Compliance API 记录。我们的目标是帮助安全团队追踪一个智能体在任务中采取的步骤，包括它调用了哪些工具和已连接的应用，以及一个操作何时经过了自动审查。我们还在探索如何展示这些工具返回了什么，以及云端浏览器访问了哪些网站。

### 保留并保护导出内容

- **保留期：** [合规日志平台](https://help.openai.com/en/articles/9261474-openai-compliance-platform-for-enterprise-and-edu-customers)将记录保留 30 天。如果你必须保留得更久，请持续导出你需要的记录。
- **导出访问：** 限制谁可以读取导出内容和使用其密钥。一份导出内容可能包含员工的消息或插件结果的预览。对你的系统实际收到的记录应用你的保留、电子取证和法律保全规则。另行确认保全措施是否覆盖原始聊天、文件或 dot 笔记。
- **日志权限：** 广泛的合规访问和对话消息权限需要工作区所有者授予。所有者或管理员可以授予受支持的、更窄的日志权限。

## 停止工作、撤销访问并管理离职

当拥有个人 dot 的员工（dot 所有者）已经离职或无法协助时，请使用这个流程。ChatGPT 工作区所有者或工作区管理员从自己的账户进行操作。如果活动仍在继续，或者你无法核实敏感工作已经停止，请在执行以下步骤的同时，立即[提交 OpenAI 支持工单](https://help.openai.com/en/articles/6614161-how-can-i-contact-support)。

- **如果员工已经离职，移除工作区访问权限。** 工作区所有者或工作区管理员可以移除一个手动管理的成员。对于由目录管理的成员，请让你的身份管理员[移除工作区分配](https://help.openai.com/en/articles/10011769-scim-provisioning-and-management)，并在同步后核实该员工不再是活跃成员。移除成员资格后，工作区访问即结束。请另行核实对 dot 的控制：正在运行的工作可以在 dot 被撤销后完成，而移除成员对每一个活跃的和委派出去的任务的影响需要确认。
- **如果员工需要保留工作区访问权限，撤销 dots 访问权限。** 工作区所有者可以在「工作区设置 → 权限与角色」中查看[使用 dots（测试版）](https://help.openai.com/en/articles/20001554-manage-dots-in-chatgpt-workspaces)。检查工作区默认设置、直接分配的角色和群组角色。任何剩下的授权都可能让 dots 保持启用。在更改一个共享的授权之前，检查还有谁依赖它。
- **在管理控制台中找到员工的智能体。** 工作区管理员，包括所有者，可以查看一个用户的智能体，并暂停或删除一个 dot。
- **暂停 dot。** 这会阻止它开始新的工作，包括它自己按计划进行的运行。如果 dot 已经在一个单独的 Work 或 Codex 会话线程中启动了一个任务，那个任务可以继续运行。要停止它，请单独取消那个任务。同时检查 dot 创建的任何独立的时间安排。
- **恢复 dot。** 只有管理员可以恢复被管理员暂停的 dot。恢复后，之前的会话会重新回应消息；委派出去的工作不受影响。
- **撤销 dots 访问权限。** 当前正在运行的工作可以完成，新消息不会触发模型操作，时间安排会被暂停。请另行核实移除工作区成员资格的效果。
- **删除 dot。** 删除无法恢复，所以请先保存所需的证据。删除一个 dot 会删除它的云端浏览器和计算机，但不会移除用户层级的插件。
- **撤销已连接的账户和会话。** 请相关服务的管理员撤销应用授权，并在支持的情况下终止 dot 的云端浏览器使用的网站会话。对于 Slack，同时检查 dot 自己的身份和员工[已连接的 Slack 账户](https://learn.chatgpt.com/codex/enterprise/dots-admin-guide)。请设备管理员限制对任何已连接计算机的访问，并检查已经在运行的本地工作。在签发每一项撤销的服务中核实该撤销。
- **核实活动。** 正在运行的工作的状态可以在 Compliance API 中查看，报告的 p95 时延为 30 分钟。定时工作的状态可以在下一次按计划运行之后 30 分钟查看。这些是报告时延，而不是立即停止的保证。请在接收服务中检查已完成的操作。
- **联系支持。** 从你自己的账户打开 help.openai.com 上的聊天气泡。支持团队可以指导用户或管理员停止一个 dot；它无法直接采取影响客户工作区中 dots 的操作。请提供工作区 ID、员工的电子邮件、可用的 dot 或任务标识符、已采取的操作、带时区的时间戳，以及最后一次观察到的活动。
