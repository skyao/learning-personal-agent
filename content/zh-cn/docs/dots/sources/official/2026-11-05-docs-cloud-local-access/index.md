Work 和 dots 可以在 OpenAI 的云端协调任务的同时，使用一台已连接计算机上被允许的文件和工具。请为每项功能分别启用本地计算机访问。

先阅读下面共用的政策、兼容性和审计指引，然后按照你计划启用的功能，阅读 Work 或 dots 的设置和最终用户指引。

本指南帮助企业工作区所有者审查政策要求，并为 Work 和 dots 启用本地计算机访问。可用性取决于你的工作区和推出进度。

关于全局基线（Global baseline）、环境覆盖以及编排器（orchestrator）和执行器（executor）字段列表，请参阅[智能体安全](https://learn.chatgpt.com/codex/enterprise/agent-security)。

## 本地计算机访问的好处

在这些功能中启用本地计算机访问，有助于团队跨设备继续工作。管理员可以在「智能体安全」中集中管理本地计算机上执行时受支持的要求。当 Work 使用云端容器、或 dot 使用云端计算机时，这些执行要求不适用。云端执行对浏览器访问、网络访问和计算机操作使用单独的控制。

### Work

- **跨设备继续同一段 Work 对话。** 在一台计算机上开始，然后从网页或移动应用查看结果或给出后续指示。在 Work Cloud 中使用本地计算机访问的任务采用云端协调。
- **使用你计算机上已批准的资源。** 使用这项功能的任务，可以通过一台已连接的计算机使用被允许的本地文件和工具，同时你在另一台设备上跟进。对于需要这台计算机的步骤，请保持它在线并处于连接状态。
- **集中管理本地执行要求。** 在「智能体安全」中为本地执行设置受支持的企业要求。云端执行的 Work Cloud 政策请另行检查。

### Dots

- **在本地进行工程工作。** 使用被允许的本地代码仓库、开发者工具和技能来调查错误、实现修改和运行构建。
- **协调编程工作。** 创建本地 Work 或 Codex 会话线程，并控制已有的本地 Codex 会话线程。
- **在受支持的任务中使用桌面应用和本地浏览器**，包括那些在云端浏览器无法完成时需要本地登录的任务。

## 在 Work Cloud 中启用本地计算机访问之前与之后

一个任务有两个部分：协调和执行。协调决定采取哪些步骤，并让对话持续推进。执行是由一个工具完成的工作，比如运行一条 shell 命令。这项功能把协调移到了 OpenAI 的云端。它并没有把每一个工具或文件都移出这台计算机。

| **领域** | **启用这项功能之前** | **启用这项功能之后** |
| --- | --- | --- |
| 继续一段本地 Work 对话 | 在可用的地方，成员选择本地或云端的 Work 会话线程。 | 当成员选择「云端」时，符合条件的新对话使用云端协调，并可以跨设备继续。当成员选择「本地」时，协调和执行都继续在本地进行。对企业而言，应用内的「本地 / 云端」切换开关及其默认值在发布时保持不变。 |
| 任务协调 | 适用现有的本地或云端工作流。 | 由 OpenAI 的云端协调 Work 任务。 |
| 需要用户计算机的步骤 | 本地 Work 可以使用这台计算机的工具和文件。云端 Work 无法使用这台计算机。 | 这台计算机仍然提供那些工具和文件，并且必须在线且处于连接状态。 |
| [企业要求](https://learn.chatgpt.com/codex/enterprise/managed-configuration) | 现有的本地要求及其优先级适用于本地 Work。 | 本地执行要求管辖已连接的计算机。启用托管政策时，受支持的全局政策适用于云端编排；Work 云端容器使用它们自己的执行配置和要求。 |
| 本地执行控制 | 适用受支持的设备和操作系统控制。 | 对于本地执行，MDM 和旧版托管设备要求的优先级高于「智能体安全」。系统要求文件的优先级低于它。 |
| Codex | 适用现有的 Codex 行为。 | Codex 的行为和对话历史保持独立。 |

## 如何设置本地计算机访问

### 在「智能体安全」中审查你的政策

#### 在哪里审查

打开「管理控制台 → 智能体安全」（Agent security）。它取代了「政策与配置」（Policies & Configuration）。它的推出与 Work 和 dots 的本地计算机访问相互独立。

- **政策设置：** 审查全局基线和任何本地覆盖。把编排器控制（包括批准和网页搜索）保留在全局中；各环境无法覆盖它们。在可用的地方使用专门的界面控件，包括**允许的批准政策**（Allowed approval policies）和**允许的网页搜索模式**（Allowed web search modes），其他受支持的字段使用 TOML。关于每项设置适用于哪里，请参阅[编排器与执行器控制](https://learn.chatgpt.com/codex/enterprise/agent-security#choose-controls-and-configuration-fields)。
- **要求与默认值：** 要求设定了用户无法覆盖的限制。默认值在这些限制之内提供起始值，并且不能覆盖一项要求。
- **功能访问：** 使用「管理控制台 → 权限」。本地计算机访问对 Work 和 dots 是分别选择开启的。

#### 哪些设置会沿用

当符合条件的旧版云端政策迁移时，它们的设置会沿用到全局中，并保留政策分配和顺序。请在「智能体安全」中审查迁移后的政策，并使用下表检查你当前的设置。如果你会自动更新政策，也请查看最后一行。迁移指引请参阅[智能体安全](https://learn.chatgpt.com/codex/enterprise/agent-security)。

| **你当前的设置** | **启用这项功能之前要做什么** |
| --- | --- |
| 已有的云端政策 | 将迁移后的全局基线与你所在组织要求的控制进行比较。记录设置，然后测试允许的操作能成功、受限的操作会被阻止。 |
| 只通过 MDM 下发的政策 | MDM 向设备下发政策。在启用这项功能之前，在「智能体安全」中为本地执行配置受支持的企业要求。对于本地执行，MDM 和旧版托管设备要求的优先级仍然高于「智能体安全」。 |
| Terraform 或政策更新脚本 | 使用政策 API 管理全局设置。要管理本地或 Codex Cloud 设置，请使用「智能体安全」界面。迁移之后，现有的全局 API 工作流仍然可用。测试你的脚本和 Terraform 集成，并确认政策分配和顺序没有变化。 |

#### 哪项政策优先

这些规则适用于不同的层级。下面的每个箭头都是从最高优先级指向最低优先级。

- **跨政策：** 优先级较高的政策胜过优先级较低的政策，即使优先级较低的政策更具体。
- **在一项政策之内：** 对于受支持的执行设置，环境覆盖 → 全局。没有覆盖的环境继承适用的全局设置。
- **本地要求：** macOS MDM 要求 → 被解释为要求的旧版 `managed_config.toml` 字段 → 「智能体安全」的云端托管要求 → 系统 `requirements.toml`。MDM 层适用于 macOS；默认值遵循单独的配置规则。

有些要求有字段特定的合并规则。关于政策范围、受支持的字段和执行范围，请参阅[托管配置](https://learn.chatgpt.com/codex/enterprise/managed-configuration)和[配置参考](https://learn.chatgpt.com/codex/config-file/config-reference)。

#### 政策如何适用于 Work 和 dots

Work 和带本地访问的 dots 的共同行为涵盖以下范围：

- **任务协调：** 启用托管政策时，协调任务的云端服务会执行「智能体安全」全局中受支持的要求，比如批准要求和允许的网页搜索模式。
- **本地执行：** 当一个工具在已连接的计算机上运行时，它会执行来自「智能体安全」的受支持本地执行要求，以及适用的设备政策，包括在支持的情况下通过 MDM 下发的政策。这些可以包括文件系统和网络限制。只有本地执行器支持的字段才适用；在 MDM 或本地 `requirements.toml` 中配置一个字段，并不保证它会在本地被执行。
- **云端执行：** Work 云端容器和 dots 的云端计算机使用单独的执行控制。本地的文件系统和网络限制不会自动适用于这些云端环境。

### 检查兼容性和数据要求

在启用任何一项功能之前，请审查资格、数据覆盖范围以及你所在组织所依赖的控制。共用的基础设施并不意味着 Work 和 dots 有完全相同的支持。

#### 审查 Work 和 dots 的资格

- **Work：** 数据驻留只适用于符合条件的内容以及受支持的工作负载、地区和配置。EKM 覆盖符合条件的工作区中受支持的已存储内容。请确认对你的工作流的覆盖情况，而不要假定每一个本地访问步骤或已连接的集成都被覆盖。Work 不支持阿联酋（UAE）推理驻留。请参阅[数据驻留与推理驻留](https://help.openai.com/en/articles/9903489-data-residency-and-inference-residency-for-chatgpt)和 [Work 云端安全](https://learn.chatgpt.com/codex/enterprise/chatgpt-work-cloud-security#data-handling-and-retention)。
- **dots 的数据驻留：** 在企业测试期间，dots 不支持数据驻留或推理驻留。符合条件的工作区可以在确认知晓这些限制后选择开启；启用 dots 并不会让它们的数据或处理符合驻留要求。
- **dots 的排除情况：** dots 不适用于 FedRAMP 工作区、使用 EKM 的工作区，以及推理驻留设为 AE（阿联酋）的工作区。HIPAA 工作区如果满足其他资格要求，可以参与。

#### 检查数据处理和本地访问保护措施

- **云端处理：** 带本地访问的 Work 和 dots 仍然使用云端协调。对话、工具结果和其他任务上下文不会只留在已连接的计算机上。
- **驻留保护措施：** 如果任何一项云端政策启用了 `enforce_residency`，那么对 Work 和 dots 而言，**允许本地计算机访问**都不可用。这项保护措施不会设置工作区的驻留，本身也不会禁用 Work Cloud 或 dots。符合条件的工作区在确认知晓测试期的驻留限制后，仍然可以选择开启 dots；本地访问仍然被阻止。
- **数据保留与访问：** 这两种体验都不提供严格的零数据保留（zero data retention）。API 零数据保留是一项单独的 API 控制。「不查看」（eyes-off）承诺和滥用监控控制也有别于零保留。如果某个工作流要求不保留任何数据，就不要为这些体验启用它。

在推出之前，请针对实际涉及的数据和工具，审查保留、删除和审计的覆盖范围。对于 Work，对话、托管的执行状态、文件和已连接应用的数据可能遵循不同的生命周期；删除一段对话并不会移除每一份相关的副本。

#### 检查钩子和网络兼容性

- **受支持的企业钩子：** 在启用托管政策和远程钩子时，带本地访问的 Work Cloud 和 dots 使用由管理员管理的远程 MCP 钩子。云端编排器会在受支持的任务和工具事件发生时调用你已连接的 MCP 服务。在全局 `requirements.toml` 中配置 `mcp_tool` 处理程序。不带本地访问的 Work Cloud 不使用这些钩子；这些企业钩子不适用于个人账户。
- **带本地访问的 Work Cloud 和 dots：** 命令或 shell、提示和智能体处理程序；来自本地配置、插件或本地目录的钩子；环境范围的钩子；以及 `SessionEnd` MCP 钩子，在云端编排下都不受支持，即使任务在你的计算机上执行工具也是如此。如果你的工作流依赖其中某个钩子，在审查出替代方案之前，请继续使用支持它的纯本地工作流。
- **Work 和 Codex 中的纯本地会话线程：** 当编排和执行都在本地时，现有的受支持钩子会继续工作。管理员仍然可以在「智能体安全」中为这种工作流配置受支持的托管钩子。
- **失败与审计覆盖：** 测试回调连通性、必需的事件和失败行为。一次明确的、受支持的拒绝可以阻止一个操作，但 `PreToolUse` 回调出错、超时或响应格式错误，可能会让钩子失败而不阻止工具。钩子并不提供完整的 [Compliance API](https://learn.chatgpt.com/codex/enterprise/compliance-api#audit-records-for-local-computer-access-with-work-cloud) 审计记录，也不覆盖每一条内部子智能体路径。
- **网络与应用控制：** 在[配置参考](https://learn.chatgpt.com/codex/config-file/config-reference)中核实字段、下发路径和执行界面。当云端编排器不使用某项设置时，由应用或设备执行的控制可能仍然适用。云端运行时不支持托管的 HTTP/SOCKS 监听端口和非回环代理监听器；套接字规则的支持取决于执行路径。请查看[网络政策优先级与运行时限制](https://learn.chatgpt.com/codex/enterprise/managed-configuration#network-policy-precedence-and-runtime-limits)，然后测试允许和被阻止的操作以及必需的连通性。

关于本地文件、云端执行或政策优先级的问题，请参阅 [Work 管理员常见问题](https://learn.chatgpt.com/codex/enterprise/work-admin-faq)、[Work 本地安全](https://learn.chatgpt.com/codex/enterprise/chatgpt-work-local-security)和 [Work 云端安全](https://learn.chatgpt.com/codex/enterprise/chatgpt-work-cloud-security)。

### 启用本地计算机访问 {#enable-local-computer-access}

为 Work 和 dots 分别授予本地计算机访问权限。使用工作区默认设置和受支持的自定义角色，向预期的用户或群组授予访问权限。

在推出之前，请审查上面的政策和兼容性要求。建议在「智能体安全」中审查或创建政策，但确认流程并不要求你在启用访问之前创建政策。政策迁移不会授予本地计算机访问权限。

#### Work

1. 以工作区所有者身份打开**管理控制台** > **权限**。
2. 为预期的用户启用 **Work Cloud**。**在 ChatGPT 桌面应用上本地使用 Codex** 不是这项功能的前提条件。
3. 在 **Work Cloud** 下，打开**允许本地计算机访问**。查看确认对话框，然后打开**智能体安全**审查或设置政策，或者确认开启访问。
4. 让用户更新到 ChatGPT 桌面应用 26.929 或更高版本。要让 **Work Cloud** 的本地计算机访问生效，必须进行这次更新。
5. 请一位拥有预期权限的成员在桌面输入框中选择**云端**并开始一个新任务。从另一台受支持的设备继续这个任务，并在计算机处于连接状态时，验证对一个已批准的本地文件或工具的访问。

#### Dots

1. 以工作区所有者身份打开**管理控制台** > **权限**，并在符合上述资格要求的前提下，为预期的用户启用 dots。
2. 在**使用 dots** 下，打开**允许本地计算机访问**。查看确认对话框，然后打开**智能体安全**审查或设置政策，或者确认开启访问。
3. 让用户更新到 ChatGPT 桌面应用 26.929 或更高版本。要让本地计算机访问生效，必须进行这次更新。
4. 让用户按照下面的 [dots 最终用户步骤](#dots-end-user-steps)连接他们的计算机。（收集说明：原页面中锚点 #dots-end-user-steps 没有对应的标题，本页把它加在「最终用户体验」下的「Dots」一节上。）
5. 请一位拥有预期权限并已连接计算机的成员，用自己的 dot 测试一个本地任务。

### 审查 OpenTelemetry 和审计覆盖

对于带本地访问的 Work 和 dots，在审查 OpenTelemetry（OTel）覆盖范围时，要把本地执行遥测与云端审计记录区分开来。你的本地执行器仍然可以导出受支持的执行事件。云端编排事件不会到达你现有的 OpenTelemetry 收集器。

使用 [Compliance API](https://learn.chatgpt.com/codex/enterprise/compliance-api#audit-records-for-local-computer-access-with-work-cloud) 获取受支持的云端记录。更改收集器端点并不能恢复云端编排事件。Compliance API 的记录并不能取代早先 OpenTelemetry 流中的每一个事件。

对于 dots，使用 [Analytics API](https://learn.chatgpt.com/codex/enterprise/analytics-api) 获取使用情况，使用 [Compliance API](https://learn.chatgpt.com/codex/enterprise/compliance-api) 获取受支持的审计记录。在本地收集器投递之外，验证你的工作流需要的记录；MCP 钩子不能替代审计覆盖。

关于云端审计覆盖，请参阅 [Work 云端安全](https://learn.chatgpt.com/codex/enterprise/chatgpt-work-cloud-security#audit-and-compliance-visibility)。

## 最终用户体验

对于 Work 和 dots，本地步骤都需要相关的计算机在线并处于连接状态，ChatGPT 桌面应用正在运行，并登录了相应的账户和工作区。

### Work

- **符合条件的任务。** 在 ChatGPT 桌面应用中选择**云端**后开始的符合条件的新任务，可以在这台计算机处于连接状态且启用了本地访问时，使用它的本地执行器。
- **登录。** 在预期的工作区中使用「通过 ChatGPT 登录」。API 密钥和 Codex 访问令牌不会启用 Work Cloud 的本地计算机访问。
- **计算机不可用。** 如果在新一轮开始时计算机不可用，一个已有的符合条件的任务可以在云端容器中继续，但无法使用那台计算机的本地文件或工具。容器不会执行来自本地执行的企业要求。一个任务无法在一轮进行中从本地执行切换到云端。
- **访问被关闭。** 关闭 Work Cloud 的本地计算机访问，会中断当前正在运行的轮次。用户可以在已有的云端对话中开始新的一轮；它会使用 Work Cloud，但无法访问本地文件。
- **已有的聊天和项目。** 在启用这项功能之前创建的任务保持它们原来的模式：只在本地，或者在云端但不能访问本地文件。启用这项功能后，开始一个新任务，才能使用 Work Cloud 的本地计算机访问。
- **本地 / 云端设置。** 对企业而言，应用内的「本地 / 云端」切换开关及其默认值在发布时保持不变。选择了**云端**的符合条件的任务，使用云端协调，并用已连接的计算机完成本地步骤。

### Dots {#dots-end-user-steps}

- **连接一台计算机。** 在 ChatGPT 桌面应用中打开 dot 的详情，然后选择「计算机」。找到「你的计算机」（或这台计算机的名称），选择**允许**，然后用「允许访问」确认。这台计算机就可以用于受支持的本地任务。
- **计算机离线。** 已保存的访问授权仍然保留，但需要这台计算机的工作在它不可用时无法进行。离线并不意味着访问权限已被撤销。
- **移除访问。** 选择「撤销访问」并确认，即可移除这个 dot 对这台计算机的授权。「已断开连接」表示访问权限已被移除；它与「离线」不同。
- **管理员的访问变更。** 如果管理员禁用了 dots 的本地计算机访问，一个已经获得授权的本地任务可能仍在完成中。不要以为 Work 中立即中断正在运行的轮次的行为也适用于 dots。
- **正在运行的任务。** 一个正在运行的本地任务不会自动迁移到云端。连接的变化可能会中断工作或重新加载运行时。这个 dot 可能会在它的云端计算机上继续后续的工作，但一个不再拥有访问权限的本地子任务无法在那台计算机上恢复，也不会被自动转移到云端。
