## 已分配的工作

你的 dot 在对话之间继续工作，并在情况变化时跟进落实。它可以自己决定何时暂停、何时醒来继续，因此你不需要把每次跟进都排进固定时间表。你也可以指定某个时间或某个受支持的事件来触发工作。告诉它哪些结果值得通知你，哪些决定需要你输入。

你的 dot 可以把工作分给并行运行并向它汇报的后台智能体。它们工作时你可以继续和 dot 交谈。它也可以创建单独的、可见的线程，并发送后续指令。

新的云端线程会出现在你的桌面、网页和移动应用中，你可以打开并继续引导工作。本地 Codex 线程在已连接的计算机上可用。对于需要特定仓库和环境的编程工作，你的 dot 可以使用你已创建的 Codex 云端环境。

| 任务 | 你的 dot 如何与之配合 |
| --- | --- |
| 新的本地 Work 或 Codex 任务 | 在连接到你的 dot 的计算机上创建任务。保持该计算机在线并打开 ChatGPT 应用。 |
| 已有的本地 Codex 任务 | 在已连接的计算机上继续该任务。指明是哪个任务以及你要改什么。 |
| 新的云端编程任务 | 在你已设置好的 Codex 云端环境中创建任务。你的计算机可以离线。 |
| 你的 dot 创建的任务 | 使用该任务原来的计算机或云端环境查看结果并发送后续指令。 |

对于云端编程工作，请先在 Codex 中创建环境，包括其仓库和设置配置。更改 dot 选定的计算机不会把已有任务迁移到那台计算机。

在桌面应用中，打开 dot 的个人资料，选择**活动**（Activity），再打开一个任务查看其进度、文件、结果或输入请求。你也可以直接给出指令。你离开时，你的 dot 可以继续协调该任务。

新任务会收到你的 dot 为这项工作的指令和上下文。它有自己的对话；它不会自动收到你与 dot 的每一段对话。连接一台计算机并不会授予对每一段已有 ChatGPT 或 Codex 对话的访问权限。

即使一次运行已经完成，也要检查输出和所报告的任何错误。运行完成本身并不确认所要求的结果已经实现或交付。参见[检查工作](https://learn.chatgpt.com/codex/dots/controls#review-work)。

## 周期性任务

在固定时间重复的工作需要保存时间表。请说明：

- 你的 dot 应检查或更新什么。
- 应在何时运行，包括时区和任何结束日期。
- 哪些变化值得通知。
- 把结果送到哪里。

例如：

> Check the connected planning channel each weekday at 9 AM Pacific for the
> next four weeks. Update the project checklist when a deadline changes.
> Message me in ChatGPT only if a deadline is at risk or you need a decision.
> Confirm the schedule.

（译注：意为「在接下来的四周里，每个工作日美国太平洋时间上午 9 点检查已连接的规划频道。截止日期有变化时更新项目检查清单。只有在某个截止日期面临风险或你需要我做决定时，才在 ChatGPT 里给我发消息。确认这个时间安排。」）

让你的 dot 确认它保存了什么。用**已安排**（Scheduled）查看周期性工作，或让 dot 列出、更改或取消它已安排的任务。

你的 dot 也可以读取和编辑你已有的 ChatGPT Work 自动化。让它查看已安排了什么，或更改某个周期性任务的指令或时间。指明你要更改的自动化，并让它确认更新。

停止进行中的工作和取消时间表是两个独立的操作。参见[控制](https://learn.chatgpt.com/codex/dots/controls#stop-work)。

### 事件监控

当已连接的服务支持事件监控时，你也可以让 dot 响应特定事件。例如，让它调查某个已连接 Slack 频道中的新错误报告，并准备修复供你审阅。告诉它要关注哪些事件、何时通知你。让它确认它可以跟踪哪些事件。仅连接 Slack 或其他来源并不会创建监控任务。

## 上下文与记忆

你的 dot 使用它正在处理的对话、相关的 ChatGPT 记忆，以及它自己保存的笔记来跟踪你的偏好和持续中的职责。这些各有用途。

### 对话上下文

上下文是 dot 在回复或工作时可用的信息：消息、指令、相关来源材料，以及来自其工具或委派工作的结果。它可以用这些信息把新请求与已在进行的工作联系起来。

你的 dot 可以搜索你过去的 ChatGPT 对话以获取相关上下文。例如，让它找出早先的一段讨论，并把其中的决定用到当前任务中。检索到的对话内容是这项工作的上下文；它不同于持久记忆，也不等于每个任务都会包含的完整历史。

一次交互可用的上下文是这些信息中的一部分。通话使用选定的对话上下文，这可能与后台任务可用的信息不同。

### 持久记忆

你的 dot 从 ChatGPT 记忆中的相关上下文开始。它也会保存自己关于偏好、决定和进行中工作的笔记，以便在之后的对话中使用。这些笔记与 ChatGPT 保存的记忆是分开的，也不是你说过的所有内容的完整记录。

在你们一起工作的过程中，你的 dot 会更新这些笔记，以反映新的决定和变化的优先级。更改 ChatGPT 的已保存记忆设置，不一定改变 dot 已经做好的笔记。

### 跨消息渠道

你可以在 ChatGPT 和 Slack 中联系同一个 dot。在两者之间切换不会创建单独的 dot，也不会重置它保存的笔记。你通过一种联系方式分享的信息，可以用于它在另一种联系方式中的工作和回复。

可见的对话仍各自独立。ChatGPT 中的一条消息不会自动复制到你的 Slack 对话中。你的 dot 使用信息的能力，也不等于获准向另一批受众披露该信息。例如，它可以用你私下分享的截止日期帮你准备一份更新，但在团队频道中分享私密细节仍需许可。

这种连续性适用于与你的 dot 的对话。连接一台计算机并不会让它可以使用每个应用中的每一段对话。联系方式和可用范围见[给 dot 发消息](https://learn.chatgpt.com/codex/dots/channels)。

## 主动研究

除了已分配的工作，你的 dot 还可以研究它有权读取的信息，并为有用的发现保存私人笔记。这种后台研究可以把新信息与早先的工作联系起来。例如，你的 dot 可能指出某个发布决定与你上周分享的草稿相冲突。

主动研究本身不会发送消息、更改已连接应用，也不会控制浏览器或计算机。后台智能体会把发现汇报给你的 dot，由它把建议或问题带给你。任何后续操作都要遵守适用于该项工作的权限和批准。

已分配的周期性任务可以包含你已授权的操作。它们的权限和时间表与主动研究是分开的。
