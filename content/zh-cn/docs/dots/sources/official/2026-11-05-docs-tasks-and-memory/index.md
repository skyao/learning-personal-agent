你的 dot 可以同时跟踪不止一项职责。你可以在同一次对话中切换任务、补充一个细节或调整优先级。描述你需要的结果以及它应该使用的来源。内置的安全防护和应用权限会自动适用；你可以补充更具体的说明。

（界面示意：今天 1:22 PM。用户：「Investigate the checkout feedback. Prepare a fix and a test video for review.」（调查关于结账的反馈。准备一个修复和一段测试视频供审阅。）dot：「I’m investigating the issue and related reports in these tasks:」（我正在以下任务中调查这个问题和相关报告：）任务卡片「Fix mobile checkout」（修复移动端结账，7）、「Investigate related reports」（调查相关报告）。用户：「Focus on mobile first. Keep the desktop behavior.」（先专注移动端。保持桌面端的行为不变。）dot：「The mobile fix is ready in a draft PR. Tests pass, and the task includes a video for your review. I’m still checking the related reports.」（移动端的修复已在一个草稿 PR 中准备好。测试通过，任务中附有一段视频供你审阅。我还在检查相关报告。）输入框：发送消息。右侧面板：Alfred，当前在线；通话；计算机：Alfred 的计算机，已连接；最近活动：修复移动端结账、调查相关报告；产出：修复移动端结账。）

## 分配的工作

你的 dot 在对话之间持续工作，并随着情况变化跟进到底。它可以自己决定何时暂停、何时醒来继续，所以你不需要把每一次跟进都放进固定的时间表。你也可以指定一个时间，或者一个应当触发工作的受支持事件。告诉它哪些结果值得汇报，哪些决定需要你的意见。

你的 dot 可以把工作分给并行运行、并向它汇报的后台智能体。在它们工作时，你可以继续和你的 dot 交谈。它还可以创建单独的、可见的会话线程，并发送后续指示。

新的云端会话线程会出现在你的桌面、网页和移动应用中，你可以在那里打开它们并继续引导工作。本地 Codex 会话线程在已连接的计算机上可用。对于需要特定代码仓库和配置的编程工作，你的 dot 可以使用你创建的 Codex 云端环境。

| 任务 | 你的 dot 如何处理它 |
| --- | --- |
| 新的本地 Work 或 Codex 任务 | 在连接到你的 dot 的计算机上创建一个任务。保持那台计算机在线并打开 ChatGPT 应用。 |
| 已有的本地 Codex 任务 | 在已连接的计算机上继续这个任务。指明是哪个任务以及你想改变什么。 |
| 新的云端编程任务 | 在你已经设置好的 Codex 云端环境中创建一个任务。你的计算机可以离线。 |
| 你的 dot 创建的任务 | 使用该任务原来的计算机或云端环境，检查结果并发送后续指示。 |

对于云端编程工作，请先在 Codex 中创建环境，包括它的代码仓库和配置。更改你的 dot 所选的计算机，并不会把已有的任务转移到那台计算机上。

在桌面应用中，打开你的 dot 的个人资料，选择**活动**（Activity），然后打开某个任务，查看它的进展、文件、结果或需要输入的请求。你也可以直接给出指示。在你离开时，你的 dot 可以继续协调这个任务。

一个新任务会从你的 dot 那里获得这项工作的指示和上下文。它有自己的对话；它不会自动获得你与你的 dot 之间的每一段对话。连接一台计算机，并不会授予对每一段已有的 ChatGPT 或 Codex 对话的访问权限。

即使在一次运行完成之后，也要检查输出和任何报告的错误。一次运行完成，本身并不能确认所请求的结果已经实现或交付。请参阅[检查工作](https://learn.chatgpt.com/codex/dots/controls#review-work)。

## 周期性任务

在固定时间重复的工作需要一个保存的时间安排。请说明：

- 你的 dot 应该检查或更新什么。
- 它应该什么时候运行，包括时区和任何结束日期。
- 哪些变化值得发通知。
- 把结果送到哪里。

例如：

> Check the connected planning channel each weekday at 9 AM Pacific for the
> next four weeks. Update the project checklist when a deadline changes.
> Message me in ChatGPT only if a deadline is at risk or you need a decision.
> Confirm the schedule.

（译注：意为「在接下来的四周里，每个工作日太平洋时间上午 9 点检查已连接的规划频道。截止日期有变化时更新项目检查清单。只有在某个截止日期面临风险或你需要我做决定时，才在 ChatGPT 里给我发消息。确认这个时间安排。」）

让你的 dot 确认它保存了什么。使用**已安排**（Scheduled）查看周期性工作，或者让你的 dot 列出、修改或取消它的定时任务。

你的 dot 还可以读取和编辑你现有的 ChatGPT Work 自动化（automations）。让它检查安排了哪些事情，或者修改某个周期性任务的指示或时间。指明你想修改的是哪个自动化，并让它确认这次更新。

停止进行中的工作和取消一个时间安排是两个不同的操作。请参阅[控制](https://learn.chatgpt.com/codex/dots/controls#stop-work)。

### 事件监控

当一个已连接的服务支持事件监控时，你可以改为让你的 dot 对某个特定事件作出响应。例如，让它调查一个已连接的 Slack 频道中新出现的错误报告，并准备修复供你审阅。告诉它要关注哪些事件，以及什么时候通知你。让它确认它能跟踪哪些事件。仅仅连接 Slack 或其他来源，并不会创建一个监控任务。

## 上下文与记忆

你的 dot 使用它正在其中工作的对话、相关的 ChatGPT 记忆，以及它自己保存的笔记，来跟踪你的偏好和长期职责。这些各有不同的用途。

### 对话上下文

上下文是你的 dot 在回应或工作时可以获得的信息：消息、指示、相关的原始材料，以及它的工具或委派工作的结果。它可以利用这些信息，把一个新的请求与已经在进行的工作联系起来。

你的 dot 可以搜索你过去的 ChatGPT 对话，寻找相关的上下文。例如，让它找到之前的一次讨论，并在你当前的任务中使用那次讨论中做出的决定。检索到的对话内容是这项工作的上下文；它不等同于持久记忆，也不是包含在每个任务中的完整历史。

一次互动中可获得的上下文，是这些信息中被挑选出来的一部分。通话使用的是挑选出的对话上下文，这可能与在后台工作的任务所能获得的信息不同。

### 持久记忆

你的 dot 从 ChatGPT 记忆中的相关上下文开始。它还会保留自己关于偏好、决定和进行中工作的笔记，以便在之后的对话中使用。这些笔记独立于 ChatGPT 保存的记忆，也不是你所说的一切的完整记录。

在你们一起工作的过程中，你的 dot 可以更新这些笔记，以反映新的决定和变化的优先级。更改 ChatGPT 保存的记忆设置，并不一定会改变你的 dot 已经做的笔记。

### 跨消息渠道

ChatGPT、Slack 和 Teams 是联系同一个 dot 的不同方式。在它们之间切换，不会创建一个单独的 dot，也不会重置它保存的笔记。你通过一种联系方式分享的信息，可以影响它通过另一种方式进行的工作和回复。

可见的对话仍然是各自独立的。ChatGPT 中的一条消息不会自动复制到你的 Slack 对话中。你的 dot 能够使用某条信息，也不等于它获得了向另一批受众披露这条信息的许可。例如，它可以用你私下分享的一个截止日期来帮你准备一份更新，但在团队频道中分享私人细节仍然需要许可。

这种连续性适用于与你的 dot 的对话。连接一台计算机，并不会让它获得每个应用中的每一段对话。关于联系方式及其可用性，请参阅[给你的 dot 发消息](https://learn.chatgpt.com/codex/dots/channels)。

## 主动研究

除了分配的工作之外，你的 dot 还可以研究它有权读取的信息，并就有用的发现保留私人笔记。这种后台研究可以把新信息与之前的工作联系起来。例如，你的 dot 可能会指出，一项发布决定与你上周分享的一份草稿相冲突。

主动研究本身不会发送消息、修改已连接的应用，也不会控制浏览器或计算机。后台智能体把它们的发现汇报给你的 dot，由 dot 带给你一条建议或一个问题。任何后续操作，都要遵守适用于那项工作的权限和批准。

分配的周期性任务可以包括你已授权的操作。它们的权限和时间安排独立于主动研究。
