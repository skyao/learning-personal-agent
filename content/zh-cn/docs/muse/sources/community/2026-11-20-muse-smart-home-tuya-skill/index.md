晚上 11 点，你抱着一堆杂货走进家门，对那个已经在替你处理收件箱、日历和旅行的智能体说了句再显然不过的话：「开灯。」什么也没发生——尽管 Muse 能订去芝加哥的航班、读 400 封邮件、给你的保险公司打电话，却仍然按不了一个开关。

上线六周后，这就是世界上最有野心的个人智能体的状况：擅长文书工作，却看不见自己身处的那个房间。然后，上周，灯亮了。算是吧。带着一个星号。而那个星号就是故事本身。

## 两个对手先行一步

苹果于 2026 年 9 月 14 日随 iOS 27 推出 Siri AI，包含完整的 HomeKit 设备控制。两天后，谷歌推出 Google Home MCP，让任何兼容 MCP 的智能体——Claude、ChatGPT、Hermes 或 OpenClaw——都能接入住宅并运行它。到 9 月 27 日，Forkast 的一篇专栏已经写下判词：Muse 是唯一完全碰不到你家的大型智能体。

这话刺痛人，原因不止是面子。一个看不见物理世界的个人智能体，是与你的生活之间隔着一堵玻璃墙的智能体。你的日历是数字的，你的灯不是，而 9 月里每个对手都已翻过那堵墙，Muse 没有。

## Meta 用硬件作答

10 月 2 日，Meta 发布了 Muse Gadgets：开源的 ESP32 与 Linux 设备 SDK，Apache 2.0 许可，位于 gadgets.muse.ai。构建者拿到一套工具包，可以把 Muse 装到屏幕、按钮、传感器和扬声器背后。一台运行 Linux SDK 的树莓派可以执行自定义命令和一套 Home Assistant 配置。一块圆形 AMOLED 开发板带有按键通话和扬声器，而这些都不是即插即用。你需要一个 SDK token，每个小装置都通过 Muse 应用配对，代码按原样提供、不含担保，还附有一句欢快的警告：折腾可能把板子弄砖、使保修失效，或造成电压骤降。

与 SDK 一同而来的还有 Muse Home Link，Meta 为这项工作打造的自家设备：一个小小的 USB-C 加密狗，把 Muse 连到你家 Wi-Fi，让它能触达兼容设备，或任何暴露本地 HTTP API 的东西。Meta 称社区构建的技能可以让它开灯、控制电视，或把文档发送到打印机。但 Home Link 不是你能买到的产品。The Verge 报道称 Meta 只制造了 5,000 台并开放了等待名单，在美国凭有效的 Muse 订阅免费领取，每位订阅者一台，先到先得。五千个加密狗，给一个用户超过 1000 万的智能体。自己算算。

## 然后 Tuya Smart（涂鸦智能）给了 Muse 一把钥匙

11 月 12 日，Tuya Smart——全球智能灯泡、插座和传感器中很大一部分背后的云平台——发布了 Tuya Cloud Devices，技能名 gadget-tuya-cloud-devices，这是一个让 Muse 用自然语言查询和控制 Tuya 接入设备的开源技能。它是一个按 Muse Gadgets 规范编写的纯 Markdown 文件，改编自 Tuya 自己的 tuya-smart-control 技能，后者最初为 OpenClaw 构建，之后移植到 Muse。

配置过程确实很短：从 Tuya 的 GitHub 仓库取得技能，在 tuya.ai 申请一个免费 API 密钥，把两者交给 Muse，无需本地设备密钥、无需同一网络、无需改固件；如果你已有 Tuya 账号，大约十分钟，如果你是第一次从零开始、要创建账号并找到正确的仓库页面，则接近半小时。旧的社区方案要你把每台设备的本地密钥从固件里挖出来，而且每次设备重新配对到网络、密钥失效时，都要把整套仪式重做一遍。Tuya 的技能通过走 Tuya 的云，跳过了这一切。

它能工作，是因为每台 Tuya 设备都通过一套标准化的物模型（Thing Model）描述自己，那是一份机器可读的清单，说明它能做什么、接受什么取值、以什么步进。在发送任何命令之前，技能会先读物模型。这就是为什么一个技能文件能覆盖灯、插座、空调、摄像头和传感器，而不必为每个型号重写。你说「把客厅的灯调暗一点」，Muse 会先以设备自己的说法问它「一点」是什么意思，然后再动手。

最有意思的是命令之后发生的事：一两秒后，技能会把设备状态读回来，只有在确认生效之后才告诉你成功了——这是多数智能体技能完全跳过的闭环。如果有多个设备符合你的请求，它会列出房间请你确认。如果设备离线，它会说明，并且根本不下命令。事件通知至少间隔 30 分钟，免得你的手机变成火警。这种回读是整个发布中唯一真正的新想法：一个在声称成功之前先核对自己物理成果的智能体。每个触及真实世界的技能都应当被要求这样做，而几乎没有谁这么做。

## 数一数有几扇门

退一步，数数 Muse 今天实际是怎么进你家门的。有三扇门，没有一扇是原生的。

第一扇门是什么都没有，因为 Muse 没有内置的智能家居支持，Meta 也没有宣布过。第二扇门是 Home Link：凭订阅免费，但只有 5,000 台、在等待名单上、仅限美国、每位订阅者一台，发货窗口是「10 月」。第三扇门是 Tuya 技能：一个免费 API 密钥加一个 Markdown 文件，今天任何人都能用，但它跑在试用阶段的 API 上，有限速和调用配额，并且是以拉取请求 #61 的形式提交到 Meta 的小装置仓库，仍在审核、未合并。在 Meta 合并它之前，权威副本在 Tuya 的仓库里，不在 Meta 的。

现在给每篇关于这个技能的文章都会重复的那个数字放放气。「3,000+ 品类」是 Tuya 平台的规模，不是 Muse 现在能控制的设备数。一个没有任何 Tuya 设备的读者，从这则公告里得到的可控设备是零。真正重要的东西更小、更不光鲜：你自己 Tuya 账号里已有的那些设备，技能能通过它们的物模型看到。如果你家用的是 HomeKit、配对到另一个网关的 Zigbee 设备，或者一个从未接入 Tuya 云的品牌，这个技能对你毫无改变。

## 它碰不到什么

有些限制是刻意的，而且是好的限制。该技能不开放门锁控制、实时视频、固件升级、网络配置或设备移除。这些请求会回到 Tuya 应用里。一个能给灯调暗的智能体是便利。一个能在你睡觉时打开你家前门的智能体是负债，而 Tuya 把这条线画在了正确的位置——这比大多数争着把物理控制权交给一个从未需要向半夜站在黑走廊里的房主解释自己的软件的公司强得多。

其他限制只是现在时：实时自动化，比如门一开就点亮走廊灯，需要一台常开的 Linux 设备——一台运行 Muse Gadgets Linux SDK 的树莓派——待在那里接收事件订阅。没有那个盒子，你得到的是按需命令，不是触发器。摄像头快照可用，一张照片或最长 60 秒视频，但实时视频不行。而 API 密钥是真正的凭证：它在请求头里传递，从不在对话中回显，且只能触达你自己账号下的设备——这是正确的设计，也是为什么你除了把它交给 Muse 本身之外，不该粘贴到任何地方。

## 为什么这也许不算数

以下是对上述一切最强的反驳，直说：一个来自第三方厂商的技能文件，跑在试用阶段的 API 上，上游拉取请求还未合并，这不叫「Muse 能控制你的家」。这是一个配了新闻稿的演示。一个好演示。仍然是演示。Siri 原生控制 HomeKit，谷歌的 MCP 是平台级集成，两者都在 9 月发布。Muse 的路线要求你找到 GitHub 仓库、取得 API 密钥、把凭证交给一个智能体，并接受底下的 API 随时可能变化或限流。对多数人来说，实际答案仍然是不，你的智能体没法关你的灯。它改变的那一周，只对那些愿意做功课的人改变了。

这个反驳对当下的判断是对的，但功课现在很短、免费、有文档，这与 9 月相比是真实的变化——那时根本没有功课，因为没有路径。一个月前，没有门。今天有三扇，其中两扇开着，一扇只花十分钟、不要钱。留意 Meta 合并哪一扇、Tuya 继续资助哪一扇，以及下一个技能是否来自一家你确实拥有其设备的公司，因为那个在你永远看不到的产品会议上做出的决定，对你的客厅比任何新闻稿都重要。现在的考验是：不是智能体能否碰到你的家，而是造出你家小装置的那些公司是否允许它、按谁的条件允许——因为智能体的能力永远只等于这条链上最不慷慨的那个 API，而眼下这条链要穿过一个你从未听说过的厂商、一个试用阶段的端点，以及一个 Meta 里还没人合并的拉取请求。

## 今晚怎么试

第一，确认你的设备是不是 Tuya 设备。如果它们在 Smart Life 应用里，或在任何跑在 Tuya 云上的品牌应用里，那就是。第二，在 tuya.ai 取得一个免费 API 密钥。第三，从 Tuya 的 GitHub 仓库取出 gadget-tuya-cloud-devices 技能，把它和密钥一起交给 Muse。第四，从一个问题开始，而不是命令：「卧室的灯现在是开着的吗？」如果 Muse 答对了，再试「把客厅的灯调暗一点」，看它是否在回读状态后确认。第五，如果你想要一有动静就触发的自动化，加一台运行 Muse Gadgets Linux SDK 的树莓派，因为仅靠按需命令做不了触发器。至于门锁、固件升级和实时视频，就把它们留在 Tuya 应用里——眼下它们就该待在那儿。

## 我们没有核实什么

本文没有做上手实测。技能的行为，包括 1–2 秒的回读和 30 分钟的通知间隔，来自 Tuya 自己的发布材料和 Unite.AI 对仓库的解读，而不是来自真的把一盏灯调暗。拉取请求 #61 的状态（截至 11 月 12 日在审核中）在发稿时未对照实时仓库重新核实。Tuya 的平台数字，3,000+ 品类和 209 万注册开发者，是公司数字，开发者数截至 2026 年 6 月 30 日。Siri AI 和 Google Home MCP 的 9 月日期来自 Forkast 的报道；本文没有独立重读苹果和谷歌的公告。Home Link 在「10 月发货」之外的状态未核实，5,000 台的数字来自 The Verge 的报道。
