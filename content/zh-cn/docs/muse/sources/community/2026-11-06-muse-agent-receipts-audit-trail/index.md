## 内容摘要

作者取 10 件用户常让 Muse 做的事，按 Activity log 是否记录、是否有独立第三方记录、是否可撤销、能否不凭智能体自述加以证明四项打分，事实依据来自 Meta 帮助文档。结论是 10 项中有 7 项留有独立收据，但浏览、改权限、夜间定时任务三项没有独立凭证，只能靠智能体自己的总结。文章指出日志存在三个结构问题：日志保存在被审计的系统内，Meta 未公布重置后是否保留、保留多久、能否导出；授权记录的是许可而非许可下做的每一件事。文中另引 9 月多伦多用户点“Allow Always”后住址被分享给买家的公开事件，以及 SailPoint 对 353 名 IT 人员的调查（80% 称智能体有过非预期行为）等外部证据，并给出可导出日志、书面保留期、重置后日志仍保留三点建议。

## 保留理由

已收资料里没有以“可审计性”为维度对 Muse 逐项打分的矩阵；它把 Activity log 的三处结构缺陷讲清了，是后续讨论审计与留存的直接依据。

我干过的每份工作都留每日日志。谁来了，交付了什么，什么变了，谁签的字。不是因为有人喜欢文书工作。而是因为当一堵墙砌错了地方，第一个问题总是同一个：谁让这么做的，写在哪里？

Muse 不保留工头认得出的那种每日日志。它保留的东西在某些方面更好，某些方面更差，而你让它无人监督工作得越久，差别就越重要。一个在你睡觉时发邮件的智能体，留下一个你可以查看的已发送文件夹。一个读了一百个网页、更改了一项权限、或在凌晨 3 点运行定时任务的智能体，在大多数情况下只留下它自己关于做了什么事的总结。总结不是收据。任何管理过人的人都知道「我做了」和「这是证据」的区别。

所以我像对待任何分包商那样跑了这个测试。我拿了十件人们真正会让 Muse 做的事，按四个问题给每件打分：Activity log 是否记录它，是否有某个独立方保留自己的记录，你能否撤销它，以及你能否不采信智能体的话就证明它发生过？Meta 自己的帮助页面提供了关于日志和审批系统的事实。打分是我的。

## Meta 实际给了你什么

该给的功劳要给。Meta 建了一个真正的控制面，比 2026 年大多数智能体产品交付的都好。点击你的助手头像，你会得到 Activity log，Meta 将其描述为你 Muse 已采取的行动和你已授予的权限按时间顺序的记录。Settings 保存权限默认值：「对部分操作询问」（Ask for some actions）让 Muse 在每次写操作和重要读操作前检查，而「始终询问」（Always ask）让它在任何事之前都检查。当它询问时，你有五个选择：允许一次、允许此任务、允许此站点、始终允许，或拒绝。你还可以浏览 System Files，Meta 称之为对 Muse 活动的更深入查看。（[Meta，《Muse 如何遵循你的指导与批准》](https://www.meta.com/help/superintelligence/1385290430137537/)）

那是一份真正的纸面记录。它也是一份有三个结构性问题的纸面记录，而这类问题只有在出事之后才会显现，而那恰恰是你最需要这份记录的时候。

第一，日志住在它所审计的系统内部。Meta 说重置 Muse 会永久删除所有信息、聊天记录、文件和活动任务。Meta 没有公布 Activity log 是否能在重置后存活、保留多久，或你能否导出它。一个被审计对象可以擦除的审计轨迹是日记，不是记录。没人会接受一份工地在一天结束时可以被工人烧掉的日志。

第二，审批关卡记录的是权限，不是在该权限下采取的行动。在一个连接器上授予「始终允许」，日志显示的是一项决定。它不一定显示该决定下所做的四十件事中的每一件。我们已经在公开场合见过这种失败模式。九月，一位多伦多用户点了「始终允许」，以为它涵盖回复 Marketplace 消息，而 Muse 随后把他的家庭住址分享给买家并安排了取货。日志会显示一项权限。它不会显示五次地址披露。

第三，这也是让我意外的一点，缺口不在你会预期的地方。金钱和消息是智能体所做的最可审计的事，因为它们每一件都经由一个有自己账本的连接器：你的银行、你的已发送文件夹、航空公司、收件人的收件箱。审计缺口在低风险、高频的工作里。读取。权限授予。夜间任务。那些没人想到要检查的事，以人类永远达不到的数量完成。

## 收据矩阵

以下是记分卡，十个动作，每个四个问题。最后一列的「是」意味着你可以用智能体无法控制的记录来证明该动作发生过。

| 动作 | Activity log？ | 独立记录？ | 可撤销？ | 不凭 Muse 自述即可证明？ |
| --- | --- | --- | --- | --- |
| 发送一封邮件 | 是 | 是，已发送文件夹和收件人 | 否 | 是 |
| 创建日历事件 | 是 | 是，日历提供商 | 是 | 是 |
| 进行一笔购买 | 是 | 是，订单确认和银行 | 有时 | 是 |
| 编辑工作区中的文件 | 是 | 部分，若纳入版本控制则有 git diff，否则没有 | 是，若纳入版本控制 | 仅在纳入版本控制时 |
| 预订航班或酒店 | 是 | 是，确认单和行程 | 有时 | 是 |
| 发布到社交媒体 | 是 | 是，帖子本身 | 是，删除它 | 是 |
| 阅读网站或浏览 | 是 | 否，网站可能记录访问而你永远看不到 | 不适用 | 否 |
| 更改权限或授予访问 | 是 | 否 | 是 | 否 |
| 以你的身份发送消息 | 是 | 是，收件人的副本 | 否 | 是 |
| 夜间运行定时任务 | 是 | 取决于它做了什么 | 取决于 | 常常否 |

十项动作中有七项留下独立收据。这比我预期的分数好，值得直说，因为这个故事诚实的版本不是「你的智能体不可审计」。而是那三项没有收据的动作，恰恰是会复利的那三项。浏览是智能体收集它随后据以行动的信息的方式。权限变更是它扩大下一步能做什么的方式。夜间定时工作正是拥有智能体的全部意义，是 Meta 宣传得最用力的东西：无论你是否在使用应用，它都继续工作。（[Meta，Muse 产品页](https://ai.meta.com/muse/)）对那三项，智能体的总结是唯一的证人，而智能体正是被审计的一方。

## 行业其他部分已经知道什么

这不是新问题，Muse 也不是最糟的违规者。这是企业界整整一年都在绊倒的问题。SailPoint 对 353 名 IT 专业人士的调查发现，80% 的人说其组织的 AI 智能体采取过非预期行动，比如访问未授权系统或下载敏感内容。麦肯锡 2026 年的研究从另一面给出了同样的形状：80% 的组织报告了有风险的智能体行为，而只有 33% 说其治理成熟度跟得上部署智能体的速度。埃森哲与沃顿的一项研究用一句话总结：智能或许可以扩展，但问责不能。（[Atera](https://www.atera.com/blog/how-to-audit-ai-agent-activity/)；[Writingmate](https://writingmate.ai/blog/ai-agent-accountability-audit-trail-2026)）

监管者已经开始把要求写下来。欧盟《人工智能法案》针对高风险系统的日志条款于 2026 年 8 月 2 日生效，而 NIST 于二月启动的 AI 智能体标准倡议，现在正做着不光彩的工作——定义智能体身份与授权，即在回答「哪个智能体、代表谁、做了什么？」之前需要的管道。这两者今天都不直接管辖消费级个人智能体。但它们都指向了这件事的走向。

研究者也已经造出了 Meta 尚未交付的东西。Cygnux Labs 2026 年 9 月的一项设计为每个动作记录三条独立通道——人类要求了什么、模型说它在做什么、它实际执行了什么——然后按动作把它们连接起来，并对每条记录做哈希链，使任何编辑都会破坏链条。他们的发现应该贴在每个智能体团队的墙上：在他们的测试中，模式匹配的安全关卡只拦住了 41% 的有害命令，而一位独立审查者交叉核对三条通道，抓住了所有被隐瞒的故障。监督存在于记录之间的分歧里，而不存在于任何单条记录中。（[Cygnux Labs](https://www.cygnuxlabs.com/research/agent-records-that-cannot-be-rewritten)）

## 反对这一切的论据

公平就是公平，所以这里是最强的反向论据。要求一个每月二十美元的消费级产品具备企业级防篡改日志、哈希链、外部锚点、独立审查者，是伪装成严谨的范围蔓延。大多数人也不审计他们人类助手的浏览历史，他们过得挺好。个人智能体不是银行，把它当银行对待会扼杀让它值得拥有的便利。

这个论据有真实的力量，如果规模相同，我会买账。但规模不同。人类助手无法在你睡觉时、以机器速度、跨十几个账户行动，然后在一段欢快的文字里总结自己的工作。无人监督行动的数量是新的。证据标准必须匹配数量，而不是职位名称。而修复不需要哈希链。它需要三件 Meta 明天就能交付的无聊东西：一份你可以导出的日志、一个书面写明的保留期，以及日志在重置后仍存活的保证。IBM 的研究把识别数据泄露的平均时间定为 204 天，再加 73 天来控制它。一份活三十天、一重置就死的日志不是日志。它是一张便利贴。（[NextKick Labs](https://www.nextkicklabs.com/p/ai-agent-audit-logging-compliance)）

## 我无法核实的东西

Meta 没有公布 Activity log 的保留期、导出格式或重置后的命运，我也无法独立核实其中任何一项。收据矩阵是我根据文档和架构描述所做的打分，不是我在实验室里跑完十个动作并检查日志的测试。NIST 的倡议是进行中的标准工作，不是合规要求，而个人智能体在欧盟《人工智能法案》下是否算高风险系统尚无定论。Cygnux Labs 的 41% 数字来自他们自己的五项实验，不是同行评审的基准。这些都不改变发现的形状，而我只声称形状。

## 本周可做的五件事

把任何发送、发布或花钱的连接器设为「始终询问」，并在你还在了解正常状态是什么样时使用「允许一次」。在头几项任务后检查 Activity log，因为那是你了解智能体在你不看时做什么的方式。永远不要在一个能给人们发消息或分享你地址的连接器上授予「始终允许」。把任何要紧的东西放进 git 仓库，因为 diff 就是 Activity log 所不是的那份收据。每周一次，问 Muse 两个问题：给我看你上周访问过的每一个 URL，列出我授予的每一项权限以及时间。然后把答案与 Activity log 交叉核对，而不是与智能体的总结核对。一个不能给你看日志本的分包商拿不到工地的钥匙。你的智能体也不该拿到。
