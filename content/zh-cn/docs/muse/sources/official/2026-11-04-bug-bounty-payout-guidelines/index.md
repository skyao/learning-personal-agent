## 指南

Muse 是 Meta 的一款 AI 产品，让人们创建自己的个性化 AI 智能体，也就是他们的 Muse。每个 Muse 智能体都运行在一台每用户专用的虚拟机中，并连接到该用户自己的服务：电子邮件、日历、消息、浏览以及第三方账户。由于 Muse 智能体掌握着用户最敏感的数据，并且可以代表用户行事，我们把攻破这一边界视为头等的安全风险。本指南说明我们如何评估针对 Muse 的报告，最高赔付为 $300,000\*。我们从与所展示影响最匹配的类别出发，再应用「减轻因素」下列出的因素，得出最终奖励。Muse 的安全模型依靠四项承重的控制措施：每个用户的 VM 与 Meta 生产环境及其他用户的隔离；凭证保护，使智能体从不接触明文秘密；对离开沙箱的内容的出站控制；以及对敏感操作的人在环路（human-in-the-loop，HITL）批准。以下类别按照攻破每一项所造成的损害程度排序。

## 赔付

### 1. 攻破 Meta 生产环境以及 Muse 以外的用户

最高

$300k\*

示例

从 Muse 访问 Meta 生产服务或内部网络

要清楚地展示这一点，请获取我们 SSRF 赔付指南中所述的金丝雀标记（canary）。引用该页面仅为说明金丝雀标记。从 Muse 跳转到生产环境的情况，按本类别评估，而不是按 SSRF 赔付指南中的金额评估。

### 2. 在整个 Muse 机群范围内攻破 Muse

最高

$250k\*

示例

攻破 Muse 控制平面或其管理工具

控制平面中允许大规模接管的身份验证或授权缺陷

跨租户访问任意用户（而不是某一个特定目标用户）的 VM、对话记录、记忆、媒体或 artifacts

### 3. 攻破某个特定用户的 Muse 智能体

最高

$130k\*

示例

通过 Muse 账户访问和登录技术栈接管账户

获得对另一个用户的 Muse 智能体的访问权限，并读取或修改其对话、智能体记忆、artifacts、空间（spaces）或已连接服务的数据

以另一个用户的完整权限驱动其智能体，比如以对方的身份发送提示或对话轮次

获取另一个用户的明文凭证，比如第一方令牌、第三方 OAuth 和刷新令牌、连接器秘密，或浏览器中存储的密码

### 4. 高价值信息泄露

最高

$25k\*

示例

在你无法以其他方式与另一个用户的 Muse 智能体交互的情况下，通过某个泄露或只读缺陷读取该用户的私有数据，比如文件、记忆、工作区内容或对话

机器和运维数据，比如运行时间、资源使用、健康检查和指标端点以及版本字符串，属于低价值信息，不符合条件。

### 5. Muse 源代码和机群共享的秘密

最高

$10k\*

示例

从你的 VM 中读取或外泄 Muse 源代码

获取在整个 Muse 机群中共享的秘密，比如模型提供方的 API 密钥或第三方 OAuth 客户端密钥

机群共享的秘密按其可触及的范围评估。能访问 Meta 生产用户数据的秘密按第 1 类评估，能访问其他用户 Muse 数据的秘密按第 2 类评估。

### 6. 在你自己的 Muse 智能体内提升权限

最高

$7.5k\*

示例

从沙箱跨入 VM 的特权侧，或者获得对某个特权进程的控制

篡改 Muse 的特权进程，例如替换它们依赖的二进制文件或套接字、附加到某个进程，或者影响它在运行时加载的内容

以完整权限访问持有敏感配置或凭证材料的守护进程或服务

从沙箱内部禁用、重新配置或以其他方式使安全控制失效

按照设计，你在自己的沙箱内拥有 root 权限，所以这里的发现指的是从沙箱跨出到 VM 的特权侧：也就是运行在你的沙箱之外、持有凭证并执行批准和出站控制的那些进程。逃逸出虚拟机本身并触及其他用户属于第 2 类。

Linux 内核或发行版软件包中的公开已知漏洞，在其公开披露后的 30 天内不符合条件，以便我们有时间打补丁。在该窗口期之后，如果 Muse 仍受影响，则按本类别评估。

### 7. 绕过 Muse 的安全控制

最高

$5k\*

示例

在用户未批准的情况下执行需要批准的操作，包括智能体批准它自己的请求

破坏批准路径，使智能体不再需要用户，例如把某个连接器的权限从「询问」（ask）改为「允许」（allow）、直接调用底层 API，或者利用 Muse 应用或网站自我批准

以规避出站流量控制的方式把数据移出沙箱，包括自我批准出站

通过白名单中的目的地、会让客户端去获取攻击者 URL 的渲染内容、域名解析、隧道、频道（channels）、空间（spaces）或计划任务（scheduled jobs）把数据洗出去

在沙箱中运行的代码获取平台代表用户持有的某个凭证的明文值，比如第一方令牌、连接器的 OAuth 和刷新令牌，或连接器秘密

为了让 Muse 保持可用，有些出站路径是按设计允许的；这些情况不符合条件。

## 提示注入

提示注入是智能体被攻破的主要途径之一，我们希望收到这类报告。我们按照注入所达成的结果来评估它们，一个达到上述任一类别的注入，会按该类别的全额赔付。

以提示注入开始的符合条件的报告示例

在智能体会读取的地方植入的内容，使它把另一个用户的电子邮件、消息或智能体记忆发送到你控制的目的地

由某个共享的 Muse 服务（而不是单个用户的智能体）处理的注入内容，触及属于其他用户的数据

在智能体会读取的地方植入的内容，暴露了另一个用户的文件、记忆或工作区内容

我们不为没有结果的注入付费：劝说智能体说出某些话、泄露其系统提示，或列出其工具。

## 减轻因素

我们从所匹配类别的最高额出发。对于一份有效的、在范围内的报告，最终奖励不会低于我们的最低额。

### 受害者交互

我们对第 3 类账户接管的奖励，取决于攻击者需要受害者做多少事情。这些金额与我们 Family of Apps 账户接管阶梯一致。

（译注：原页面以上下堆叠的标签和金额呈现，不是表格；以下按相同顺序整理为表格。）

| 受害者交互 | 奖励 |
|---|---|
| 0 次点击 | $130,000 |
| 0.5 次点击 | $90,000 |
| 1 次点击 | $50,000 |
| 2 次点击 | $25,000 |
| 超过 2 次点击 | $10,000 |

* 0 次点击指攻击在受害者没有任何操作的情况下得手，例如通过计划任务或智能体在后台处理的内容。
* 0.5 次点击指受害者正常使用智能体，攻击借此得手，比如让它阅读电子邮件、浏览网页、购物或运行一项例行任务。
* 1 次点击指一次由攻击者引导的操作，比如点击攻击者提供的链接。

### 现实可利用性

在上述金额之外，对于不可能现实地针对真实用户执行的攻击链，我们不予奖励。这是对整个攻击链的判断，而不是数点击次数。

一个我们不会奖励的攻击链示例：必须说服受害者把攻击者提供的文本粘贴到提示中，然后让一个工具对其自身的输出再运行一次，然后再批准一个明白描述了恶意操作的提示。

## 不符合赔付条件

* 单纯的提示注入和提示走私（prompt smuggling），包括用不可见字符或特殊格式字符隐藏的指令（当它们被串联到符合条件的结果时会获得赔付，例如一个接管了另一个用户的智能体的提示注入）。
* 越狱、有害内容和完整性绕过，包括劝说智能体产出冒犯性的输出
* 提取系统提示
* 枚举智能体的工具或能力
* 幻觉和事实不正确的输出
* 在你自己的沙箱中安装你自己的恶意软件（按设计你在那里已经拥有 root 权限）
* 泄露机器、健康检查、指标或运维数据
* 拒绝服务。崩溃或资源耗尽类缺陷，按它还展示了什么来评估，而不是按可用性的丧失本身来评估
* 绕过速率限制和暴力破解
* 受害者通过一个明白描述了将会发生什么的确认提示批准的操作
