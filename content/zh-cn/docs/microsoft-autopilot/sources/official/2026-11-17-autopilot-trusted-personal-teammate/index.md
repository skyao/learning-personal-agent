我给我的 Autopilot 起名叫 Sebastian。

我在 Teams 和 Outlook 里与 Sebastian 一起工作。我请他帮我准备一天的工作、处理需要回复的对话、协调会议。有些任务是单次请求。另一些按例程运行，不需要我再开口。而且我不是唯一能和他一起工作的人，别人也可以。

这些工作大多很平常：核对、协调、跟进，确保没有东西被漏掉。但它需要真正的注意力。我希望能把更多这类事交出去。

这正是我们用 Autopilot 在构建的东西：一位值得信赖的个人队友，它理解你的工作、与其他人协作，并在你专注于别处时继续推进。给它一个名字、一个角色和一个目标。Autopilot 有自己的身份、记忆、工作区和远程计算机，以及完成工作的工具。它在云端运行，所以工作不取决于你是否开着笔记本电脑。

**「Sebastian，把我送到 Ignite 再送回来」**

拿「去 Microsoft Ignite」这样一个请求来说。找一趟航班是一项任务。把我送到那里、帮我把这场活动用到最好、再让我回到工作中，则是一项大得多的责任。

出发前，我需要为活动、准备和旅途留出时间。把它与工作和个人安排对照。把航班和酒店选项过一遍，包括我在意的取舍。在我批准后完成预订。然后处理注册、地面交通，以及我需要出现在哪里。

到了那里，工作就变了。帮我梳理日程、为会议做准备。让我的日常工作继续推进，管理外出安排，并确保有事需要我关注时人们能联系到我。帮忙协调一顿晚餐、找一家可预订的餐厅，或组织一场下班后的活动。趁收据还好找的时候把它们记下来。

而回家并不是终点。还有返程、我错过的对话、我欠下的跟进，以及我本来会拖延的报销单。

这就是我希望 Sebastian 承担的那种责任。我不想把每一步都变成单独的提示词，也不想每天早上再把这次行程解释一遍。我想把结果委派出去，一起把决定过一遍，并让它把上下文带着往前走。

我已经用过 Sebastian 来保护我日历上的旅途时间，并在外出前梳理应该从日历上拿掉的会议。在我选定会议之后，他移除了相关的那几次，同时保留了重复系列。这个区别很重要。「清空下周」不应意外变成「把这个会议永久取消」。

「把我送到 Ignite 再送回来」描述的是更宏大的目标。我每天与 Sebastian 的工作，是在帮我们理解要让那个目标变得可靠需要什么。

## 我们如何构建 Autopilot

**它从我的工作出发**

Autopilot 建立在 Microsoft IQ 之上，因此扎根于我的工作本来发生的地方：Outlook、会议、文件、聊天，以及我周围的人与优先事项。我不需要手动连接我的工具，也不需要解释每个人是谁。而且因为 Sebastian 有持久记忆，他会在上周学到的东西上继续，而不是从头开始。

**Sebastian 有自己的身份**

Sebastian 有自己的身份。这听起来像技术细节，但它改变了我们协作的方式。

例如，Sebastian 会**通过电子邮件给我发我的 Sunday Reset**。我可以回复那封邮件，继续和他对话。它不只是一份投递到我收件箱的报告。它是我队友发来的一封我可以回复的邮件，不用打开另一个应用，也不用开一段新对话。

**别人可以在 Teams 里和 Sebastian 说话来约我的时间。** 他知道我的日程偏好，所以每当有人想见面，我不必再解释一遍。他们不需要让我去问我的助理。他们可以直接和他打交道。

**我也可以在群聊和频道里把工作委派给 Sebastian。** 如果我们正在讨论某件需要跟进的事，我可以把他拉进那段对话，把活交给他。我不必离开讨论、把所有内容复制到一个私聊里、再解释每个人是谁。

这是 Ignite 例子里重要的一部分。当我在参加一场会议或与客户会面时，人们仍然需要我的时间。团队对话仍然需要跟进。我希望 Sebastian 用我已经设定好的偏好和边界来帮忙做这种协调。

把我送到 Ignite 是有用的。帮我人在那里、却不必继续做工作那头所有事情的中转人，才是更大的构想。

**把已经准备好、值得我关注的工作拿给我**

最近，在外出期间，我请 Sebastian 帮忙处理未回复的 Teams 对话。他准备了 **40 份回复草稿**，按优先级分组，放进一个私有的、可编辑的队列，我可以审阅，然后再请他帮忙。他可以监视工作中正在发生的事，并在有紧急问题时提醒我。

这比告诉我「你有消息要回」有用得多。工作被推进到了我可以审阅并做决定的程度。回复仍然是草稿。我仍然对将要发出的内容负责。

有时正确的结果是一个完成的任务。有时是一个准备得足够充分、让我能迅速做出的决定。一个有用的个人智能体需要理解这个区别。

**打造一个可靠的同事**

每天使用 Sebastian 让这些要求变得非常具体。

**它必须是个人的。** 队友越理解你的优先事项、偏好和工作风格，就越有用。持久记忆和上下文意味着你可以在之前的工作上继续，而不是从头开始。建立在 Microsoft IQ 之上，Autopilot 可以借助组织上下文理解请求背后的工作。

**它必须是主动的。** 早晨简报应该不用再提示就送到。例行的责任需要长期关注。但主动不意味着不断打扰我。它意味着把活干完，并把我值得关注的事情拿给我。

**它必须是协作的。** 自己的身份让双向邮件对话成为可能。别人可以在 Teams 里与它共事。你可以在共享聊天和频道里委派工作。个人队友应当对你共事的人有用，而不是与他们隔绝。

**它必须是企业级的。** 我希望 Sebastian 独立工作，但这不意味着他应该没有边界地运作。他需要知道他被允许做什么、何时请求批准，以及如何处理不应与所有人共享的信息。Microsoft 构建 Autopilot 时赋予它自己的身份、托管环境，以及围绕受支持操作的保障措施。组织可以用 Microsoft Agent 365 和安全能力扩展这些保护，用于治理访问、保护敏感信息和了解活动。目标很直接：在让组织保持控制的同时，给 Autopilot 有意义的责任。

**而且它必须是可管理的。** 我需要设定优先级、建立边界、决定什么需要批准，以及改变方向。我的组织需要管理访问与监督。更大的自主不应意味着更少的问责。

## 接下来与如何开始

我们仍在构建和学习。我与 Sebastian 的经历强化了一点：可靠性与能力同样重要。准备一份回复和发送它是两回事。找到一个时间和确认一个会议是两回事。完成一项任务包括知道其中哪些真正发生了。

智能体就是这样赢得更多责任的。

**从一件值得交出去的事开始。** 你不必从「把我送到 Ignite 再送回来」开始。

从一项你熟悉的责任开始。为我准备季度评审。把需要回复的对话拿给我，草稿已经准备好待审。接手我们刚在团队聊天里讨论的跟进事项。

给 Autopilot 一个清晰的结果和边界。审阅工作。细化你希望它如何完成。

对我来说，价值不在于花更多时间和 Sebastian 说话。而在于脑子里要装的东西更少、要追的事更少，以及有更多时间做那些需要我的工作。

从今天起，Autopilot 向 Frontier 中的合格客户推出。要被认定为合格，客户需要加入 Frontier 计划、拥有 Copilot 许可、启用基于用量的计费（usage-based billing），并具备所需的管理与安全能力。我们将利用预览期在更广泛开放之前验证并细化要求。[在此了解更多](https://aka.ms/autopilot-documentation)。

而这只是一波新智能体的开始，因为我们正把支撑 Autopilot 的能力开放给我们 Microsoft 产品组合中受支持的智能体。这些智能体准备好以自己的身份、受保护的资源和生产力应用来工作。像 Sales Development Agent 这样的 Microsoft 智能体，以及来自 Copilot Studio 等受支持平台的智能体，都可以配备自己的电子邮件地址和受保护的 Microsoft 365 资源，以进行持续的独立工作。[在此了解更多](http://aka.ms/microsoft-365-resources-for-agents)。
