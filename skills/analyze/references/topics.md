# 分析主题

主题是两个维度共用的划分：产品维度在 `docs/<product>/analysis/<slug>/` 下按主题写，主题维度在 `analysis/<slug>/` 下跨产品写。目录名用下表的 slug，不另起名字。主题的增减由用户决定（2026-11-12 定下这 13 个）。

「主要标签」用于从资料库筛选候选资料（`inventory.py tag ...`），只是起点：标签打在资料的主要内容上，顺带提到的不打，所以还要按关键词补查。

## 各主题要回答的问题

笔记关注「它怎么工作、做成什么样、怎么收费和扩张」。每个主题围绕下面的问题组织；产品页回答「这个产品怎么做」，主题页回答「各家做法有什么异同、为什么、往哪里走」。资料回答不了的问题写进「资料缺口」，不要硬答。

### runtime 运行环境
- 智能体在哪里运行：云端虚拟机、沙箱、用户本机、浏览器、混合？每个用户（或每个智能体）分配什么样的环境？
- 环境里有什么：浏览器、文件系统、命令行、登录状态；环境是否持久，关机、休眠、重置如何处理？
- 多个智能体、多个设备如何共享或隔离环境？
- 运行环境带来的成本与限制（算力额度、并发上限、超时）。

### memory 记忆与上下文
- 接入哪些个人数据（邮件、日历、文件、消息、相册、购物记录），怎么授权？
- 记忆如何形成、存放、更新、遗忘；用户能否查看、编辑、删除？
- 跨会话、跨设备、跨智能体如何共享上下文？记忆与所属平台已有的个人数据（如 ChatGPT 记忆、Meta 账号数据）是什么关系？

### continuous-execution 持续执行
- 用户离开后能做什么：定时任务、事件触发、长期目标跟进、主动联系用户？
- 任务的生命周期：创建、暂停、停止、汇报、失败重试；有哪些数量或时长限制？
- 主动性的边界：什么情况下主动打扰用户，频率如何控制？

### connectors 连接器
- 能接哪些第三方应用和服务，通过什么机制（官方 API、MCP、浏览器操作、插件市场、自定义连接）？
- 生态策略：开放给第三方开发者吗？平台方（如亚马逊）拦截或合作的情况？
- 连接器的授权粒度与失效处理。

### channels 交互渠道
- 用户通过什么入口和智能体交流：独立 App、所属平台内嵌、短信、iMessage、WhatsApp、Telegram、邮件、电话？
- 智能体是否有自己的邮箱、号码、身份，对外以谁的名义沟通？
- 接入各渠道的审批、费用与限制。

### devices 设备
- 支持哪些终端（手机、电脑、手表、眼镜、专用硬件），各终端承担什么角色？
- 本地设备与云端的分工；专用硬件的形态与定位。

### models 模型
- 底层用什么模型，是否为 Personal Agent 专门优化或训练？
- 按任务、档位、设备如何选择或切换模型？用户能否自选？
- 只收与 Personal Agent 运行相关的模型信息（见 tracking.md「模型资料的收录原则」）。

### security 安全
- 权限模型：哪些动作需要用户批准（付款、发送、删除、对外沟通），审批如何设计？
- 凭证管理：密码、登录状态、支付信息放在哪里，智能体能否看到？
- 防护机制：提示注入、恶意网页、越权操作的防护；独立审查模型（如 Sentinel）。
- 已披露的漏洞、安全事件、漏洞赏金，以及厂商的回应。

### privacy 隐私
- 数据用途：是否用于训练、广告，默认设置与退出方式。
- 数据范围与保存：采集什么、保存多久、能否导出与删除。
- 第三方数据：智能体接触到的他人信息（联系人、群聊成员、通话对象）如何处理，是否需要对方同意？
- 监管与地区差异。

### access-pricing 开放与价格
- 开放范围：地区、邀请制、等候名单、平台账号要求、年龄限制。
- 价格：套餐档位、额度与超额计费、免费层；与所属平台订阅的捆绑关系。
- 开放与定价的变化时间线。

### business 商业与规模
- 用户规模、活跃度、付费数据（标明出处与口径）。
- 商业模式：订阅、交易抽佣、广告、企业版；成本结构与单位经济。
- 厂商的战略意图：为什么做、与主营业务的关系、融资与并购。

### reliability 实际效果与可靠性
- 实测中能完成什么、做不到什么；任务完成率、出错率（标明测试方与口径）。
- 典型失败与翻车案例：原因、影响、厂商回应。
- 用户反馈的整体倾向；官方宣称与实测之间的差距。

### landscape 行业格局（仅主题维度）
- 参与者与路线划分：大厂、模型公司、创业公司；国内与海外。
- 各家的切入点与优势来源（用户入口、个人数据、模型、生态、硬件）。
- 竞争与合作关系、平台之间的拦截与开放、行业时间线。
- 未纳入跟踪的产品（观察列表、已评估未纳入的）只作为格局中的参照提及，不展开分析。
