# 资料页模板与翻译规则

一篇资料一个目录，网站上可见的只有 `index.md`：

```
YYYY-MM-DD-<slug>/
  index.md      资料页：frontmatter、收集说明、摘要、保留理由；翻译完成后在分隔线下加译文
  original.md   外文原文全文存档（中文资料没有这个文件，见「中文资料」）
  images/       图片
```

`original.md` 不生成页面、不发布到网站：`hugo.toml` 的 `ignoreFiles` 排除了它（2026-11-05 加入；只靠 leaf bundle 不够，目录里先写 `original.md`、后写 `index.md` 时，正在运行的 `hugo server` 会把它当成普通页面，侧边栏出现一个空标题条目）。它只供收集 agent 写入、翻译 agent 读取。

## 目录命名

`sources/<类型>/YYYY-MM-DD-<slug>/index.md`，类型目录见 source-types.md。

- 日期为资料的原始发布日期；只知道月份时用当月 01 日，并在 frontmatter 的 `dateNote` 说明。
- 帮助文档、产品页等不标发布日期的资料：依次取页面结构化数据（JSON-LD 的 `datePublished`、`dateModified`）、页面显示的更新日期、收集日期，并在 `dateNote` 写明取自哪里。
- 收集日期（`collectedAt`，以及取收集日期作 `date` 时）按美东时区（America/New_York）的当地日期记，不用系统的 UTC 日期。2026-11-05 及以前已入库的页面按 UTC 记录，维持原样，不回改。
- slug 取自原标题的英文关键词，小写、连字符分隔、不超过 6 个词。中文资料用拼音或英文意译，例如 `2026-10-09-ugoearn-five-tasks`。
- 同一天同名时加后缀 `-2`。

## frontmatter

```yaml
---
title: "我们如何设计 Muse"              # 中文标题；中文资料用原标题
linkTitle: "我们如何设计 Muse"          # 侧边栏短标题，不超过 16 个汉字
date: 2026-09-08                         # 原始发布日期
originalTitle: "How We Designed Muse"   # 外文资料必填；中文资料省略
sourceUrl: "https://introducing.muse.ai/"
altUrls: ["https://muse.ai/blog/how-we-designed-muse"]   # 同一篇内容的其他官方地址，去重时一并比对
author: "Mona Sarantakos, Christine Awad"   # 不详写「未署名」
publisher: "Meta"                        # 发布方或媒体名
language: en                             # en / zh / ja ...
fidelity: 全文                           # 原文存档的完整度，见下表
translation: 待翻译                      # 待翻译 / 已翻译 / 不需要（中文资料、实测记录）
collectedAt: 2026-11-05                  # 收集日期
tags: [发布, 持续执行]                   # 1 到 4 个，只能从 tags.md 的词表中选
products: [muse]                         # 涉及的产品目录名；industry 下必填
# 以下按需填写
reprintUrl: ""                           # 依据转载全文时填转载地址
updatedAt: ""                            # 原文标注的更新日期
dateNote: ""                             # 日期的不确定说明
basedOn: ""                              # 二手报道：被转述的原始报道，如「TIME，2026-10-06」
basedOnUrl: ""                           # 二手报道：原始报道的地址
---

{{< source-info >}}

（收集说明：……）

**收集者摘要**：（3–5 句。）

**保留理由**：（1–2 句。）
```

翻译完成后（或中文资料收集时），在末尾加一条分隔线，下面是正文：

```markdown
**保留理由**：……

---

（译文或中文原文；原文第一级标题从 `##` 开始）
```

`{{< source-info >}}` 根据 frontmatter 和所在目录渲染来源信息块，正文中不再手写来源、作者、日期。来源类型由页面所在的类型目录决定，frontmatter 中不另写。

### fidelity 取值

`fidelity` 描述原文存档（外文资料的 `original.md`，中文资料的「原文」一节）的完整度，与是否翻译无关；翻译状态记在 `translation`。

| 取值 | 含义 |
| --- | --- |
| 全文 | 依据原文全文存档 |
| 转载全文 | 原文无法读取，依据完整转载存档；填 `reprintUrl` |
| 节选 | 只取得部分内容；在缺失位置写「（以下内容无法获取）」 |
| 字幕整理 | 视频或播客，依据字幕或文字稿整理；保留说话人 |
| 实测记录 | 用户自己的实测 |
| 仅链接 | 暂只记录原文链接和基本信息，原文待补；补全时改为相应取值 |

2026-11-05 以前入库的页面沿用旧取值，不回改：「原文」（中文资料原样保存）、「全文翻译」「转载全文翻译」（正文就是全文译文，`translation: 已翻译`），它们没有 `original.md`。

### translation 取值

| 取值 | 含义 |
| --- | --- |
| 待翻译 | 外文资料，`original.md` 已存档，译文未完成 |
| 已翻译 | 译文已写入 `index.md` 的「译文」一节（旧页面：正文即译文） |
| 不需要 | 中文资料、实测记录 |

`fidelity: 仅链接` 的外文页面也填「待翻译」，但没有 `original.md`，要先由收集 agent 补抓原文。

## 页面正文

- **收集说明**：写取文路径与处理（转载、快照、手工复制、删去的网页元素、结构还原），以及判断资料性质需要的背景（作者身份、有无官方回复）。
- **收集者摘要**：3–5 句，只复述原文的主要内容和关键事实（数字、日期、结论照录），不加评价，不加原文没有的信息。
- **保留理由**：1–2 句，写这篇提供了什么已收资料里没有的东西，例如一手实测、官方未公开的细节、时间线证据、某个说法的出处。
- **译文**：翻译 agent 完成后追加在最后：先空一行加分隔线 `---`，再空一行接译文，不加「译文」标题，原文的标题层级不变（第一级从 `##` 开始）。规则见下面的「正文规则」与 translator.md。
- 分隔线以上的部分（来源信息块、收集说明、摘要、保留理由）都不用 Markdown 标题，摘要与保留理由用粗体标签开头，这样页面右侧的目录只显示正文的结构（用户 2026-11-05 决定）。分隔线前后必须各有一个空行，否则 `---` 会把上一段变成标题。

## 原文存档 original.md

- 开头两行写来源与取文信息，空一行后是正文：
  ```
  来源：<sourceUrl 或 reprintUrl>
  取文：<YYYY-MM-DD>，<直接下载 / Wayback 快照 <时间戳> / 用户手工复制 / ……>

  （正文）
  ```
- 不加 frontmatter。正文用 Markdown，原文第一级标题从 `##` 开始。
- 由脚本生成：`extract.py` 的首行 META 不写入文件，其余输出重定向进来；之后用 `sed` 等删去网页残留，用 `localize_images.py` 下载图片到 `images/`。不在对话中手写原文。
- 「正文规则」中的「共同规则」（去网页元素、保留结构、链接、图片处理）适用于 `original.md`；原文措辞不改。对原文做了删节或结构还原时，在 `index.md` 的收集说明里写明，不在 `original.md` 里加注。
- 用户手工复制的原文（如 Reddit 帖子），把用户保存的文件挪进来，补上开头两行；排版不规整时只修断行与列表格式。

## 取全文

- 优先直接下载网页，再从 HTML 抽取正文；页面正文由脚本渲染、直接下载拿不到时，改用能执行脚本的浏览器或网页抓取工具。经过模型抽取的文本可能有细微出入，抽查关键句后再用，并在本轮报告中注明哪些资料走了这条路径。
- 抽取后对照原页面检查完整性：正文容器之外常有要点框、头图、视频、图注、脚注，漏抽要补上。图表、轮播、标签页等由脚本渲染的组件，静态 HTML 中往往只剩空占位，要从页面内嵌的数据中找回。
- 无法从静态页面确定位置或顺序的内容，按最可能的位置放置，并在该处加译注说明。
- 可用脚本见 `skills/collect-sources/scripts/`（依赖 `beautifulsoup4` 与 `markdownify`，建议装在独立的虚拟环境里）：
  - `extract.py <html> [css选择器]`：抽取正文为 Markdown，首行输出页面元数据（og、JSON-LD 日期）。
  - `figures.py <html>`：按文档顺序列出 figure、img、video、table 及其前一段文字，用于核对漏抽的媒体。
  - `rsc_media.py <html>`：从 Next.js 页面内嵌的 RSC 数据中提取图片路径、替代文本、视频地址与图注。
  - `container.py <html> <开头短语> <结尾短语>`：找出同时包含两个短语的最小元素，用于自动抽取失败、需要定位正文容器的页面。
  - `localize_images.py <md> <页面目录> [基准URL]`：下载 Markdown 中的图片到 `images/` 并改写链接；改写后的 Markdown 输出到标准输出，要重定向到文件再替换原文件。
  - `shrink_images.py <images目录> [上限KB]`：缩小超过上限的图片（需要 Pillow）。
- 下载的网页放在临时目录，不放进仓库。
- 直接下载时用 curl 默认的客户端标识，不伪装成浏览器；被拒绝（403）时按下面的 Wayback 方法处理。
- 常见情况（2026-11-05 补抓行业综合资料时整理）：
  - 图片延迟加载的站点（如 WordPress 的 `data-lazy-src`），`src` 只是 `data:image/svg` 占位，抽取前先把真实地址换回 `src`。
  - Substack 文章可用 `<站点>/api/v1/posts/<slug>` 取得 JSON，正文在 `body_html`；播客文字稿由页面脚本加载，静态页面和该接口都拿不到。
  - 转载页（如 DNYUZ）背后的原文地址，可以在引用该文的其他文章里用 `grep` 找 `wired.com/story/` 之类的链接。
  - Wayback 的 `available` 接口偶尔返回空结果；没有快照时可以再用 CDX 接口（`/cdx/search/cdx?url=<地址>`）确认。
- 各产品渠道的具体抓取方法与已知问题，写在该产品的 skill 中。

## 二手报道

一手报道无法读取（付费墙、反爬）且找不到完整转载时，经用户同意，可以收一篇质量较好的二手报道，并填写 `basedOn` 与 `basedOnUrl`。信息块会显示「据媒体报道，本文转述……的报道，原文未直接读取」。之后取得一手原文时，收一手原文，二手报道保留。

## 原站拒绝自动访问时：使用 Internet Archive 存档

原站对直接下载和网页抓取工具都返回 403 等拒绝时，不得绕过（不伪装客户端、不破解验证）。可以改用 Internet Archive（Wayback Machine）的公开快照（用户 2026-11-05 同意）：

1. 查询是否有快照：`https://archive.org/wayback/available?url=<不带协议的地址>`，返回最近一次快照的时间戳。
2. 下载原始页面：`https://web.archive.org/web/<时间戳>id_/https://<地址>`（`id_` 返回不带存档工具栏的原始 HTML）。响应可能是 gzip 压缩的，先解压再抽取。
3. 页面按转载处理：`fidelity` 用「转载全文翻译」或「转载全文」，`sourceUrl` 仍填原站地址，`reprintUrl` 填快照地址，`dateNote` 写明快照时间。快照可能比原站当前版本旧，以后原站可访问时以原站为准。
4. 页面中的图片可同样通过 `https://web.archive.org/web/<时间戳>im_/<图片地址>` 下载。

微信公众号不适用此方法（暂不收集，见 source-types.md）。

## 原文更新

帮助文档、产品页等会持续修改的资料，发现原文更新时覆盖原页面，更新 `updatedAt` 和 `collectedAt`，不另存新版本；提交信息注明「更新」。历史版本由 git 记录。

## 正文规则

### 共同规则

- 保存全文，不删减、不调整段落顺序。
- 去掉与正文无关的网页元素：导航、广告、订阅提示、推荐阅读、评论区、分享按钮。
- 保留原文的标题层级、列表、表格、引用和代码块。页面标题已由 frontmatter 给出；原文第一级标题从 `##` 开始，`original.md` 与 `index.md` 分隔线下的正文都一样。
- 原文中的链接保留原始 URL；相对链接改为绝对地址（如 GitHub README 中的 `esp32/` 改为完整的仓库地址），站内锚点链接改为指向译文标题生成的锚点。
- 原文中的跟踪参数（如 `srsltid=`、`utm_*`）去掉。
- 图片下载到 `images/`，用相对路径引用；图注照录（外文图注翻译），替代文本译为中文写入 `![...]`。无法下载的图片保留原图 URL。
- 单张图片尽量不超过 600 KB：优先取站点提供的缩小版（宽约 1000 像素）；站点不提供时用 `shrink_images.py` 缩小。文件名去掉哈希后缀。
- 超过上限的动图不下载，改为指向原图的链接行：`[动图：<说明>](<原图地址>)`，并加说明。
- 图片里的文字是正文内容（如引语卡片）且没有替代文本时，看图转录，并加译注说明。
- 视频地址带有过期签名（如 fbcdn 的 `oe=` 参数）时，占位行链接到原文页面，不链接视频文件。
- 视频、音频等嵌入内容写为占位行：`[视频：<标题或说明>](<URL>)`。

### 外文资料的翻译

这一节由翻译 agent 遵守（见 translator.md）；收集 agent 不翻译。

- 译文要准确、完整，语句通顺；不意译、不润色、不补充原文没有的内容。
- 产品名、公司名、人名、模型名保留英文，不翻译，例如 Muse、Sentinel、Mona Sarantakos。
- 功能名与术语首次出现时写「中文译名（English）」，之后用中文；没有通行译名的保留英文。
- 数字、日期、金额、百分比、版本号照录，不换算币种和时区；原文给出时区时一并保留。
- 引语译为中文，加中文引号。
- 代码、命令、配置、日志、提示词原样保留，不翻译；需要时在其后加译注说明含义，例如「（译注：意为「……」）」。
- 原文语义含糊或可能有多种理解时，按字面译出，在该处加译注：「（译注：原文为 "..."）」。译注只用于语言层面的说明，不写评价。
- 文风约定（去口语、人称等）只适用于分析页；译文以忠实为先。

### 中文资料

- 不建 `original.md`，原文直接放在 `index.md` 保留理由之后的分隔线下，不加「原文」标题，原文第一级标题从 `##` 开始；用 shell 把抽取结果追加进去，不在对话中手写。`translation: 不需要`。
- 原样保存，不改写措辞、不统一术语。
- 只做排版清理：去除网页元素，修复因复制造成的断行和乱码。
- 转载页面附加的内容（推荐语、转载站的作者卡片、站内推广）不属于原文，删除。

### 收集说明与译注

- 「译注」只用于翻译页面，说明语言层面的问题或无法确定的位置。
- 对原文做了删节、结构还原或替换（例如去掉推广区块、动图改为链接）时，用「（收集说明：……）」写在相应位置；原文是中文时也用这个写法。

### 实测记录

- 按用户提供的原始记录整理：命令、输出、截图、时间、账号条件照录。
- 正文开头写清测试时间、账号与地区条件、客户端版本。
- 用户的推断与观察分开：观察照录；用户原记录中的推断保留原话。
